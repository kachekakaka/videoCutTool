# 0006. 视频智能降码压缩与画质对比预览架构决策

> 状态：智能降码与抽样对比决策有效；2026-10-28 收窄旧音频及管线描述的适用范围。精确导出与分段画面处理的当前规则见[导出模式](../架构.md#导出模式)。

## Context

高码率素材即使裁短也可能体积很大；仅给出编码参数又无法帮助用户判断细节损失。需要可选压缩能力及导出前的画质抽样。

## Decision

- 保留快速无损路径，按需展开降码参数和画质对比，减少普通裁剪的操作负担。
- 以少量预设和自定义参数控制质量、尺寸与编码器。具体参数由 [compressPresets](../../src/shared/compressPresets.ts)维护，能力选择与探测查 [MediaCuttingEngine.probeEncoderSupport](../../src/main/services/MediaCuttingEngine.ts)。
- 预览对代表性短窗口实际编码，再比较原画与结果；预览和正式导出复用编码能力。采样点独立于切点，不改变保留决定。
- 参数变动、离开视图及更换媒体时取消失效请求；界面采用本地图片引用，避免把大量图片内容塞进通信消息。预览实现见 [CompressionPreviewService](../../src/main/services/CompressionPreviewService.ts)。

## Consequences

抽样提供局部画质依据，不能预测每一帧质量或用图片字节数推算成片大小，也不保证固定预览延迟。缓存和中间文件须按[数据归属](../架构.md#数据与产物归属)管理。

2026-09-12 已撤销“限宽 1920”、单张 JPEG 模拟压缩、固定画质／体积百分比和低于 500ms 的承诺，改为实际限高与短窗口编码。原文“全部音轨始终流复制”限定在智能降码路径；精确导出另有音频编码规则。原先“一律先合并再整体压制”的描述不能覆盖分段画面处理，实际管线须保留每段配置。容器和流保留策略查 [MediaFormatResolver](../../src/main/services/MediaFormatResolver.ts)，不从旧示例复制接口。
