# 0003. RetentionDraft 领域深模块与后台异步剪辑引擎架构决策

> 状态：有效。2026-10-28 将可变参数、状态与持久化细节移交当前真源；本篇保留选择原因及责任边界。

## Context

切点和保留决定曾分散维护，删除切点后索引重排导致决定错配；前后端还重复推导区间。工作台与方案中心各自编排执行，造成前台等待、状态反向保存和重复逻辑。

## Decision

- 用 [RetentionDraft](../../src/shared/RetentionDraft.ts)统一编辑状态及切点变化的不变量。删除切点合并区间时，只要任一原区间保留，合并区间就保留；转换为执行规格也从该模块统一进入。
- 草稿在视图切换间常驻；新素材和方案回载按明确操作重置。阈值及其他切点行为查实现，不在 ADR 复制。
- 执行统一交给主进程 [MediaCuttingEngine](../../src/main/services/MediaCuttingEngine.ts)，队列串行处理方案；这不表示应用任何时刻只能存在一个 FFmpeg 进程。
- 由后台维护持久状态，前端展示结果与通知，允许用户继续编辑。状态语义见 [Execution Status](../../CONTEXT.md#execution-status)，执行与恢复边界见[模块与契约](../架构.md#模块与契约)。

## Consequences

草稿与执行分开后，编辑行为可独立验证，状态保存和恢复责任集中。界面仍需处理提交失败，不能把点击执行等同于后台已接受。

2026-09-12 的后续修订增加恢复快照、删除标记及结果保存失败后的恢复，目的是保护已保存意图并避免重复导出；具体存储顺序由 [PlanRecordStore](../../src/main/services/PlanRecordStore.ts)维护。它们属于长期数据，不能随临时缓存清理。
