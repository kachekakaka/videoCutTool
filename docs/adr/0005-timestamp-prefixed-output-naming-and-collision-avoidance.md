# 0005. 导出产物前置时间戳命名与防覆盖物理避让决策

## Context
在前期版本中，导出裁剪视频采用单一的 `${baseName}_cut.mp4` 命名方式。随着“方案管理中心（Plans）”与“后台异步剪辑引擎（MediaCuttingEngine）”的深入应用，暴露了两个关键问题：
1. **版本识别与时间溯源困难**：对同一原视频制作不同版本或在不同时间导出时，操作员无法从文件名直接判断导出批次与时间先后；
2. **方案属性割裂**：用户在工作台或方案中心赋予了明确的语义标题（如“精彩集锦”、“精简速览”），但导出的成品文件名缺失该业务标识；
3. **同名覆盖风险**：若同名文件已存在，虽然主进程有计数递增，但缺乏清晰的自然时间隔离与防覆盖确定性预期。

## Decision
经过权衡（时间戳前置方案 A vs 后缀标签方案 B、弹窗打断 vs 静默避让），确立以下命名规范与安全不变量：

1. **时间戳前置与方案名注入规范（Timestamp-prefixed Output Naming）**：
   - 导出的成品文件名以任务发起时刻的格式化时间戳 `YYYYMMDD_HHmm` 作为首部前缀；
   - **有方案名称时**：在原视频基准名之前注入方括号方案名前缀：
     - 合并单文件：`YYYYMMDD_HHmm_[方案名]原视频名.mp4`
     - 多分段不合并：`YYYYMMDD_HHmm_[方案名]原视频名_seg01.mp4`、`_seg02.mp4`...
   - **无方案名称时（匿名/默认）**：
     - 合并单文件：`YYYYMMDD_HHmm_原视频名_cut.mp4`
     - 多分段不合并：`YYYYMMDD_HHmm_原视频名_seg01.mp4`、`_seg02.mp4`...

2. **同分钟物理碰撞避让不变量（Collision Avoidance）**：
   - 当在同一自然分钟内连续对同一视频以相同方案名触发导出时，底层自动检测目标文件物理存在性；
   - 若检测到文件已存在，系统自动在文件名后追加 `_01`、`_02`... 递增计数流水号，物理级别杜绝同名覆盖，且无需打断操作员进行弹窗询问。

3. **工作台预定输出胶囊实时联动**：
   - 前端工作台底部预定输出路径胶囊与方案标题输入框深度绑定，打字时毫秒级响应并展示最终落盘文件名，提供确定性心理安全感。

## Consequences
- **文件列表时间天然有序**：操作系统资源管理器按文件名升序/降序排列时，自动按剪辑时间严格排序，极大降低版本检索心智负担；
- **批处理免打扰与零数据丢失**：后台静默剪辑引擎全自动避让物理冲突，保障连续打标与异步生产过程顺畅安全；
- **方案与产物双向语义绑定**：方案中心记录的 `title` 与磁盘文件名的 `[Title]` 标签一一对应，形成闭环资产追踪链。
