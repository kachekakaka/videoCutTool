# 0002. 外置跳板启动架构与工作区数据目录解耦决策

> 状态：目录发行与数据解耦决策有效；2026-10-28 移除固定体积、启动耗时和旧配置兼容要求。当前交付入口见 [README](../../README.md#开发与协作约束)。

## Context

早期单文件自解压发行需要每次展开运行时，造成启动等待；直接展开又让程序根目录堆满依赖。程序旁的指针与实际配置同名，也容易混淆程序位置和用户数据位置。

## Decision

- 使用便携目录发行，根目录提供原生启动器，运行时集中在 `app/`，避免每次启动自解压。
- 根目录的 `workspace.json` 只承担数据目录指针职责；实际配置及方案由用户选定的数据目录承载。
- 启动互斥与窗口显示时机由 [electron/main.ts](../../electron/main.ts)维护；构建和启动器细节分别查 [build-portable.ps1](../../scripts/build-portable.ps1)及 [launcher.cs](../../scripts/launcher.cs)。

## Consequences

用户须保留完整发行目录，不能只移动启动器。数据与程序分开后，可独立维护程序版本和用户数据，但部署和清理必须遵守[数据与产物归属](../架构.md#数据与产物归属)。

原记录中的固定包体积、启动器大小、低于 0.3 秒启动及零系统目录写入均不作为保证；性能须针对交付版本实测。早期读取旧 `config.json` 指针的兼容设想不构成后续开发要求，初始化行为以 [ConfigService](../../src/main/services/ConfigService.ts)和当前项目开发原则为准。
