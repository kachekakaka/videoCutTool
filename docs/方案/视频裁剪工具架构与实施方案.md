## 1. 问题阐述（Problem Statement）

用户在整理长视频、课程录屏或影视资料时，需要高频剔除片头、片尾或中插广告。目前面临的核心痛点包括：
1. **原生环境构建沉重**：在原 `JA_WORKSPACE`（C++ Qt6）中，微小调整需要经历沉重的编译链接，缺少一个轻量、便携、开箱即用的日常桌面小工具；
2. **重编码画质损耗与等待耗时**：常规视频剪辑软件往往执行二次编码，耗时长且损伤画质；而直接按时间点硬切断又因为缺少前置参考帧，极易造成切片开头花屏、卡顿 1~3 秒甚至黑屏；
3. **误删正片风险**：现有简易工具在向关键帧吸附时逻辑粗糙，经常误切正片开头，无法贯彻“宁可多留半秒关键帧，绝不能多删一帧正片”的铁律保全准则；
4. **缺乏方案管理中心**：无法对批量的剪辑方案进行结构化的增删改查、标记完成状态或一键批量执行无损剪辑；
5. **界面拥挤与排版错位**：常规界面在窗口拉宽或多卡片排布时，按钮挤压折行、文字错位、卡片高低不齐，视觉与操作体验较差。

---

## 2. 解决方案（Solution）

打造一款采用 **Motrix** 现代暗黑极简设计风格、基于 **Electron + React + TypeScript + TailwindCSS + FFmpeg** 的独立视频无损裁剪桌面软件：
1. **Motrix 经典左侧导航栏**：采用 68px 紧凑侧边栏，将界面划分为【视频裁剪工作台】、【方案管理中心】与【系统设置】三大核心视图；
2. **固定三段式自适应分段卡片流**：每张分段卡片严格采用“元信息行 + 独立起止时间行 + 底端操作行”的排版栅格，全屏贯彻 1360px 统一垂直对齐轴线，彻底杜绝折行与高低错位；
3. **关键帧保全铁律算法（向左吸附关键帧）**：基于 FFprobe 提取的关键帧毫秒索引，所有保留段起点自动向左吸附前向 I 帧，确保 100% 秒级无损流拷贝剪辑，且正片零截断；
4. **方案管理闭环（Plan Manager）**：方案集中持久化存储于 `./plans/{plan_id}.json`，醒目标记【✔ 已完成剪辑】与【⏳ 待执行】，支持增删改查、二次回载编辑与一键批量执行；
5. **便携配置与开箱即用**：初次启动自动在可执行文件同级生成 `config.json`，默认输出至源视频同级专属 `_cuts/` 子文件夹；方案数据契约与 `JA_WORKSPACE` 100% 互通兼容。

## 3. 用户故事清单（User Stories）

### 视图与整体排版体验
1. **作为** 操作人员，**我希望** 界面左侧提供 68px 的 Motrix 风格图标导航栏，**以便于** 在工作台、方案库与设置页之间无干扰极速切换。
2. **作为** 操作人员，**我希望** 顶栏操作区、视频播放器、分段卡片流与底栏状态栏全部严格对齐在统一的 1360px 垂直轴线上，**以便于** 在大屏和宽屏显示器下窗口居中大方，杜绝界面元素左右散乱漂移。
3. **作为** 操作人员，**我希望** 播放控制栏的【播放/暂停】核心按钮在播放器底部保持物理几何绝对居中，**以便于** 无论时间码长度如何变化，播放核心控制始终对称舒适。

### 视频载入与时间轴交互
4. **作为** 操作人员，**我希望** 可以直接拖拽或点击选择本地视频文件，**以便于** 软件自动调用本地 FFprobe 秒级探测视频时长与全片关键帧索引。
5. **作为** 操作人员，**我希望** 能在时间轴上任意点击跳转或按空格键播放/暂停，**以便于** 快速定位需要裁剪的视频节点。
6. **作为** 操作人员，**我希望** 支持逐帧步进（键盘左右方向键或界面按钮），**以便于** 能够以毫秒级精度精细核对切点。
7. **作为** 操作人员，**我希望** 在播放到合适位置时按下键盘 C 键或点击剪刀按钮插入切点，**以便于** 快速在时间轴上插上标记旗标并将视频分割为多个相邻片段。

### 分段卡片流与决策交互
8. **作为** 操作人员，**我希望** 分段卡片的第一行专门展示序号、保留/丢弃胶囊标签和片段时长，**以便于** 顶部空间极度宽裕，文字绝不折行挤压。
9. **作为** 操作人员，**我希望** 分段卡片的第二行专门展示大号纯白等宽字体的起止时间与连接箭头，**以便于** 时间码字字清晰、一目了然，绝不被删除线划掉或挤成两行。
10. **作为** 操作人员，**我希望** 分段卡片的第三行提供一体化的【✔ 保留 / ✖ 丢弃】单选切换胶囊，**以便于** 一键切换分段决策，并即时联动时间轴颜色变化。
11. **作为** 操作人员，**我希望** 分段卡片上提供【▶ 试听】按钮，**以便于** 快速在该段起止范围内定向循环播放，确认是否误切。
12. **作为** 操作人员，**我希望** 卡片上配备 `[-0.1s]` 与 `[+0.1s]` 微调步进按钮，**以便于** 无需重新拖动主时间轴即可直接微调切点位置。
13. **作为** 操作人员，**我希望** 自适应网格中的所有分段卡片强制等高拉伸，且底端操作栏排布在同一条绝对水平线上，**以便于** 整行卡片严整齐平，杜绝高低错位。

### 方案管理中心与生命周期
14. **作为** 操作人员，**我希望** 可以将当前时间轴上的所有切点与决策存为一份方案记录（Plan Record），**以便于** 保存整理成果供后续批处理执行。
15. **作为** 操作人员，**我希望** 在方案管理中心可以通过分类标签（`全部方案` / `⏳ 待执行` / `✔ 已完成剪辑`）筛选方案，**以便于** 有序管理我的剪辑任务清单。
16. **作为** 操作人员，**我希望** 已经执行完毕的方案在卡片顶部醒目标注绿色徽章 `✔ 已完成剪辑`、生成产物路径与完成时间点，**以便于** 无需打开文件夹即可明确知道哪些视频已剪辑就绪。
17. **作为** 操作人员，**我希望** 方案管理页提供【🚀 批量执行待办方案】按钮，**以便于** 一键启动后台队列，依次无损秒切所有未完成的方案。
18. **作为** 操作人员，**我希望** 能够将已保存的方案重新载入回工作台微调切点，且保存时支持原地覆盖更新，**以便于** 方案二次修改时不产生垃圾重复记录。
19. **作为** 操作人员，**我希望** 能够查看和一键复制标准的 `MediaRetentionPlan` JSON 数据，**以便于** 直接无缝交由 `JA_WORKSPACE` 或外部自动化脚本消费。
20. **作为** 操作人员，**我希望** 可以物理删除不需要的历史方案，**以便于** 保持方案库清爽整洁。

### 无损剪辑与保全铁律
21. **作为** 操作人员，**我希望** 剪辑引擎严格执行“向左吸附前一个关键帧（Floor to Keyframe）”算法，**以便于** 导出的视频永远以完整的关键帧（I 帧）起播，绝无花屏黑屏，且保留的正片零截断。
22. **作为** 操作人员，**我希望** 勾选自动合并选项时，软件自动调用 FFmpeg concat demuxer 将所有保留片段无损合并为单个文件，**以便于** 直接得到完整干净的新视频。
23. **作为** 操作人员，**我希望** 引擎能自动融合因关键帧外扩而发生重叠的相邻保留区间，**以便于** 合并后的视频不产生多余的重复画面。

### 便携配置与默认输出策略
24. **作为** 操作人员，**我希望** 软件初次启动时自动在可执行文件同级目录释放 `config.json`，**以便于** 绿色免安装，配置随时可读可迁移。
25. **作为** 操作人员，**我希望** 默认导出目录规则设定为原视频同级目录下的专属 `_cuts/` 子文件夹，**以便于** 产物与原片物理隔离，原文件夹整洁不混乱。
26. **作为** 操作人员，**我希望** 能在设置页面灵活切换为同级目录导出或统一固定目录导出，**以便于** 适应不同的媒体管理习惯。

## 4. 实施决策（Implementation Decisions）

### 4.1 模块职责划分
- **裁剪工作台模块（Cutter Workbench）**：负责 HTML5 视频播放桥接、双缓冲 Canvas 时间轴重绘、响应式分段卡片网格渲染与实时切点编辑；
- **方案管理中心模块（Plan Manager Store）**：负责本地方案持久化（`./plans/{plan_id}.json`）、状态机（`ready` 待执行 $\rightarrow$ `completed` 已完成）、标签筛选与批处理调度；
- **系统设置模块（Settings & Config）**：负责应用同级 `config.json` 自动探测、自愈生成、配置读写与输出路径解析；
- **底层无损领域引擎（Core Retention Engine，纯 TypeScript 模块，无 UI 依赖）**：
  - `KeyframeProber`：调用 `ffprobe` 解析视频流 packet/frame 数据，提取毫秒级关键帧时间戳列表；
  - `RetentionPlanner`：纯函数规划器，执行关键帧向外保全对齐准则，计算各段的 `safeRange`，合并相邻重叠，输出标准方案；
  - `FFmpegExecutor`：组装 `-c copy -avoid_negative_ts make_zero -map 0` 极速流拷贝命令行与 concat 合并清单，异步执行并反馈退出码。

### 4.2 核心数据契约（TypeScript 模型）

```typescript
// 方案管理中心持久化方案记录实体 (Plan Record)
export interface PlanRecord {
  id: string;                      // 方案唯一标识 (例如 plan_20260903_01)
  title: string;                   // 展示标题 (通常为 视频文件名 + 标注)
  sourcePath: string;              // 原始视频文件绝对路径
  outputPath: string;              // 目标剪辑生成视频路径
  totalDurationMs: number;         // 视频原始总时长 (毫秒)
  keptDurationMs: number;          // 预期保留正片总时长 (毫秒)
  cutsCount: number;               // 切点数量
  status: 'ready' | 'completed';   // 执行状态：待执行 vs 已完成
  updatedAt: string;               // 最近更新时间
  completedAt: string | null;      // 实际执行完成时间戳 (已完成时记录)
  cuts: number[];                  // 切点毫秒列表 [30000, 93055, ...]
  decisions: Record<string, 'keep' | 'discard'>; // 分段保留决策映射表
}

// 应用程序可执行文件同级持久化配置文件 (config.json)
export interface AppConfig {
  version: string;
  outputDirectoryRule: 'sub_folder' | 'same_directory' | 'custom_fixed';
  subFolderName: string;           // 默认 "_cuts"
  customOutputDirectory: string;   // 固定导出目录绝对路径
  keyframeSafetyGuaranteed: true;  // 关键帧铁律保全（绝不多删）强制开启
  autoConcatSingleFile: boolean;   // 多保留段是否默认合并为单文件
  ffmpegPath: string;              // 本地 FFmpeg 路径 (默认 "./tools/ffmpeg.exe")
  ffprobePath: string;             // 本地 FFprobe 路径 (默认 "./tools/ffprobe.exe")
  plansStoragePath: string;        // 方案持久化存储目录 (默认 "./plans")
}
```

### 4.3 分段卡片固定三段式栅格规则（排版防折行决策）
- **行 1（元信息行）**：固定高度 24px。左侧放 `#序号` + 紧凑决策胶囊（`✔ 保留` / `✖ 丢弃`）；右侧放时长胶囊（`⏱ 30.00秒`）。本行禁止放入时间码，确保空间充裕，绝不折字；
- **行 2（独立起止时间行）**：专属独立深色微背景条。起止时间大号纯白等宽字居中排布，中间以细长箭头相连（`00:00.000 ──▶ 00:30.000`）。设置 `white-space: nowrap`，强制单行呈现，绝不折行；
- **行 3（操作按钮行）**：强制底端对齐（`margin-top: auto`）。包含【试听】、一体化【保留/丢弃切换胶囊】与【-0.1s / +0.1s 微调步进器】；
- **网格容器规则**：`grid-template-columns: repeat(auto-fill, minmax(310px, 1fr)); align-items: stretch;`；所有卡片高度统一，整行卡片底端操作栏处于绝对同一水平线上。

## 5. 质量保证与极简测试策略（Testing Strategy）

### 5.1 反过度治理原则
- **坚决不建重型测试体系**：不设立 UI 组件测试、E2E 端到端测试、自动化 CI 门禁或覆盖率硬性指标；桌面交互与卡片排版直接由人工肉眼在原型和应用中直观验证，避免“改一次样式、挂一批测试”的沉重维护成本。

### 5.2 唯一算法保护切口（纯函数单测）
视频流拷贝剪辑的唯一隐蔽风险是关键帧吸附计算错误导致花屏或误删正片。因此，测试严格收缩为**唯一一个极简纯函数单测**（预计代码量 < 50 行）：

- **待测对象**：`RetentionPlanner.test.ts`（纯数学/数组计算，无任何 Electron、DOM 或 FFmpeg 外部依赖）；
- **核心断言不变量**：
  $$\text{safeRange.startMs} \le \text{userRange.startMs} \quad \text{且} \quad \text{safeRange.endMs} \ge \text{userRange.endMs}$$
- **核心用例**：
  1. 切点在非关键帧处时，起点必然安全向左吸附到前一个 I 帧；
  2. 两个相邻保留段因关键帧外扩发生重叠时，自动合并为单一安全区间；
  3. 首尾边界（0ms 起点与全片结束点）的保全边界对齐。

## 6. 范围外事项（Out of Scope）

1. **逐帧重新编码渲染**：本项目专注于零画质损伤、秒级导出的流复制（Fast-Copy），不引入慢速的软件重编码视频渲染管线；
2. **多轨道混音与多视频画中画**：不支持多视频轨叠加与复杂特效字幕合成，定位于极致轻量聚焦的粗剪剔除工具；
3. **云端同步与账号登录体系**：软件为完全纯本地、单机离线的便携工具，不引入任何外部云端服务与用户鉴权。

## 7. 补充说明（Further Notes）

- **与 `JA_WORKSPACE` 的兼容**：方案契约与 `JA_WORKSPACE` 原 C++ 核心库结构体完全对齐，导出的方案文件可无缝作为任务导入给 `ja.exe` 批量处理；
- **跨平台保障**：打包支持 Windows 便携版（zip/exe）与 Linux AppImage，内部统一携带静态编译的 FFmpeg/FFprobe 工具链二进制。
