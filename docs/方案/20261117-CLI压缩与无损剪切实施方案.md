状态：待审阅，尚未实施。日期：2026-11-17。

前置调整：[同盘处理方案](../../archive/docs/方案/20261117-全项目导出同盘处理实施方案.md)已实施，本地定向验证及 C/D 两卷 NTFS 实盘验收通过并归档。CLI 尚未实施；后续复用 [OutputTaskWorkspace](../../src/main/services/OutputTaskWorkspace.ts)与 [OutputPublisher](../../src/main/services/OutputPublisher.ts)，导出媒体归属、发布和根锁生命周期以[架构真源](../架构.md#同卷处理与发布)为准。定向 review 中的存储故障终止及待保存结果读取问题仍需在 CLI 实施前补齐，不因同盘调整自动解决。

## 目标与首版边界

让本机其他程序通过命令行传入原片完整路径、成品完整路径和处理参数，执行整片压缩或无损剪切；不打开窗口，等待完成后通过 JSON 和退出码返回结果。

首版面向 Windows x64 便携包，每次调用处理一个原片、生成一个成品。剪切支持一个或多个按时间排序的保留区间，多区间按顺序合成一个文件。使用现有关键帧无损策略，不提供逐帧精确导出、画面处理、覆盖已有文件、后台脱离进程运行或远程服务。

CLI 与桌面界面复用处理服务和媒体引擎，但首版不共享任务列表。CLI 使用独立数据目录，避免恢复桌面的排队任务或干扰其状态。后续 HTTP 可复用公共任务入口；监听服务、鉴权、文件传输及远程路径映射届时另行实现。

## 已核对的现状

- [应用入口](../../electron/main.ts)在初始化时选择数据目录、构造服务并打开窗口；单实例冲突仅退出或聚焦窗口，没有业务命令处理。
- [便携启动器](../../scripts/launcher.cs)是桌面启动入口，当前参数通过字符串拼接传递，不承担等待任务、标准流转发和退出码回传。
- [PlanManager](../../src/main/services/PlanManager.ts)启动会恢复已保存队列；CLI 不能直接套用桌面启动流程。
- [BatchCompressionService](../../src/main/services/BatchCompressionService.ts)已有压缩检查与保存入口，但依赖内部文件授权，输出目录由应用生成。
- [MediaCuttingEngine](../../src/main/services/MediaCuttingEngine.ts)最终发布时重新分配输出路径；仅传入 outputPath 不能实现指定完整文件名。
- [输出路径规则](../../docs/架构.md#输出路径与命名)、[媒体检查的耗时边界](../../docs/架构.md#媒体检查的耗时边界)和[业务术语](../../CONTEXT.md)继续作为相关事实真源。

## 命令契约

便携根目录新增控制台入口 `VideoCutTool-cli.exe`，原桌面入口保持用途不变。以下为拟实现接口，当前尚不能执行：

```powershell
.\VideoCutTool-cli.exe compress --input "D:\素材\原片.mp4" --output "E:\成品\压缩.mp4" --preset balanced --data-dir "D:\VCT-CLI数据"
.\VideoCutTool-cli.exe compress --input "D:\素材\原片.mp4" --output "E:\成品\压缩.mp4" --preset custom --crf 24 --max-height 1080 --encoder cpu --data-dir "D:\VCT-CLI数据"
.\VideoCutTool-cli.exe cut --input "D:\素材\原片.mp4" --output "E:\成品\剪切.mp4" --range 10000:30000 --range 60000:90000 --data-dir "D:\VCT-CLI数据"
.\VideoCutTool-cli.exe --help
.\VideoCutTool-cli.exe --version
```

- `--input`、`--output`、`--data-dir` 必填且要求绝对路径，避免启动器工作目录改变含义；支持中文、空格和合法特殊字符。数据目录是 CLI 专用的持久目录，不是成品目录。
- `compress` 默认使用 `balanced`，预设枚举和参数合法范围复用 [CompressConfig](../../src/shared/types.ts)及现有校验。`--crf`、`--max-height` 仅在 `--preset custom` 时接受，其他组合报错，不静默忽略。`--encoder` 支持 `auto/cpu/nvenc/qsv`，默认 `auto`；实际编码器在结果中返回，自动选择及回退规则复用引擎。
- `cut` 的 `--range 起点:终点` 使用非负整数毫秒，可重复。必须起点小于终点、顺序递增且不重叠，终点不得超过媒体有效时长。相邻区间可合并；无范围、空范围和越界均报错。首版只做无损剪切，不接受压缩参数。
- 原片封面默认沿用当前导出的去除策略，可用 `--keep-cover` 请求保留；流与容器不兼容时明确失败，不静默丢弃或转换模式。
- 未知选项、除 `--range` 外的重复选项、缺失值均报参数错误。首版不增加独立 JSON 请求文件语法，程序直接使用子进程参数数组调用即可。
- `--help` 和 `--version` 不启动媒体处理、不创建数据目录。

无损剪切仍按关键帧保全内容，实际起点可能提前、片尾可能扩出，不承诺精确等于请求区间。请求区间之间可能因关键帧扩展而重叠，规划继续复用现有 Retention Draft / Retention Plan 规则；帮助与结果警告必须解释此边界。

## 输出与进程生命周期

默认等待当前任务结束，不提供 `--detach`。stdout 只输出一行最终 JSON；诊断和节流后的进度写 stderr，不混入 JSON。帮助与版本命令输出普通文本。全部文本使用 UTF-8。

成功示例：

```json
{"ok":true,"taskId":"生成的ID","operation":"compress","status":"completed","outputPaths":["E:\\成品\\压缩.mp4"],"resolvedEncoder":"cpu","warnings":[]}
```

失败示例：

```json
{"ok":false,"operation":"cut","status":"failed","error":{"code":"OUTPUT_EXISTS","message":"目标文件已存在"},"outputPaths":[]}
```

任务创建前失败可省略 taskId；没有完成的成品不得作为成功输出返回。发布完成但状态保存失败时，返回明确错误以及已完成产物路径，不能让调用方误以为没有产物而盲目重试。记录与最终结果仍须遵守现有保存成功边界。

| 退出码 | 含义 |
| --- | --- |
| 0 | 成功，或帮助/版本正常输出 |
| 2 | 命令或参数错误 |
| 3 | 环境、路径、工具、容器不支持、目标已存在等前置检查失败 |
| 4 | CLI 数据目录正被占用 |
| 5 | 执行或结果持久化失败 |
| 130 | 用户中断 |

Ctrl+C 通过明确的控制通道交给任务取消逻辑：终止本次媒体子进程，等待清理和状态保存，再退出。控制台启动器等待子进程且回传其退出码；不通过系统范围进程名批量结束进程。强制杀进程不承诺即时清理，后续启动按现有登记恢复，不能自动重跑上次任务。

## 数据与并发边界

为保持首版简单，`--data-dir` 显式指定独立 CLI 数据目录，首次可自动建立配置、方案与索引。它不写桌面 `workspace.json`，不修改桌面配置，也不自动导入桌面任务。

CLI 目录使用用途标记，并在读取或写入配置之前取得独占锁；已有未标记且非空目录拒绝直接认领，桌面已使用的数据目录拒绝作为 CLI 目录。桌面初始化同样识别 CLI 用途标记并拒绝绑定，防止反向误用。锁使用进程持有的操作系统互斥资源或保持句柄的排他锁，不以单个残留文件是否存在判断占用；规范化真实路径，处理大小写和目录别名。

同一 CLI 数据目录同时只运行一个进程，第二次调用立即返回占用错误。不同目录可独立运行，但不承诺资源调度；GUI 与 CLI 可以同时运行，各自使用独立队列、索引及缓存登记空间。

CLI 启动只执行本次新任务，历史记录用于诊断，不自动恢复历史排队项。为 PlanManager 增加明确的启动策略，CLI 模式不加载或派发历史队列，且不能将历史排队项混入本次队列快照。桌面维持原队列恢复语义。

持久配置、方案和完整索引归入 CLI 数据目录。导出媒体中间文件遵循[架构真源](../架构.md#同卷处理与发布)，置于成品目录中的专用受管空间；其他运行缓存按既有临时空间规则存放。CLI 使用独立且可跨重启发现的维护登记，与桌面共享目标侧受管根时必须遵守所有权互斥，不得相互清理存活任务；实际占用时明确失败，不转移到其他盘。导出根锁按任务及清理的使用期间持有，闲置后释放，不因桌面保持打开而阻止 CLI；这与整个 CLI 调用期间持有的数据目录锁分别管理。历史发现不创建缺失目录，具体生命周期与恢复规则统一引用架构真源，不在 README 复制。

## 实现结构

1. 新增 `electron/cli.ts` 作为无窗口执行入口，等待 Electron 就绪后只初始化必要处理服务；不构造 BrowserWindow、播放器、预览服务或文件选择对话框。继续随便携包分发 Electron 和媒体工具，不要求使用者安装 Node.js。
2. 新增 `src/main/cli/arguments.ts`、`src/main/cli/run.ts`，分别负责命令解析和标准流/退出码/取消适配。启动器通过明确内部标志进入 CLI 分支，`electron/main.ts` 在执行桌面模块副作用前完成分流；桌面初始化可拆入 `electron/desktop.ts`。构建必须保留 CLI 所需模块。
3. 新增 `src/main/services/ProcessingRuntime.ts`，集中构造配置、索引、引擎、方案管理器及关闭流程，显式传入数据目录、缓存空间与启动策略。桌面事件转发和 CLI 标准流处理留在各自适配层。
4. 新增 `src/main/services/ProcessingTaskService.ts` 与 `src/shared/processingTask.ts`，定义独立于 Electron IPC、命令行、HTTP 的请求、结果与进度契约。公共入口接收规范化路径、压缩或保留区间及输出要求，提供提交、等待、订阅进度和取消；通过既有 PlanManager 和 MediaCuttingEngine 执行，不再写另一套 FFmpeg 命令生成器。
5. CLI 显式路径经规范化、可读性和格式校验后进入公共入口；桌面继续保留可信窗口及 FileAccessRegistry 检查，不能为了 CLI 放宽现有 IPC 来源限制。将必要的纯业务参数校验从 IpcSecurity 中抽出复用。
6. 剪切请求通过共享媒体索引准备时长、源版本和关键帧信息，转换为 Retention Draft、保留决定及单个输出分组，再提交现有执行流程。压缩复用轻量检查与执行时探测，不先建立裁剪完整索引。源版本绑定和发布前检查继续复用现有机制。
7. 引擎增加明确的输出意图：桌面使用自动命名，CLI 使用指定完整路径。将请求目标与执行后 outputPath/outputPaths 分开保存，避免压缩准备阶段清空结果字段时丢失目标。同步调整类型、记录存储校验、请求校验及引擎计划构造，不做旧数据迁移或历史兼容分支。

## 指定输出路径

- 首版只生成一个输出文件，因此 `--output` 始终是完整文件路径，不自动改名或加序号。
- 要求父目录已存在且可写；输入和输出不得是同一个文件，校验规范路径以及已有路径的文件身份/链接关系。
- 后缀必须与现有格式解析器选择的输出容器一致；不支持的组合在执行前报错，不能自动换后缀、转码或生成别处文件。
- 已有目标立即失败，不提供覆盖开关；发布时仍进行排他创建，防止预检后另一调用抢先创建。CLI 遇到目标冲突直接报错，桌面自动命名仍按原逻辑重试。
- 导出媒体从开始就在成品所在卷内处理，验证完成后排他发布；不再跨盘复制或以最终名称写半成品。复用全项目同盘发布入口，文件系统不支持时明确失败，不能回退复制。成功回执仍以成品发布及结果保存完成为界。
- 不能将任意用户输出目录登记为可整体清理的缓存目录。

## 实施顺序与验收

1. 先实现纯参数及请求契约、独立数据目录和运行时启动策略。
2. 接通压缩、无损剪切和明确输出路径，跑服务层定向验证。
3. 接通无窗口入口、控制台启动器、取消与结果回传，再完成便携构建验证。
4. 补充用户文档并按 [README 验证与交付](../../README.md#验证与交付)交付。

验收必须覆盖：

- 类型检查及本次涉及的既有测试通过；新增测试重点覆盖未知/重复参数、范围非法、指定路径不被重命名、输出冲突及历史任务不被误启动。
- 代表性 MP4 整片压缩、单区间和多区间无损剪切成功；使用 ffprobe 核对视频/音轨、成品可读性与实际时长。无损验证确认使用流复制及关键帧策略，不以时长恰好等于请求区间作为通过标准。
- 代表性正常 FLV 非零起始时间戳素材：索引准备、非零位置剪切和源版本复用正确；不将整片索引扫描带入压缩参数校验。没有原素材时明确替代样本的覆盖限制。
- 中文、空格和特殊字符路径，源文件不存在，源目标相同，已有目标、容器不兼容、工具缺失、编码器不可用均给出非零退出码及明确错误。
- Ctrl+C 后本次媒体进程退出，中间文件回收，返回取消码；启动器与子进程异常退出有明确结果，不残留本次处理进程。
- 同一 CLI 数据目录并发调用被拒绝；桌面目录不能作为 CLI 目录，CLI 目录不能被桌面绑定；CLI 不执行历史任务、不改变桌面队列及 workspace 绑定。
- 程序与成品不同卷时，媒体中间文件仍位于成品卷，同卷发布无复制兜底；失败回收不删除原片或抢占者文件。结果保存失败时返回已发布产物信息，不能误报成功。
- 对桌面原有自动命名及压缩/剪切受影响路径做最小回归。
- 一次 Windows 便携候选构建后，从根控制台入口及 PowerShell 子进程重定向两种方式实际验证等待、stdout JSON、stderr、退出码和不弹窗。此项不能仅靠开发模式测试代替。

验证脚本、日志、素材、截图及验收报告置于 `../videoCutTool_tmp/20261117-cli/`（仓库同级目录）。实施通过后，在本方案头部补充实际完成日期与验证结论，将其移动至 `archive/docs/方案/` 并修正相对链接。本次仅交付方案，执行文档链接检查，不构建、不运行媒体处理、不提交 Git。
