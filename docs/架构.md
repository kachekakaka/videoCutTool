# 当前架构与媒体处理边界

本文维护当前模块职责、调用成本与数据归属，不作为一次性实施方案归档。术语见 [CONTEXT](../CONTEXT.md)，任务状态见[待做事项](待做事项.md)，验收与交付要求见 [README](../README.md#验证与交付)。历史设计及取舍见 [ADR](adr/)。

## 支持范围

应用采用 Electron、React、TypeScript 与 FFmpeg，面向本地视频裁剪、画面处理和批量压缩。当前构建与实际交付覆盖 Windows x64 便携目录；Linux AppImage 和向 JA_WORKSPACE 直接导入方案不属于已验证能力，早期设想不能作为兼容承诺。

字段、联合类型和默认值以 [types.ts](../src/shared/types.ts) 为准。`PlanRecord` 区分裁剪记录与整片压缩记录；执行状态及其含义见 [Execution Status](../CONTEXT.md#execution-status)。本文不复制接口定义或配置模板。

后台引擎串行执行方案。接受任务、开始处理及完成都以对应状态保存成功为界；同一 ID 在排队、处理及结果保存期间只接受一次。处理中不能删除或覆盖保存，删除排队记录时同步移出队列。结果保存失败时保留待保存结果，避免重复导出。

裁剪方案的内容修订用于识别编辑内容变化，纯执行状态更新不改变内容修订；旧源版本确认见下节。恢复快照与删除标记由 PlanRecordStore 管理，不能按临时缓存处理。

## 播放、修复与导出

### 素材准备与索引复用

普通 MP4 优先读取容器采样表。受支持的正常 FLV／MPEG-TS 首次建立完整定位索引后才启动播放器及编辑，准备期间显示进度并允许取消。再次打开、方案回载及导出复用匹配源版本的结果；媒体索引的含义与保留规则见 [Media Index](../CONTEXT.md#media-index)。首次索引小，不代表首次扫描便宜。

流式播放按位置读取原片，不生成整片 MP4 副本；FLV／MPEG-TS 流式失败不静默切换到整片兼容预览。其他格式的兼容预览只是播放副本，导出仍引用原素材。

保存裁剪方案校验源版本与内容修订后，只持久化编辑意图，不查询索引或重新扫描媒体。索引发布不改写方案或推进其恢复快照。旧方案缺少已确认的源版本时，先通过应用内提示确认素材对应关系，再回载切点；取消不改原方案。

### 异常时间轴修复

流式分析发现时间戳重置或大幅跳变时，提示“修复并继续编辑”，继续本次可取消的只读分析。用户确认后，[TimelineRepairService](../src/main/services/TimelineRepairService.ts)复用同次分析，无损另存新 MP4，并发布绑定最终文件身份的索引。原片和已保存方案保留，新草稿不自动迁移切点。

无法可靠配对断点或不符合支持条件时停止，不自动转码。修复不能恢复原片已损坏的画面。安全另存由 [RepairOutput](../src/main/services/RepairOutput.ts)负责，需要目标文件系统支持排他硬链接；已验证 Windows NTFS，不支持时提示更换位置，不向最终文件名写半成品。跨盘临时副本登记在目标盘同级临时空间，重启按归属回收；修复成品是用户素材，不属于播放缓存。

### 导出模式

| 模式 | 边界与编码 | 适用限制 |
| --- | --- | --- |
| 快速无损 | 使用关键帧保全范围，视频与保留音轨流复制 | 起点可能提前，片尾可能扩出，余量以实际产物为准 |
| 智能降码 | 沿用关键帧保全范围，编码视频，保留音轨流复制 | 压缩不等于逐帧精确截断；预设参数见 [compressPresets](../src/shared/compressPresets.ts) |
| 精确导出 | 按显示帧区间重新编码，包含起点帧、不包含终点帧 | 视频使用软件 H.264，音轨编码为 AAC，输出 MP4；耗时更长、非严格无损 |

关键帧模式的规划范围保持 `safeRange.startMs <= userRange.startMs` 且 `safeRange.endMs >= userRange.endMs`；该不变量不代表产物边界有固定余量上限。精确导出的帧间手输时间向下一帧对齐，毫秒舍入的逐帧切点还原到对应帧，实现见 [PreciseExport](../src/main/services/PreciseExport.ts)。

精确导出支持一路视频、多音轨或无音轨、分段画面处理及输出组合；附加流须明确处理，不静默丢弃。三种模式均保留原片，模式随裁剪方案保存。时间轴异常须先修复；当前不实现仅重编码边缘再与原始压缩数据混合拼接。

画面处理必然需要视频重新编码；精确模式可直接结合画面处理，关键帧模式则进入智能降码。分段空间配置及输出分组由草稿传递到引擎，不能先无条件合并区间而丢掉各段配置。滤镜、容器和流映射分别见 [spatialFiltergraph](../src/shared/spatialFiltergraph.ts)、[MediaFormatResolver](../src/main/services/MediaFormatResolver.ts)和后台引擎。

## 媒体检查的耗时边界

修改导入、探测、预览、保存或导出前，核对读取范围和直接调用方；有缓存不代表检查始终便宜。

| 入口 | 成本与使用边界 |
| --- | --- |
| [MediaTools.probeCompressionFile](../src/main/services/MediaTools.ts) | 有限探测格式与流摘要，不计算精确时长；用于批量选入文件，未确认的信息留待执行时检查。 |
| [MediaTools.probeFile](../src/main/services/MediaTools.ts) | 优先复用匹配源版本的完整索引摘要，不因短期缓存到期重新扫描。没有索引的非零起点 FLV 仍可能全片探测；裁剪入口须先经过共享索引服务，不将该分支带入批量选入、调参和保存。 |
| [BatchCompressionService.save](../src/main/services/BatchCompressionService.ts) | 校验路径、可读性和参数并持久化方案，不启动媒体探测；保存成功不等于素材已通过完整检查。 |
| [MediaIndexService](../src/main/services/MediaIndexService.ts) | 完整结果保存在数据目录，方案通过已确认的源版本表达关联。启动仅枚举索引记录及方案，不逐原片补关联或扫描媒体；索引初始化不阻塞方案加载，诊断通过详情或初始化完成通知展示。未完成写入走登记临时目录。 |
| [StreamPlaybackIndexService](../src/main/services/StreamPlaybackIndexService.ts) | FLV／正常 MPEG-TS 首次有限探测后分析一次，播放、逐帧、导出与修复共享在途任务或持久结果。异常提示后继续可取消分析；原片变化或真实读取失败则停止。最后一个使用者释放时可取消未完成任务。 |
| [KeyframeProber](../src/main/services/KeyframeProber.ts) | 普通 MP4 优先读取支持的采样表，跳过媒体负载；其他结构进行一次明确分析并持久保存。信息不足时停止依赖该能力的操作，不隐藏追加第二次全片解码。FLV 导出通过 IndexedFlvInput 向 FFmpeg 提供含位置目录的只读虚拟输入，实际按 Range 读取。 |
| [TimelineRepairService](../src/main/services/TimelineRepairService.ts) | 接续已完成或在途的原片分析，无损封装仍须完整读写保留内容。成品索引发布失败时保留新 MP4，按其采样表恢复准备，不再次修复原片。 |
| [PlaybackPreviewService](../src/main/services/PlaybackPreviewService.ts) | 其他格式的兼容播放副本：换封装读取整片并写磁盘，重新编码还增加编解码成本；不进入批量压缩的选入、调参和保存。 |

准备进度使用小响应，不反复传输关键帧或逐帧数组；完整数据在准备完成后取得。播放器成功取得引用后，工作台才释放准备引用，复用同一内存任务。取消、换片及退出按使用引用释放，不为交接建立长期内存缓存。阶段计时只作诊断，不写入方案或持久索引，也不增加媒体读取。

## 数据与产物归属

| 资产 | 保存与处理边界 |
| --- | --- |
| 程序目录 | 根启动器与 `app/` 保持完整；`workspace.json` 指向用户选定的数据目录。 |
| 数据目录 | 保存实际 `config.json`、方案、恢复记录及完整媒体索引；配置初始化以 ConfigService 为准。 |
| 用户原片与修复成品 | 属于用户素材；修复另存、导出不覆盖原片，不参与缓存淘汰。 |
| 裁剪与压缩产物 | 随原素材保存，规则与修改入口见[输出路径与命名](#输出路径与命名)。 |
| 运行缓存与中间文件 | 仅按登记归属及实际使用引用回收；容量是软目标，不能限制长视频正常使用。策略常量以 CacheMaintenanceService 为准。 |
| 构建候选与验证产物 | 登记与保护入口见 [portable-artifacts.ps1](../scripts/portable-artifacts.ps1)；清理命令见 [README](../README.md#开发与协作约束)。报告、日志、截图与媒体附件按归属和已有授权区分，不能仅凭位于临时目录就删除。 |

未知历史文件不会被自动认领。完整索引的保留规则不受运行缓存策略覆盖；临时目录也可能包含配置或已保存方案，清理前须核对实际引用。

### 输出路径与命名

裁剪与整片压缩分别使用原视频目录下的同类产物目录，不按方案另建目录；[Plan Title](../CONTEXT.md#plan-title)只参与命名。新产物使用未占用的路径，保留原片与已有文件；已有产物不追溯搬迁或重命名。

具体目录名、方案标题省略条件、分段标记与重名序号以 [OutputPathResolver](../src/main/services/OutputPathResolver.ts)为准，时间格式见其调用的 [timeUtils](../src/shared/timeUtils.ts)。修改或解释文件名时核对这两个入口，文档不另存一套格式模板。

## 界面与范围边界

界面采用 Motrix 风格，布局与交互演示维护在唯一[原型](prototypes/prototype.html)。业务确认使用应用内弹窗，保留取消入口及必要风险说明；文件／目录选择使用系统选择器。像素尺寸与手势阈值查实现，原型中的数据和处理进度只用于演示，不证明实际媒体能力。

为降低选框与时间轴手势的相互干扰，工作台将时间剪辑与画面处理分视图呈现，共用同一草稿；进入画面处理时暂停播放。画面处理再区分裁切与去水印／遮罩，作用范围以 [Spatial Scope](../CONTEXT.md#spatial-scope)为准；切换与编辑入口见 [CutterPage](../src/renderer/components/CutterPage.tsx)。

批量压缩的创建与单条编辑只维护整片压缩参数和方案，不包含播放预览、画质对比、分段裁剪或画面处理。文件选入与保存的检查时机见[媒体检查的耗时边界](#媒体检查的耗时边界)。

应用保持本地单机定位，当前不提供云同步、账号体系、多视频画中画或多轨混音。当前验证覆盖与暂缓事项分别从[任务归档](../archive/docs/20261023-已完成任务归档.md)和[待做事项](待做事项.md)进入；实现存在、定向验证通过与正式发布是不同状态。
