# 导出原片版本绑定方案

> 完成日期：2026-10-29。状态：已实施并归档。
> 验证结论：类型检查、16 项定向测试及短素材裁剪／整片压缩对比通过；身份读取、媒体命令与进程数保持，未新增扫描，复测未见稳定性能退化。详见[验收报告](../../../../videoCutTool_tmp/20261029-导出原片版本绑定/验收报告.md)。
> 源码基准：`b37b5e0`。

## 1. 目标与范围

在 `MediaCuttingEngine.ts` 同文件内，用执行数据绑定计划、必填原片版本和可复用的探测摘要，修复执行入口重新读取版本作为新基准、可能把旧方案切点用于新原片的问题。准备、执行入口和发布前始终对照本轮确定的同一个版本。

保留现有队列、保存顺序、重试语义及媒体处理流程。不增加扫描、探测、文件属性读取或等待阶段，不降低性能。成本边界遵循[架构](../../../docs/架构.md#媒体检查的耗时边界)，验证范围遵循 [README](../../../README.md#验证与交付)。

## 2. 技术路径

1. **同文件交接执行数据。** 增加普通只读类型 `PlanExecutionData`，包含 `plan`、`source: { identity: string; info?: ProbedFile }` 和 `compressionOnly`。`executeSnapshot` 接收该数据及现有取消信号；版本必填，摘要可选。复用 `Job.prepared` 已有的版本与摘要组合，不新增管理类、缓存、深拷贝或持久字段。
2. **裁剪沿用方案确认版本。** 缺少 `processing.sourceIdentity` 时，在媒体准备前失败；保留现有出队身份检查。探测返回后，比较已有的 `meta.sourceIdentity`，匹配才构造草稿和计划；缺失或不匹配均失败，不用当前文件版本替代确认版本，不自动重扫。
3. **压缩保留准备与重试行为。** 保留现有“读取身份 → 同版本复用摘要或探测 → 再次检查身份”的顺序，将版本与摘要一起交给执行阶段。准备信息保存失败重新入队后，仍按当前版本决定复用或重新探测；本轮准备成功后，版本贯穿时长保存、临时目录等待及后续执行，不重新建立基准。
4. **原有检查改为比较固定版本。** 执行入口现有身份读取与传入版本比较，通过后才使用摘要或继续现有探测；发布前现有检查也比较同一版本。原片变化沿用失败结果、状态保存和资源清理。虚拟输入、整理文件及裁剪产物继续使用自身媒体信息，不给每个中间步骤增加原片检查。
5. **收紧直接执行契约。** 保留 `executeRawPlan` 名称，参数改为完整执行数据，取消无版本的直接执行方式；目前只有测试中的三处调用，无生产调用。不增加缺省版本或兼容分支。工具配置仍在现有 `executionSnapshot` 时点捕获；`pendingFinal` 重试只保存结果，不重新校验原片或导出。

## 4. 行为变化与成本

- 裁剪确认 A 后，即使相同路径换成可正常处理的 B，也不能在执行入口改认 B 并发布旧切点结果。探测返回新版本时提前失败，等待期间换片在执行入口失败，处理期间换片由发布前检查拦截。
- 整片压缩在每轮准备时绑定版本；准备状态保存重试仍可按现有规则接受当前文件并重新探测。已完成结果的保存重试不受后来原片变化影响。
- 沿用现有文件身份定义与检查时机，不引入内容扫描、原片复制或文件锁。正常媒体命令、索引复用、硬件回退和取消流程保持原样。

| 路径 | 引擎直接读取原片身份：当前 → 实施后 | 探测与扫描 |
| --- | --- | --- |
| 已确认的队列裁剪正常完成 | 3 → 3 | 原有次数不变，新增元数据版本比较仅访问内存。 |
| 普通整片压缩正常完成 | 4 → 4 | 首次摘要探测及缓存命中行为不变。 |
| 完成结果保存重试 | 0 → 0 | 不探测、不扫描、不重复导出。 |
| 直接执行有效计划的执行体 | 2 → 2 | 原有次数不变；测试夹具自行提供版本。 |

以上仅统计引擎直接调用，探测和索引内部原有检查不变；测试准备版本的文件读取不计作生产路径收益。正常路径仅增加常量级数据传递和字符串比较。

## 5. 验收点

| 场景 | 通过标准 |
| --- | --- |
| 裁剪版本交接 | 缺少确认版本时不启动媒体准备；排队检查通过后，探测返回缺失或不同版本时不生成执行计划、不发布结果。 |
| 准备后换片 | 裁剪在临时目录等待期间换片，以及压缩准备后在时长保存／临时目录等待期间换片，均由执行入口拒绝，不使用旧摘要继续处理新原片。 |
| 处理中换片 | 发布前发现版本变化，结果失败且无本次正式产物；索引输入与临时资源按现有流程释放。 |
| 队列与重试 | 串行调度、去重、状态保存顺序不变；压缩准备保存失败后，同版本复用摘要、不同版本按原流程重新探测；完成结果保存失败后，只重试保存。 |
| 正常执行与成本 | 同素材、同配置、同缓存状态对比，身份读取、媒体探测／扫描及工具进程数不增加，媒体命令与处理顺序不变，输出正确、耗时无稳定退化；现有工具快照与资源归属用例继续通过。 |

实施前留存受影响路径基线；实施后只做类型检查、上述既有测试文件、一份短代表性素材的裁剪与整片压缩前后对比，以及文档链接与差异检查。用可控等待覆盖换片窗口，不靠反复长片导出碰时序。发现差异只复测对应场景，通过即停止；不扩展 UI／E2E、全量回归或正式打包。验证证据放入仓库同级 `../videoCutTool_tmp/20261029-导出原片版本绑定/`，注明样本与覆盖限制。
