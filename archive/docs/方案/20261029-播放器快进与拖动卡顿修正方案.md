# 播放器快进与拖动卡顿修正方案

完成日期：2026-10-29。状态：已实施并完成定向验证。

验证结论：真实原片两个慢点的跳转中位耗时由 533.6／618.9 ms 降至 67.1／87.5 ms；快进、连续拖动、失败停止与重试、手动预览边界、开发 StrictMode、已有索引 FLV 隐藏恢复和短片快速无损导出通过。类型及文档检查通过，未增加扫描、自动转码或解码切换开关。历史损坏包原始样本未取得，错误路径使用隔离故障素材验证，不据此承诺所有损坏录像均可播放。详见[验收报告](../../../../videoCutTool_tmp/20261029-播放器快进与拖动卡顿修正/验收报告.md)。

## 目标与推荐

恢复浏览器默认的解码选择，让支持的素材能够使用硬件解码，改善快进和拖动后等待画面的时间。保留快速无损导出，不增加扫描、素材体检或自动转码。

已确认的原因是全局禁用了硬件视频解码。本机同一旧包、同一原片的隔离对比中，两个较慢定位点由约 439–877 ms 降至 124–206 ms；这是本机实测依据，不代表所有素材和机器。详见[原排查报告](../../../../videoCutTool_tmp/20261029-旧版本跳转卡顿排查/排查报告.md)。本轮先修这个已确认的原因，保留现有准确定位和目标画面确认逻辑。

## 能否不重启就切换解码

- **现有播放器不能通过简单设置可靠地强制即时切换硬解／软解。** 当前使用原生 `<video>`，流式播放也接到同一个原生视频元素；现有解码开关属于程序启动参数，重新载入视频不能作为切换成功的保证。[Electron 文档](https://www.electronjs.org/docs/latest/api/command-line-switches)要求在应用就绪前设置启动参数。
- 真正由应用控制无重启切换，需要另行引入可控解码实现并验证音画同步、定位和资源释放，不属于本轮的简单修正。[WebCodecs 的解码偏好](https://www.w3.org/TR/webcodecs/#enumdef-hardwareacceleration)也不是现有 `<video>` 上能直接设置的属性。
- **推荐本轮不新增解码切换设置。** 由 Chromium 按设备、驱动和编码能力选择解码器，不强行绕过其兼容限制，也不承诺损坏录像一定能自动退回软解。
- 改动在更新后的程序启动时生效，当前已经运行的旧程序需要关闭后打开新版；日常换素材、快进和拖动不需要重启。“重试播放”只是重新载入，不代表切换解码器。

## 改动文件与行为

| 文件 | 实际改动 |
| --- | --- |
| [electron/main.ts](../../../electron/main.ts) | 移除无条件禁用硬件视频解码的启动开关及对应旧说明，恢复 Chromium 默认选择；不新增强制启用硬解参数或设置项。 |
| [VideoPlayer.tsx](../../../src/renderer/components/VideoPlayer.tsx) | 移除原生播放报错后自动调用 `preparePreview(false)` 的整片换封装及其尝试标记。报错时停止播放、使未完成定位失效并显示错误；保留重试。现有手动“生成兼容预览”入口仅在用户点击后执行，并说明会处理整片、导出仍使用原片；保留取消和释放流程。 |
| [docs/架构.md](../../../docs/架构.md) | 更新播放解码策略和错误处理边界，明确原生播放报错也不自动生成整片播放副本。 |

现有两个会话、索引共享、文件分流、导出队列和快速无损编码参数保持原样。不新增“异常素材识别”、后台检测、解码测速、预加载或转码服务。普通定位仍按现有路径读取所需媒体；不承诺首次建立 FLV 索引本来就没有整片分析，成本边界沿用[现有规定](../../../docs/架构.md#媒体检查的耗时边界)。

恢复默认解码后，个别损坏录像可能仍无法播放；必须清楚报错，不静默转码，也不以牺牲所有正常素材的跳转速度来掩盖失败。

## 必要验收

1. **真实素材定位计时：** 用此次录屏原片，在同机、相同 Electron 和已有索引下比较修改前后。检查 433.5 秒、1000 秒两个慢点，以及 7200 秒附近的对照点；每点少量重复，记录实际解码器和目标画面呈现时间。两个慢点中位耗时目标降至原来一半以内，快点无明显回退；不把鼠标操作耗时或仅触发 `seeked` 当作画面已就绪。旧包结果不代替修改后验证。
2. **实际操作：** 快进、后退、拖动并松开、短暂连续拖动和一次逐帧操作，确认最终画面与位置一致、旧定位不覆盖新位置；一次真实隐藏／恢复及开发模式 StrictMode 检查，不扩大为全量回归。
3. **错误边界：** 优先复用历史损坏包样本，检查错误后停止、重试及换正常素材可恢复。没有原样本则注明限制，用短测试素材或故障注入验证错误分支，不能据此宣称损坏录像兼容性通过。未点击手动预览时，错误不调用播放副本服务、不启动整片换封装或转码；手动入口仅做一次短素材定向检查。
4. **读取与导出：** 对一个已有索引的 FLV 做定位冒烟，确认索引复用、无新增整片任务。核对快速无损调用仍为流复制，并用一个短片段完成导出冒烟，不扫描或重编码整部原片。
5. **检查与交付：** 实施时执行 `npx tsc --noEmit`、`npm run check:docs` 和上述定向验证，通过即停止；不引入新测试框架，不因本次修改升级 Electron。测试使用隔离实例，证据放入仓库同级临时目录；不覆盖正在使用的旧安装包。

本方案已按上述范围实施并归档，验证结论和限制见文件头部；本轮未更新安装包。
