## 问题陈述 (Problem Statement)

用户在长时间轴精细剪辑与粗剪作业中，针对已建立的切点标记反馈了以下核心痛点：

1. **已插入切点无法自由移动，试错成本高**：  
   用户在时间轴打完切点后，如果发现切点偏前或偏后几帧，目前无法在时间轴上直接拖拽调整该切点位置；必须先删除切点、重新寻找目标画格并再次打切点，或者在下方卡片中反复点击微调按钮，操作链冗长繁琐。
2. **缺乏键盘直接指定时间的精确输入途径**：  
   用户无法直接对某个已有切点输入具体时间戳（如将某切点直接改为 `00:03:15.500`），难以与字幕时间轴或外部时间线标记精准对齐。
3. **主画面跳动造成视觉认知干扰**：  
   如果在拖动切点时直接强行跳转主播放器，会打断操作员原本正在播放或仔细比对的主画面，造成剧烈的视线跳跃与认知负荷。专业剪辑师更习惯主画面保持原位，而在拖动切点上方悬浮一个小窗实时预览局部画格。
4. **桌面与未来移动端的手势统一诉求**：  
   时间轴左键拖拽默认为播放游标寻址（Seek）。切点拖拽若直接以左键普通拖拽触发，容易引发“想寻址却误拖了切点”或“想拖切点却移动了游标”的操作冲突，且无法自然平滑移植到移动端触屏交互设备。

## 解决方案 (Solution)

基于 ADR 0004 确立的架构规范，建立一套兼顾工效、无损数学不变量与沉浸式体验的全新切点交互体系：

1. **三重手势分流与长按 300ms 唤醒**：
   - **短按 / 单击（< 300ms）**：选中切点，高亮显示切点线，下方对应的分段卡片平滑滚动居中并高亮呼应；
   - **快速双击**：切点上方就地（In-place）浮现暗黑微型输入气泡，支持键盘直接输入或粘贴时间码，按回车精确修改，按 Esc 取消；
   - **长按（>= 300ms）**：切点顶部菱形旗标产生 Scale 1.25 弹性微放大动效并呈现高亮亮蓝光晕，光标变为抓取手势（`grabbing`），激活拖拽模式并呼出悬浮画格预览小窗。天然兼顾桌面鼠标与未来移动端触屏操作。
2. **独立解耦的悬浮画格微型预览（Scrub Thumbnail Preview）**：
   - 拖拽切点时，**主播放器画面保持原位正常播放或停留，绝不强行跳转 Seek**；
   - 切点正上方悬浮跟随一个 `160x90`（标准 16:9）暗黑圆角发光小窗，通过后台专用的轻量级辅助离线渲染单元提取目标时间戳的真实画格；
   - 小窗底部集成显示毫秒级时间码（`HH:MM:SS.mmm`），并在吸附时显示青色 `● 关键帧已吸附` 徽标，在达到物理限制时显示红色 `已达相邻切点极限` 警告。
3. **物理安全不变量与关键帧向近磁吸**：
   - **碰撞不穿透**：底层严格执行数学限位，切点严禁穿透相邻切点，且与前后切点及视频首尾必须保持至少 200ms 物理安全间距；
   - **关键帧向近磁吸**：当拖拽距离物理关键帧在 ±8px 视窗范围时，切点自动产生磁吸贴合，引导操作员落点在最佳零重编码切割点。
4. **下方卡片流双向联动**：
   - 分段卡片上的入点/出点时间码同样支持直接点击打字输入，与时间轴双击输入完全双向同步。
5. **原子历史快照与决策保全**：
   - 拖拽松手（`mouseup`）或时间码输入确认时，原子推入一次 Undo 历史快照，支持 `Ctrl+Z` 一键撤销整个拖拽位移；
   - 移动切点仅改变两侧分段的时长边界，严格保留原分段既有的 `keep` / `discard` 决策。

## 用户故事 (User Stories)

1. 作为一名剪辑师，当我发现已有的某个切点位置稍有偏差时，我希望能用鼠标在切点旗标上**长按片刻直接向左或向右拖动**，以便于快速校正切点位置而无需删掉重来。
2. 作为一名习惯触屏与平板交互的用户，我希望通过**长按 300ms 激活拖动**，以便于该操作手势在移动设备和触屏显示器上同样自然可用，且不与快速点击冲突。
3. 作为一名精细剪辑师，在拖拽切点时，我希望**主播放器继续保持当前画面不被打断**，同时在切点上方**浮现一个微型小窗实时预览我当前拖到的画格**，以便于我无需转移视线就能精准捕捉镜头切换瞬间。
4. 作为一名追求无损剪辑效率的用户，在拖拽切点靠近关键帧时，我希望切点能**自动轻微吸附到该关键帧**并在小窗提示青色微标，以便于我轻松切在物理关键帧上达成秒级无损导出。
5. 作为一名注重安全边界的操作员，在拖动切点靠近前一个或后一个切点时，我希望时间轴有**清晰的 200ms 碰撞墙阻挡**，以便于绝不发生分段交错或倒挂错误。
6. 作为一名有精确时间记录的视频编辑者，我希望能**双击时间轴切点直接输入时间码（如 00:02:14.300）**，或者在下方卡片时间码上直接敲字修改，以便于分秒不差地指定目标时间。
7. 作为一名操作员，在拖拽松手或修改时间后，如果发现改错了，我希望按 **`Ctrl+Z` 能够一步完整撤回**，且分段的原有保留/丢弃决策完全不受影响。

## 实现决策 (Implementation Decisions)

### 1. 将要构建与修改的模块

- **核心领域深模块**：[`src/shared/RetentionDraft.ts`](file:///d:/Projects/litleTools/videoCutTool/src/shared/RetentionDraft.ts)
  - 新增 `moveCut(cutIndex: number, newTimeMs: number): boolean` 领域方法；
  - 严格封装 200ms 碰撞墙防撞算法：`prevBound + 200 <= newTime <= nextBound - 200`；
  - 内部 `intervals` 连续区间原子更新（前段 `endMs` 与后段 `startMs` 同步设为 `newTime`），保留决策 `decision` 保持原值。
- **时间轴画布交互组件**：[`src/renderer/components/Timeline.tsx`](file:///d:/Projects/litleTools/videoCutTool/src/renderer/components/Timeline.tsx)
  - 引入切点长按状态机：`longPressTimerRef`、`isCutDraggingRef`、`draggedCutIndexRef`；
  - 绘制层：长按激活状态下，当前切点顶部菱形以 Scale 1.25 放大重绘，外圈增加蓝色光晕脉冲；
  - 吸附计算：在屏幕像素空间计算与物理关键帧的距离（`|kx - currentX| <= 8px`），命中时磁吸吸附；
  - 悬浮画格预览小窗：在切点上方定位渲染 `160x90` 浮层，内部挂载独立辅助解码器；
  - 就地时间码输入气泡：双击时在切点坐标绝对定位渲染 `<input>` 浮层，按 Enter 调用更新，按 Esc 关闭。
- **辅助画格离线渲染单元**：[`src/renderer/components/TimelineThumbnailPreview.tsx`](file:///d:/Projects/litleTools/videoCutTool/src/renderer/components/TimelineThumbnailPreview.tsx) (新建)
  - 封装专用的隐蔽辅助 `<video>` 实例，通过 `currentTime` 精确寻道当前拖动时间戳；
  - 负责显示微型画格、时间码与吸附徽标，主播放器完全解耦。
- **分段卡片流**：[`src/renderer/components/SegmentCardsGrid.tsx`](file:///d:/Projects/litleTools/videoCutTool/src/renderer/components/SegmentCardsGrid.tsx)

### 2. 状态机与手势判定逻辑

```typescript
// 切点长按与拖拽状态机
interface CutDragState {
  isDragging: boolean;
  cutIndex: number;
  originalTimeMs: number;
  currentTimeMs: number;
  isSnappedToKeyframe: boolean;
  isHitBarrier: boolean;
}
```

- **MouseDown**: 若光标落在切点热区（±8px）内，启动 `setTimeout(300ms)` 定时器；
- **MouseMove**: 若定时器尚未触发且位移超过 5px，判定为普通 Seek 或拖动；若长按定时器已触发，切点进入 `isDragging = true`，呼出小窗跟随光标计算限位与磁吸；
- **MouseUp**: 若未达 300ms 则触发普通选中（或双击检测）；若处于 `isDragging`，调用 `onMoveCut` 落地最终位置并销毁小窗。

## 测试决策 (Testing Decisions)

坚持轻量纯函数单测原则（严格遵守 `AGENTS.md`：严禁引入成套重型 UI 测试体系，仅在 `tests/RetentionDraft.test.ts` 中针对核心领域算法补充单测）：

1. **测试 Seam**：
   - 聚焦于唯一的纯函数 Seam：`RetentionDraft.moveCut(cutIndex, newTimeMs)`。
2. **测试覆盖场景**：
   - **合法位移测试**：将中间切点在合法安全区间内向左/向右移动，验证两侧相邻分段的 `startMs` 与 `endMs` 精确更新；
   - **碰撞屏障硬拦截测试**：试图将切点拖动至距离前一切点 < 200ms 或距离视频开头 < 200ms，验证返回 `false` 且切点时间保持原值未被破坏；
   - **决策保全不变性测试**：移动切点后，验证前一段的 `decision` 与后一段的 `decision`（无论是 keep 还是 discard）100% 保持不变，绝对不发生状态漂移。

## 范围外说明 (Out of Scope)

1. **不引入音频波形图生成**：切点拖拽仅依赖视频物理时间轴与关键帧，不加载重型音频解码与波形绘制；
2. **不改变底层 FFmpeg 剪辑执行管线**：切点位移只作用于草稿层与方案层，后台剪辑引擎继续使用原有的无损流复制管线；
3. **不支持多切点框选批量平移**：本期专注于单切点的极精细拖拽与微调，暂不引入多选批量位移。
