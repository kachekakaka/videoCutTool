状态：已实施并验证，完成日期：2026-10-17。
验证结论：生产构建、Electron Playwright 交互、CPU/NVENC 媒体输出、部分失败及存储恢复、既有裁剪和画质对比回归均通过；1100 个文件授权未被淘汰。详细记录位于仓库同级 `videoCutTool_tmp/walkthrough.md`。

## 1. 已确认的使用方式

用户已逐项接受两轮访谈推荐，核心流程为：

**进入“批量压缩” → 多选或拖入视频 → 统一设置参数和输出位置 → 保存独立方案 → 在方案中心选择执行。**

| 项目 | 已确认内容 |
| --- | --- |
| 页面入口 | 左侧新增“批量压缩”，只提供文件列表、参数、输出位置和保存操作。 |
| 处理范围 | 每个视频整片压缩、分别输出；不合并多个视频，不做裁剪、画面处理、播放预览或画质对比。 |
| 文件添加 | 文件对话框多选、一次拖入多个文件；可以追加、逐项移除和清空。不扫描文件夹。 |
| 重复文件 | 当前列表按路径去重；不同目录的同名文件分别保留。不按文件内容去重，也不阻止同一素材以后再次创建方案。 |
| 压缩参数 | 整批共用一套参数；沿用高画质、均衡、高压缩、降至 1080p、自定义画质、分辨率限制和硬件加速；音轨原样保留。 |
| 保存粒度 | 一个视频一条 Plan Record；一次保存全部有效项，但不立即执行，不创建批次父记录。 |
| 方案标题 | 默认取不带扩展名的原文件名，允许在列表逐项修改，不逐个弹窗命名。 |
| 输出位置 | 默认沿用系统输出目录规则；可以为本批统一指定目录；沿用现有命名及重名避让规则。 |
| 部分失败 | 无效项不能保存，正常项继续；成功项不回滚，失败项显示原因并可重试。重试不重复创建已保存记录。 |
| 执行 | 方案中心增加勾选执行，保留执行全部待办；后台沿用逐个执行队列。 |
| 编辑 | 批量压缩创建的方案回到简洁压缩页面，单条修改标题、参数和输出目录；裁剪方案仍进入裁剪工作台。 |
| 列表生命周期 | 切换页面保留列表和参数；保存后停留当前页，成功项移出待保存列表、失败项保留，提供“前往方案中心”。 |
| 参数生命周期 | 本次参数保留，便于继续添加下一批；关闭软件后不恢复未保存列表和参数，已保存方案正常保留。 |

第一版不增加逐文件压缩参数覆盖、已保存方案的批量参数编辑、文件夹扫描、并行压缩或未保存草稿的重启恢复。

## 3. 记录与草稿设计

### 3.1 单文件方案记录

在 `PlanRecord` 增加可选的正向业务标记 `compressionOnly?: true`。标记存在表示该记录只允许整片压缩，并决定简洁编辑入口和直接压缩执行路径；普通裁剪记录不设置该标记。不能仅凭“没有切点且开启压缩”判断来源，否则会把裁剪工作台创建的方案错误分流。

这是记录能力的表达，不引入格式版本兼容分支或数据迁移。已有裁剪记录和新建裁剪记录都遵循相同的普通裁剪契约；主进程拒绝标记值错误或标记与内容矛盾的记录。

整片压缩记录必须满足：

- `compress.enabled` 为真，参数来自现有 `CompressConfig` 契约。
- `cuts` 为空，`decisions` 为 `{ seg_0: 'keep' }`，保留时长等于源视频时长，切点数为零。
- `concatSingleFile` 固定为真，只表示该源视频输出一个文件，不代表跨文件拼接。
- 不含空间裁剪、遮罩或分段覆盖配置；封面处理沿用系统当前设置并保存到记录中。
- 每条有独立 ID、标题、输出位置和执行状态；创建后参数为独立快照。
- 新建及编辑保存后为 `ready`；更新旧记录时清除上次执行的错误、完成时间、产物路径列表和实际编码器等结果字段，避免显示过期成功结果。

记录构造与验证集中处理，页面不直接拼装不受校验的磁盘记录。底层整片执行不伪造关键帧，也不调用保留区间向外吸附算法。

### 3.2 页面内存状态

批量创建与单条编辑使用分开的内存状态，同一个页面呈现两种表单。进入单条编辑不能覆盖尚未保存的批量列表；返回批量创建后继续原来的草稿。

每个待保存文件持有稳定的条目 ID、规范化路径键、标题、元数据、检查状态及错误信息。首次保存前分配稳定方案 ID；失败后重试仍使用相同 ID，不在每次点击时生成新 ID。

切换 Tab 不销毁草稿。移除、清空、切换被编辑记录后，异步检查必须通过条目 ID 和请求代次判定结果是否仍有效，不能把已移除文件重新插回列表。软件关闭后不持久化这些草稿。

## 4. 导入、参数和输出位置

### 4.1 导入及检查

1. 多选对话框使用视频过滤器及 `multiSelections`；取消返回空集合，不改变已有列表。
2. 多选结果逐项授权并返回逐项成功或错误，不用一次整体失败吞掉有效项。拖放仍通过 preload 的物理文件路径能力取得路径，逐项进入同一流程。
3. 主进程规范化绝对路径；Windows 路径键忽略大小写，其余平台保留大小写。同一键在当前列表只保留一项，不比较文件内容。不同目录同名文件显示目录辅助区分。
4. 使用已有 `MediaTools.probeFile()` 获取基础信息并检查可处理的视频流；不加载播放器，不生成缩略图、兼容播放副本、对比样本或关键帧索引。
5. 检查按队列逐个进行，显示“检查中／可保存／错误”，避免大量文件同时启动媒体工具。部分特殊容器可能仍需要时间戳读取，不承诺所有文件瞬时完成检查。
6. 不扫描目录；文件夹及无法识别的视频显示逐项原因。检查完成才允许该项保存，其他有效项可独立保存。
7. 文件授权保持“用户实际选择或拖入”的来源边界，并继续检查路径实际目标。去掉对当前窗口已授权素材的固定容量淘汰，登记按现有清理生命周期释放，不能因列表较大静默拒绝前面的素材。

基础检查只能确认可识别的媒体信息，不能保证整片每一帧都可解码；后续解码失败仍按单条执行失败处理。

### 4.2 参数与目录

- 参数控件直接使用 `compressPresets.ts` 的预设数据及现有参数含义；默认均衡和开启硬件加速。将当前裁剪页参数控件提取为共享组件，预览按钮继续由裁剪页单独提供。
- 本批统一参数不改变已保存方案；逐项标题独立修改。标题去除首尾空白后不能为空，并按现有文件名限制校验。
- 输出位置有“使用系统规则”和“指定本批目录”两种状态；指定目录只影响本批，不能调用保存全局配置的接口。
- 每次保存开始时快照本次参数与输出规则，逐文件解析输出目录、容器及预定路径，避免保存期间修改系统设置导致同批参数混用。
- 保存后目录固定在该条记录中；实际执行时仍按启动时间、标题、源文件名及当前磁盘占用重新分配最终文件名，不提前创建空产物或承诺预定名称永不变化。
- 最终容器继续由现有流保留规则选择；不能强制全部 MP4 而丢弃不兼容音轨。整片压缩保证按所选参数执行，不保证输出一定比输入小，也不新增目标大小或自动丢弃成品规则。

## 5. 保存与单条编辑

新增小型 `BatchCompressionService`，负责基础信息读取、整片记录构造、目录解析及保存衔接；持久化仍只调用 `PlanManager.savePlan()`。它不维护第二份方案列表或执行队列。

页面串行调用单条保存接口，形成一次批量保存操作：

1. 冻结本次有效文件及参数快照；保存期间禁用重复提交和会改变本次内容的控件。
2. 主进程复核素材授权、基础信息、标题、参数、目录及整片限制，再保存对应 ID。
3. 只有收到持久化成功确认才把条目从待保存列表移除；单条错误留在列表并继续下一条。
4. 汇总“成功 X 条、失败 Y 条、仍在检查 Z 条”，停留当前页并提供“前往方案中心”。保持本次参数和目录选择，便于继续追加文件。
5. 若调用中断导致保存结果未知，先按稳定 ID 查询已有记录核对，再重试；不能盲目新建 ID。保存结果由现有方案变更事件同步到方案中心。

单条编辑加载已保存的整片压缩记录，隐藏文件追加、移除及批量保存控件，只编辑标题、压缩参数和输出目录；保存更新同一 ID。页面返回批量模式时恢复原批量草稿。正在排队、执行或等待结果落盘的记录禁止覆盖保存，主进程继续做最终校验。

编辑裁剪方案仍走当前裁剪工作台，不能为了编辑压缩参数误抹掉已有切点或画面效果。普通裁剪记录的创建流程不设置整片压缩标记。

## 6. 方案中心与后台执行

### 6.1 勾选执行

- `PlansPage` 增加复选框、选中数量和“执行选中项”；允许选择未提交及失败记录。已完成方案保留现有单条重新导出操作，处理中及排队记录不可重复选入。
- 全选明确为“选择本页可执行项”；翻页、切换筛选时清空选择，避免隐藏项被无意执行。状态变为不可执行或记录被删除时同步移出选择集合。
- 新增 `executeSelectedPlans(ids)` 接口，只对传入 ID 去重并逐项复核后提交，不能把空集合或过期 ID 当成全部待办。
- 原有“批量执行待办”继续只处理全部 `ready` 记录；不改变其状态范围。两种入口均返回接受数量与逐条错误。
- 卡片标识“整片压缩”，编辑按钮根据业务标记路由；现有订阅机制继续更新状态与单条进度。

### 6.2 整片直接压缩

在 `MediaCuttingEngine` 的现有队列中按整片压缩标记分流，普通裁剪路径保持原有职责。整片路径执行顺序为：

**基础探测 → 必要的时间戳整理 → 整片转码 → 产物校验 → 防覆盖发布 → 保存完成状态。**

具体要求：

1. 不调用完整关键帧探测、`RetentionDraft.toPlan()` 或 `cut()`，不为正常素材额外生成整片无损切片。
2. 保留必要的异常时间戳整理；需要时只整理一次，再整片编码，不增加片段寻址或拼接。正常文件直接读取原片。
3. 使用现有编码器探测与自动回退规则、`buildCompressArgs()` 和容器解析；按实际保留流显式映射全部应保留音轨，处理封面开关，不能沿用“中间输入已筛选”的假设。
4. 共用现有校验、排他发布、防覆盖重试和本任务临时目录清理。提取必要的小型共享方法，避免复制完整执行管线。
5. 进度仅登记实际存在的步骤，不显示虚假的裁剪、合并阶段；编码结束后仍需校验、发布、保存，全部成功才视为完成。
6. 继续使用一个后台任务槽位。单个解码或编码失败记录为失败后继续下一条；持久化失败继续使用现有暂停及重试保存流程。
7. 素材在保存后移走、删除或无法解码时，仅对应记录失败并给出原因；关闭软件后的执行恢复继续使用现有中断状态，不新增自动续传或断点编码。

## 8. 实施顺序

1. 核对当前工作区已有改动；在其基础上实施，不覆盖其他任务尚未提交的修改。同步唯一交互原型的批量压缩页和方案勾选交互。
2. 完成数据标记与校验、导入检查及保存服务、目录覆盖和 IPC 契约。
3. 新增常驻批量页面、共享参数组件和单条编辑分流；完成部分成功、异步检查失效处理和重复提交防护。
4. 增加选中执行入口，再接通后台整片直接压缩路径与实际步骤进度。
5. 构建及一次性交互、媒体验收，修正发现的问题；仅在验证通过后归档本方案。

## 9. 验收标准

| 场景 | 通过标准 |
| --- | --- |
| 新增入口 | 左侧出现批量压缩；1360px 内容中轴和现有视觉风格保持一致；唯一原型同步。 |
| 多选与拖放 | 多选及多文件拖放均可追加；取消不清空；目录不展开；移除和清空后迟到结果不回填。 |
