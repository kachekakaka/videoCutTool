## 问题陈述 (Problem Statement)

在日常使用桌面端视频裁剪工具时，用户在界面排布与视觉体验上面临以下局部痛点：
1. **主视频视窗纵向受挤压**：在 1080p 显示器或普通窗口下，主工作台下方纵向排列了控制行、时间轴、分段列表头、选择合并按钮、分段卡片、独立占两行的输出提示文本、底栏、边界提示，层级多达 7~8 层，造成核心的主视频视窗垂直高度偏紧，观察画面细节与关键帧微表情不够充裕。
2. **底栏白底下拉框视觉突兀且操作繁琐**：底部 Dock 栏中的“输出方式”使用了原生白底 `<select>` 下拉框（`全部合成一个 ∨`），与暗黑主色调产生刺眼反差，且需要额外点击一次展开浮层才能选择。
3. **输出提示说明独占空间**：分段卡片下方的输出提示文本（`将输出 1 个文件 按原视频顺序拼接`、`文件 1 ： 第1段`）单独占据两行（约 30px）垂直空间，当分段增多时进一步拉长页面。
4. **多切点时卡片无限向下撑开页面**：切断产生 5~10 个以上分段时，现有单列横向长卡片会无节制地向下撑长，破坏单屏直观掌控感。

## 解决方案 (Solution)

以当前真实运行的软件界面为 **100% 视觉基线**，不颠覆现有架构，不做任何破坏肌肉记忆的推倒重来，仅针对上述痛点实施克制、精准的局部微调：
1. **平铺式深色分段胶囊替换白底下拉框**：底栏“输出方式”改为与整体风格融合的深色分段药丸按钮（`[分别输出]` `[全部合成]` `[自定义合并]`），实现零层级一键直选。
2. **收纳输出提示文本以释放垂直视野**：将卡片下方独占两行的拼接说明收纳为“分段列表 (N)”标题栏右侧的精巧胶囊徽章（`📦 预定输出 X 个文件`），鼠标悬浮展示具体合并映射，释放约 30px 高度。
3. **轻度收拢垂直间距**：轻度精炼各板块间的上下 padding 与 gap，将释放出的 40~60px 垂直高度全额补贴给主视频视窗，视窗采用弹性充满（`flex: 1`），让画面更舒展聚焦。
4. **双排网格紧凑滚动卡片**：分段卡片规格优化为双排紧凑网格（高度锁定在约 108px），超出两排时在卡片容器内顺畅独立滚动，不再无节制下坠。
5. **忠实保持操作流与轨道顺序**：
   - 控制行与时间轴严格维持“控制行在上、时间轴在下”的排布不动；
   - 多段合并依然沿用原有的 `[选择合并片段]` 交互模式，卡片自身不增加额外认知负担；
   - “首帧封面”微调至导出模式右侧，逻辑归属更自然。

## 用户故事 (User Stories)

1. 作为一名经常需要精确剪辑长视频的剪辑人员，我希望中央视频播放视窗能占据更充裕的垂直视野，以便于更清晰地观察画面细节与关键帧微表情。
2. 作为一名暗色主题用户，我希望底部的输出方式选择具备与工作台一致的深色胶囊外观，以便于在不产生刺眼白底反差的前提下一键直接切换输出模式。
3. 作为一名需要对视频进行密集切片的用户，我希望在切出多个分段时卡片能规整地以双排紧凑排列并支持内部独立滚动，以便于快速检视多个片段信息而不会让整个桌面页面无限向下撑开。
4. 作为一名熟悉当前操作快捷键与布局习惯的用户，我希望控制行和时间轴的相对上下顺序保持不变，以便于我无需重新适应肌肉记忆即可直接上手。
5. 作为一名导出使用者，我希望在分段标题右侧能一眼看到预定输出的文件总数，并可通过悬浮直观了解片段拼接关系，以便于在不浪费垂直空间的前提下确认导出产物结构。

## 实现决策 (Implementation Decisions)

以下保留原定设计；最终实现以链接的源码为准。实际卡片容器最大高度为 160px，列数按窗口宽度响应变化，并非固定双列或 108px。模式切换移入顶栏，涉及 `src/App.tsx`、`Header.tsx` 和 `WorkbenchModeBar.tsx`；空间工具栏按需显示。`VideoPlayer.tsx` 取消固定最小高度，避免窄窗口下画面和裁剪框伸入播放控制栏。自定义合并仍保留拆分入口。原型同文件追加 V2 Tab，其中连结按钮和模拟画面属于交互演示，不代表桌面应用新增对应能力。

### 1. 将要修改的模块与组件
- [`src/renderer/components/CutterPage.tsx`](../../../src/renderer/components/CutterPage.tsx)：主工作台页面容器与底栏排布
- [`src/renderer/components/SegmentCardsGrid.tsx`](../../../src/renderer/components/SegmentCardsGrid.tsx)：分段卡片网格容器与排版
- [`docs/prototypes/prototype.html`](../../../docs/prototypes/prototype.html)：原型真源文件（同步收敛对齐该微调）

### 2. 详细界面微调规范

#### A. 底栏输出方式（`CutterPage.tsx`）
- 替换目标：将现有的原生 `<select value={outputMode} onChange={...}>` 替换为无障碍单选分段按钮组（Segmented Pills）；
- 选项包含：`分别输出`、`全部合成`、`自定义合并`；
- 行为与绑定：点击时直接调用原有的 `setOutputMode('separate' | 'single' | 'custom')`，保持状态响应与下游导出计算 100% 不变。

#### B. 标题栏徽章与文本收纳（`CutterPage.tsx`）
- 移除卡片下方的独立提示文本块（`将输出 X 个文件...`）；
- 在 `✂ 分段列表 (N)` 标题右侧插入胶囊徽章：
  - 显示文案：`📦 预定输出 ${outputFiles.length} 个文件`；
  - `title` 属性绑定各文件的片段映射（如 `文件 1: #1 + #2`），实现悬浮浮层提示。

#### C. 垂直高度弹性充满（`CutterPage.tsx`）
- 主工作台外层容器保持单屏高度约束（避免出现整页外层大滚动条）；
- 视频视窗外层使用 `flex: 1; min-height: 240px;` 自适应充满剩余竖向空间；
- 将各板块上下 padding / gap 适度收拢（如由 `gap-4` 微调为 `gap-2.5`）。

#### D. 分段卡片双排紧凑流（`SegmentCardsGrid.tsx`）
- 卡片容器包裹层样式调整为：
  `grid grid-cols-1 md:grid-cols-2 gap-2 max-h-[108px] overflow-y-auto pr-1`；
- 卡片内部保持原有交互：起止时间、保留/丢弃切换、试听、微调按钮；
- 单张卡片高度精炼至 50px 左右，两排时正好填满 108px，超出时平滑纵向滚动。

#### E. 首帧封面复选框平移
- 仅将已有的 `<input type="checkbox" checked={coverFirstFrame} ... />` 节点移至导出模式（快速无损/精确导出/智能降码）右侧，与导出配置项逻辑成组。

## 测试决策 (Testing Decisions)

### 1. 测试标准与范围
- **只测外部公开行为，不测样式实现细节**：验证组件渲染后是否正确挂载、是否能正确响应交互与切换状态；
- **既有测试无回归**：执行 `npm test`（Vitest），确保所有既有 116 个单元/集成测试 100% 通过；
- **文档链接校验**：执行 `npm run check:docs`，确保文档与超链接 0 错误 0 警告。

### 2. 关键验证用例清单（人工验收步骤）
1. **输出方式切换验证**：点击“分别输出”、“全部合成”、“自定义合并”，底栏按钮高亮状态即时切换，底层 `outputMode` 正确更新；
2. **多片段双排排列验证**：连续插入 4 个以上切点，分段列表规整呈现为双列网格，超出 2 排时内部可流畅滚动，主视窗与底栏不发生位移挤压；
3. **输出汇总徽章验证**：观察分段标题右侧 `📦 预定输出 X 个文件` 徽章，数字随切点与合并操作联动更新，鼠标悬浮可查看清晰的分段拼接对应关系；
4. **视频视窗大视野验证**：在 1080p 及常规窗口下，主视频视窗高度充盈，页面外层无异常垂直滚动条；
5. **全流程剪辑验证**：点击“存为方案”与“立即剪辑”，导出任务成功生成，产物行为与微调前完全一致。

## 范围外说明 (Out of Scope)

- **绝不改动任何后端剪辑与媒体处理逻辑**：不触碰 `ffmpeg`、`ffprobe`、关键帧探测算法与命令组装；
- **绝不改动数据模型与持久化结构**：不新增、修改或废除 `RetentionDraft`、`RetentionPlan` 的数据契约与 Schema；
- **不引入重型第三方 UI 组件库**：纯基于 Tailwind CSS / 内联样式原生构建，保持极简轻量；
- **不做多重布局向后兼容配置**：遵循 KISS 原则，直接改写为理想微调布局，不增加无谓的“旧布局/新布局”用户切换开关。
