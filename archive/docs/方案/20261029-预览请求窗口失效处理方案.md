# 预览请求窗口失效处理方案

> 完成日期：2026-10-29。状态：已实施并归档。
> 验证结论：类型检查及 12 组定向检查通过；冷／热预览的扫描与媒体调用次数未增加，缓存复用保持，冷编码专项复测未见稳定退化。详见[验收报告](../../../../videoCutTool_tmp/20261029-预览请求窗口失效处理/验收报告.md)。
> 源码基准：`a0da1c2`。

## 1. 目标与范围

采用**页面代次上下文＋按代次清理**，解决旧页面请求迟到启动预览、旧清理误释放新页面引用，以及窗口关闭后迟到授权重新写入的问题。

仅调整兼容播放预览和画质抽样预览的主进程交接边界。保留两个现有预览服务，由服务继续持有请求、取消控制器和缓存引用；主进程只判断页面归属。保持前端 IPC、流式准备／播放两个会话及媒体处理算法不变，不新增任务管理器、请求登记表或取消监听体系。

遵循[媒体检查的耗时边界](../../../docs/架构.md#媒体检查的耗时边界)及[验证与交付](../../../README.md#验证与交付)。不增加扫描、探测、通信往返或正常等待；性能要求由定向验收确认。

## 2. 技术路径

1. **统一捕获页面上下文。** 在 IPC 进入、等待 `configChanges` 之前记录原页面代次，复用现有可信来源校验和频率限制。上下文只提供内部键、有效性判断及断言；检查代次、导航准入、`quitting`、窗口销毁／崩溃，以及重新读取的 `event.senderFrame` 是否仍为有效主框架。

2. **请求和引用按代次归属。** 两组预览的启动、取消、释放及取消标记统一使用 `窗口 ID:页面代次:请求 ID`。窗口失效时先记录旧前缀、同步推进代次，再调用原有 `releaseOwner(旧前缀)`；新页面不等待旧清理完成。代次只用于内存中的归属键，**不进入磁盘内容缓存键**，保留跨刷新缓存复用。

3. **明确导航边界。** 将已有窗口代次记录扩为代次与预览准入标志，不建立另一套代次。主框架跨文档导航开始时关闭准入并清理旧代，`did-navigate` 后恢复；不等待 `did-finish-load`，不按整个页面仍在加载而拒绝新文档。导航被阻止、取消或失败后，若没有新的主文档导航在进行、原可信主文档仍可用，应恢复新请求准入，旧代请求仍保持失效。生命周期监听在首次 `loadURL/loadFile` 前注册。崩溃、销毁同样使旧代失效；普通切 Tab、视图切换、最小化和同文档导航不推进代次。原流式打开及修复继续读取同一代次数值。

4. **只在交接点把关。** 配置等待后、原有文件检查后、媒体结果返回后、结果交付前检查同一上下文。启动前最后一次检查与服务登记之间不再 `await`。进度仅向仍有效的原页面发送；失败或失效沿现有 `catch → release(本次键)` 收尾。运行中取消与退出继续由原有服务清理和 `shutdown()` 完成。

5. **封住授权回写。** `FileAccessRegistry.authorize(file, assertCanRegister?)` 增加可选同步断言，仅两个预览入口传入。在现有 `realpath/stat` 完成后、首次授权表写入前调用，断言与写入之间不再等待。保持画质预览的并行授权，不增加文件检查，不引入授权代次表或事后撤销流程。

6. **保持取消职责清晰。** 取消和释放经过鉴权、捕获原代次后直接执行，不等待配置变更；启动仍等待配置。单请求取消保留原有启动前一次 `checkCanceled` 和服务内 abort，不把删除式取消检查复用为反复调用的页面有效性判断。

## 4. 验收点

| 场景 | 通过标准 |
| --- | --- |
| 等待配置／文件检查时失效 | 等待结束后拒绝旧请求，不登记预览任务、不启动媒体进程；退出期间同样成立。 |
| 运行中失效，旧清理与新页面并行 | 旧请求取消并收尾，旧代请求和引用最终归零；新代引用保留，即使两代使用同一请求 ID；旧进度不进入新页面。 |
| 授权期间失效 | 不发生清理后的迟到授权写入、不交付旧结果；本次缓存引用释放。 |
| 主文档切换 | 导航间隙不接收旧文档预览；新文档提交后即可使用，不等全部资源加载；被阻止或取消的导航不使仍可用的页面永久失去预览能力；同文档导航不清理引用。 |
| 正常预览与控制 | 两种预览正常返回，原有取消、释放、错误处理有效；共用代次读取的流式打开保持可用。 |
| 读取与性能 | 相同素材、参数及冷／热缓存条件下，对比实施前后媒体扫描、探测、进程调用次数与完成耗时；调用次数不增加，缓存命中保持，耗时无稳定退化。单次波动只复查受影响路径。 |

实施后运行类型检查及上述定向验证。异步边界使用可控延迟配合实际 Electron 页面刷新、崩溃或关闭，各覆盖必要场景，不做全组合测试；不引入测试框架、全量回归或额外长片扫描。验证入口、报告要求以 README 为准，脚本和证据放在仓库同级 `../videoCutTool_tmp/20261029-预览请求窗口失效处理/`。
