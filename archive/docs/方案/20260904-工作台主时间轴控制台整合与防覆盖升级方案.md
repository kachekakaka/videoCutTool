## 1. 背景与现状诊断

经过多轮真实视频裁剪与用户使用实测，发现当前版本存在以下 4 项核心交互痛点与安全隐患：

### 1.1 核心问题诊断
1. **播放控制与时间轴物理割裂，视线往返跳跃**：
   - 视频播放器内嵌了独立的底栏控制条（高 44px），下方又独立放置了一整块时间轴（高 60px）；
   - 视线与操作割裂：用户点击播放/暂停控件时，视线必须跳到下方看时间轴指针；视频视窗本身也被内嵌控制栏压缩了垂直空间。
2. **分段卡片流过于庞大，产生突兀垂直滚动条**：
   - 每张分段卡片采用 3 行式宽松排布（序号行、独立大时间码行、底部按钮微调行），单卡高度达 `135px`；
   - 导致在标准窗口下分段列表占用大量高度，即使只有 3 段也会强行挤出系统原生垂直滚动条，视觉粗糙且侵占工作台空间。
3. **裁剪输出重名静默覆盖风险（严重缺陷）**：
   - `ConfigService.resolveOutputPath` 写死输出名为 `${baseName}_cut.mp4`，且 FFmpeg 剪辑参数写死 `-y`（强制覆盖）；
   - 当用户对同一视频进行多次调优裁剪时，新产物会**无预警静默覆盖上一次的成果**；
   - 若用户加载的视频本身就位于输出目录且重名，存在覆盖破坏原视频文件的致命安全隐患；
   - 界面底部缺少当前目标产物文件名的实时预览，用户无法在点击前确认输出安全性。
4. **控制台路径打印中文字符乱码**：
   - `KeyframeProber` 与 `FFmpegExecutor` 构造函数中使用 `console.log('... 使用路径:', ...)`，中文字符在部分 Windows GBK 终端中被解码为 `浣跨敤璺缎`。

## 2. 目标与整体架构设计

### 2.1 架构设计：三层极简流式工作台

```
┌──────────────────────────────────────────────────────────┐
│ 1. 顶层：纯净视频画面视窗（Video Viewport）               │
│    - 彻底剥离控制条，100% 呈现视频画面                     │
│    - 由 Flexbox 弹性填充（flex-1 min-h-[260px]），视野最大化 │
├──────────────────────────────────────────────────────────┤
│ 2. 中层：主时间轴控制台（Timeline Console，二合一整合）   │
│    ┌──────────────────────────────────────────────────┐  │
│    │ [时间码/比例]   │ ◀◀ 1s ◀1帧 ▶ 1帧▶ 1s▶▶ │ 🔍1.0x ✂ 插入切点 │  │
│    ├──────────────────────────────────────────────────┤  │
│    │ [关键帧刻度/指针/切点/色块 Canvas 时间轴]         │  │
│    └──────────────────────────────────────────────────┘  │
│    - 播放核心控制与时间线物理贴合，三段式降噪，高降至 85px   │
├──────────────────────────────────────────────────────────┤
│ 3. 下层：精炼双行分段卡片流（抗挤压排版，锁定 72px 黄金高度）│
│    - 行 1（状态与动作）：#1 [✔保留|丢弃] 308.3s  [合并][▶试听]│
│    - 行 2（时间与微调）：00:00 ──▶ 05:08        [-0.1s][+0.1s]│
│    - 左右分工（单行各约 120px，总宽 240px），绝不物理折行    │
├──────────────────────────────────────────────────────────┤
│ 4. 底层：精炼 Dock 栏（含防覆盖实时产物预览）             │
│    - 实时预显：📁 预定产物: xxx_cut_01.mp4                 │
│    - 原片/保留/丢弃时长统计 + 合并/封面偏好 + 执行剪辑      │
└──────────────────────────────────────────────────────────┘
```

### 2.2 防重名与覆盖保护机制（全场景覆盖）
1. **源文件冲突物理阻断**：
   - 严禁 `path.resolve(outputPath) === path.resolve(sourcePath)`，若相同则强行添加 `_cut_01` 前缀；
2. **智能序号自动避让递增（Auto-Increment）**：
   - **单文件合并模式**：若已存在 `video_cut.mp4`，自动顺延递增为 `video_cut_01.mp4`、`video_cut_02.mp4`...；
   - **多分段不合并模式**：自动检测各分段是否存在，顺延递增为 `video_seg01_01.mp4`、`video_seg02_01.mp4`...；
   - **执行前原子物理校验**：在 `FFmpegExecutor.executePlan` 真正执行剪辑前进行二次碰撞探测，杜绝 UI 预显与文件物理状态竞态；
3. **底栏产物可见性**：
   - 在底栏执行按钮左侧动态展示当前即将导出的真实产物文件名，赋予用户 100% 确定性。

### 2.3 终端日志完全英文标准化
- 将启动打印改为国际化标准前缀：
  - `[KeyframeProber] Path: D:/Tools/ffmpeg/ffprobe.exe`
  - `[FFmpegExecutor] Path: D:/Tools/ffmpeg/ffmpeg.exe`
  - 彻底根除任何 Windows 环境下的编码冲突。

## 4. 实施步骤

1. **第 1 步：底层安全与日志加固**：
   - 改造 `ConfigService.ts` 与 `FFmpegExecutor.ts`，落地同名自动递增逻辑；
   - 改造 `KeyframeProber.ts` 与 `FFmpegExecutor.ts` 日志输出，根治终端乱码。
2. **第 2 步：重构分段卡片流 `SegmentCardsGrid.tsx`**：
   - 压缩重塑为精炼双行卡片，彻底消灭右侧垂直滚动条，确保 3~4 段一屏平铺。
3. **第 3 步：重塑主时间轴控制台与纯净视频视窗**：
   - 从 `VideoPlayer.tsx` 剥离控制条，视频区纯净自适应；
   - 在 `Timeline.tsx` 中集成控制栏与画布，形成二合一主时间轴控制台。
4. **第 4 步：工作台 `CutterPage.tsx` 整合与产物名预显**：
   - 整合新架构布局，底栏增加实时输出文件名提示。
5. **第 5 步：构建与真实验证**：
   - 运行编译和单测；
   - 自动化 CDP 验证同名多次裁剪递增（`_cut_01.mp4`, `_cut_02.mp4`）、验证布局无滚动条、控制台无乱码。
6. **第 6 步：验收通过后闭环归档至 `archive/docs/方案/`**。
