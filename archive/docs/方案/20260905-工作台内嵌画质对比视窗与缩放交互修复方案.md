## 问题陈述 (Problem Statement)

1. **全屏黑色遮罩打断剪辑心流（模态阻断感强烈）**：  
   当前画质对比功能被封装为一个全屏覆盖的遮罩弹窗（`CompressionPreviewModal`）。当用户点击预览时，整个屏幕被黑色蒙层遮蔽，下方的主时间轴控制台、分段卡片流与底部导出状态被完全遮盖。用户无法在对比画质的同时对照具体时间码或片段位置，产生严重的“跳出应用”割裂感。
2. **跨页面切换导致抽样页码与对比状态丢失（缺乏状态记忆）**：  
   由于模态框生命周期与弹窗组件开关严格绑定，用户在对比抽样帧（如切换至“场景 2”或“场景 3”）时，若临时点击左侧导航栏切换到“方案管理”或“设置”查看信息，模态框立即被销毁。当切回工作台再次打开预览时，所有抽样数据与选中的场景页码强制重置回初始状态，造成明显的认知负担与重复等待。
3. **画面放大后卷帘对比线丢失与手势事件抢占（功能严重失效）**：  
   当用户在对比视窗中选择放大画面（200% 或 400%）以检视微小边缘画质时，由于内部容器经过了 CSS `transform: scale(...) translate(...)` 变换，而分割线拖拽坐标未做逆矩阵映射，导致拖拽把手直接被推移至可视屏幕外；且容器整体的平移（Pan）鼠标事件全局抢占了拖拽把手的拖动事件，导致用户在放大状态下“左右移动的框彻底丢失”，无法完成细节画质检验。

## 解决方案 (Solution)

1. **工作台主视窗就地双态切换（In-place Dual-view Switcher）**：  
   彻底废弃全屏遮罩弹窗模式，将画质对比重构为内嵌式深模块视窗（`VideoCompareView`），直接呈现在原本播放视频的中央主画布位置；在主视窗右上角或底栏提供轻量双态切换胶囊：
   `[ 🎬 剪辑播放视窗 | 🔍 降码画质 A/B 对比 ]`  
   用户点击后在中央大画布毫秒级平滑切换，下方的主时间轴、快捷键提示条与分段卡片完好保留，随时来回自由切换。
2. **工作台级抽样缓存与状态常驻保活**：  
   将抽样画格数据（`samples`）、当前选中的场景页码（`currentSampleIndex`）、对比模式（`split` / `side-by-side`）提升至工作台内存状态中。跨 Tab 切换或在播放/对比之间切换时，状态保持常驻，绝不重置页码；仅当用户更改降码参数或切换视频源时，才触发局部增量刷新。
3. **视口坐标系隔离与多重手势解耦**：  
   - **视口坐标系隔离**：卷帘分割线锚定在视窗可见视口层，不论图像放大多少倍（100%、200%、400%）或平移到哪个角落，分割线与中央把手永远稳定可见，并通过逆变换精确裁切底层图像；
   - **手势分离**：把手拖拽区域具备专属 `pointer-events` 优先级；画面平移（Pan）支持按住空格/右键/中键拖拽，避免与左键拖动分割线冲突；
   - **快捷复位**：支持双击居中复位、滚轮缩放与快捷键（1~5 键切换抽样场景帧）。

## 用户故事 (User Stories)

1. 作为一名追求工作流连贯性的剪辑者，我希望画质对比直接在播放器区域展开，以便于我不被任何全屏弹窗遮挡，能随时对照下方时间轴。
2. 作为一名需要反复斟酌参数的用户，我希望在“剪辑播放”与“画质对比”之间一键来回切换，以便于我确认画质后能直接在底栏点击导出或微调切点。
3. 作为一名多任务操作的用户，我希望在查看抽样帧场景 2 时切到“方案管理”确认信息后再切回工作台，场景 2 依然保持选中，以便于我不必重新等待抽样或丢失浏览焦点。
4. 作为一名对画面细节敏感的用户，我希望将画质放大到 200% 或 400% 时，左右移动的卷帘分割线依然清晰可见并顺畅拖动，以便于我能极其精准地对比暗部与文字噪点。
5. 作为一名键盘效率用户，我希望在对比模式下直接按数字键 `1`、`2`、`3` 切换抽样帧，按 `Esc` 或点击胶囊直接回到常规播放，以便于全流程无摩擦极速操作。

## 实现决策 (Implementation Decisions)

### 1. 视窗架构重塑与深模块定义
- **废弃**：`CompressionPreviewModal.tsx`（作为全屏弹窗的形态）；
- **重构并沉淀为**：[`src/renderer/components/VideoCompareView.tsx`](file:///d:/Projects/litleTools/videoCutTool/src/renderer/components/VideoCompareView.tsx)
  - 接口契约：
    ```typescript
    export interface VideoCompareViewProps {
      videoPath: string;
      config: CompressConfig;
      sampleTimestampsMs: number[];
      cachedSamples: PreviewSample[];
      currentSampleIndex: number;
      onSampleIndexChange: (index: number) => void;
      onSamplesLoaded: (samples: PreviewSample[]) => void;
      onSwitchToPlayer: () => void;
      aspectRatioMode?: 'auto' | '16:9' | '1:1' | 'contain';
    }
    ```
  - 深模块特性：将抽样获取、加载状态、左右并排与卷帘渲染、视口矩阵变换、平移手势全部封装在内，对外暴露极简的状态与通知接口。

### 2. 工作台主视窗就地双态挂载 (`CutterPage.tsx`)
- 在 `CutterPage` 中新增状态：
  `const [mainViewportMode, setMainViewportMode] = useState<'player' | 'compare'>('player');`
- 中央主画面区域渲染逻辑：
  ```tsx
  {/* 中央主视窗：播放器与画质对比就地无缝切换 */}
  {mainViewportMode === 'player' ? (
    <VideoPlayer ... />
  ) : (
    <VideoCompareView ... />
  )}
  ```
- 在主视窗右上角浮动操作栏与底栏提供高对比度切换入口：
  `[ 🎬 剪辑播放 | 🔍 画质对比 ]`

### 3. 卷帘对比放大手势与视口逆变换数学不变量
- **问题根因**：原先分割线位于放大的图像内部，导致 `left: ${splitPercent}%` 随图像平移产生偏移并漂出屏幕。
- **重构方案（视口锚定与局部逆映射）**：
  1. 视口固定层：分割线把手 `SplitBar` 直接定位在外部视窗容器上，`left: splitPercent%` 恒定在视口可见区域；
  2. 裁切逆映射：放大的降码图像通过相对于视口的 `clip-path: polygon(splitPercent% 0, 100% 0, 100% 100%, splitPercent% 100%)` 进行视口级物理裁剪，绝不因内部平移导致分割线出圈；
  3. 平移隔离：平移手势限定在图像画布拖拽，拖拽分割线时不触发画布平移，彻底根绝手势冲突。

### 4. 交互原型真源同步 (`docs/prototypes/prototype.html`)
- 在原型文件的 Tab 4 中同步更新为“就地视窗切换”演示模式，确保设计资产与实现 100% 同步。
