# 全项目导出同盘处理实施方案

状态：已实施并通过本次定向验证。完成日期：2026-11-17。

实施记录：已接入目标侧任务空间、统一排他硬链接发布和按使用期间持有的导出根锁；删除复制兜底及修复 copying 阶段。类型检查、105 项相关测试和 6 类真实媒体流程通过；另验证处理阶段/发布后强杀恢复。用户明确授权 C 盘独立测试目录后，程序/成品不同卷及原片/成品不同卷两组各六类流程通过，直接跨卷发布实测 EXDEV 且不复制。具体证据、耗时、空间采样与限制见[本次验收报告](../../../../videoCutTool_tmp/20261117-same-volume/verification.md)。目标路径选择在第二组引擎测试构建中注入，不新增 CLI 或产品目录选项。桌面最小回归已补齐：当前源码 Electron 的预览、精确导出按钮、真实异常 TS 修复确认/取消/回载及窄窗口通过，并修正修复弹窗遗留复制文案。未做候选包验收，不承诺网络文件系统。C 盘独立测试目录已由用户手动清理并确认不存在。

## 目标与用户确认的方向

整个项目的导出任务在成品所在文件系统卷内生成中间文件和待发布成品，验证完成后直接同卷发布，不再先写程序所在盘再拷贝成品。取消发布环节的跨盘复制及复制兜底，不保留可切回旧行为的选项。

“同盘”以成品所在文件系统卷为准，不是以原片盘、程序盘或盘符文字为准。原片在 D 盘、成品在 E 盘时，直接读 D 盘原片，在 E 盘处理和生成成品；不会先复制原片到 E 盘。读原片、编码、切片、拼接仍会产生必要的媒体读写，本次不承诺消除所有中间文件或提高机械盘处理速度。

本方案先于 [CLI 方案](../../../docs/方案/20261117-CLI压缩与无损剪切实施方案.md)实施；CLI 后续复用统一规则。2026-11-17 用户已授权直接实施本方案，本次不实现 CLI。

## 覆盖范围与现状

| 流程 | 当前入口与行为 | 本次调整 |
| --- | --- | --- |
| 无损剪切、拼接、智能降码、整片压缩 | [MediaCuttingEngine](../../../src/main/services/MediaCuttingEngine.ts)在构造时固定临时根，发布失败可改用完整复制 | 执行每份方案时按成品目录创建任务空间，移除复制兜底 |
| 精确导出、画面处理 | [PreciseExport](../../../src/main/services/PreciseExport.ts)等使用引擎传入的任务目录 | 随任务目录统一落在成品盘，保留现有编码与校验逻辑 |
| 时间轴修复另存 | 原 TimelineRepairService 接收程序侧 temporaryRoot；原 RepairOutput 跨盘时再复制到目标侧临时空间（现已移除，替代入口为 [OutputPublisher](../../../src/main/services/OutputPublisher.ts)） | 从开始就在目标侧生成 carrier，删除跨盘复制分支 |
| 缓存归属与回收 | [CacheMaintenanceService](../../../src/main/services/CacheMaintenanceService.ts)通过持久登记发现受管目录 | 登记各成品目录下的专用任务根，保留进程所有权和按文件身份清理规则 |

播放兼容副本、缩略图、压缩画质对比预览、持久媒体索引及其暂存不属于导出发布，继续按现有归属存放；不把交互预览改成往用户素材目录写缓存。程序打包和发布包复制也不在本次范围。事实真源仍为 [架构](../../../docs/架构.md)，尤其是[媒体读取成本](../../../docs/架构.md#媒体检查的耗时边界)及[数据归属](../../../docs/架构.md#数据与产物归属)。

## 任务空间与同卷发布

1. 先按现有输出规则解析成品目录；桌面继续使用原片旁的 cut 或压缩目录，修复使用用户选择的目标目录。未来 CLI 使用调用方指定成品的父目录。
2. 在该成品目录内部建立 `videoCutTool_tmp/slices/managed/` 专用根，再通过维护服务分配独立任务目录。所有本次媒体中间文件，包括时间戳整理副本、切片、拼接文件、编码输出、精确导出中间载体和修复 carrier，均置于该任务目录。
3. 路径解析先检查真实位置及目录类型；拒绝通过临时根的符号链接、junction 或挂载重定向把媒体写到其他卷。不能用字符串盘符相等替代检查。沿用现有安全路径限制；不支持的重解析路径明确报错，不静默退回程序盘。
4. 已存在的专用根必须有合法归属标记，未知非空同名目录不能被认领或清理；成品目录本身不得注册为可清理根。新目录建立、归属登记与取消的交接要可恢复。
5. 在启动耗时媒体处理前，在受管任务目录内用微小探针验证创建、同卷硬链接和清理能力。最终发布仍使用排他硬链接，既不重复复制文件内容，也不覆盖已有路径；探针通过不代替最终权限、同卷和冲突检查。
6. 编码、拼接和完整性验证全部成功、文件句柄关闭后，才为完整文件建立成品名称。发布后的文件不再原地修改；随后删除临时名称不会影响成品内容。
7. 遇到 EXDEV、文件系统不支持硬链接、权限不足等错误直接失败，明确提示目标位置不支持本次安全发布。禁止回退到复制，也不能使用可能覆盖目标的普通 rename 代替排他发布。

首版以 Windows NTFS 实测为验收范围。FAT/exFAT 或不支持所需能力的共享存储将明确失败，这是取消复制兜底后的能力取舍，不宣称所有同盘路径均可导出；网络位置必须按实际能力判断，未经验证不承诺支持。

本任务中“导出媒体中间文件”按用户本次同盘要求放到成品目录，是对既有统一临时目录约定的特定调整。开发验证脚本、测试素材、日志、截图和报告继续放仓库同级 `../videoCutTool_tmp/`，不修改 AGENTS.md。文档在实施后将两类归属分别写入架构真源。

## 发布、取消与恢复边界

- 现有自动命名及重名重试继续保留；未来 CLI 的明确目标路径遇到占用则失败。两者共用同卷排他发布，不共用重命名策略。
- 多文件导出不宣称整组原子完成：部分文件已发布后失败时，保留完整成品并准确返回其路径；仅在既有命名冲突重试需要撤销本轮产物时，按记录身份删除本次创建的文件，不能删除其他进程文件。
- 发布前取消或强杀，只留下受管任务文件，不出现以成品名称写了一半的文件。发布后取消不得将已完整发布的成品误当缓存删除；状态保存失败或强杀仍可能留下完整成品及未更新记录，不宣称业务状态与文件系统事务原子一致。
- 缓存登记仍保存在应用现有持久登记位置，指向目标盘受管根；不能把登记仅放进随进程变化的临时目录，导致下次无法发现。登记持续存在不代表持续持有根锁。
- 导出任务根采用按使用期间占用的生命周期，不能沿用“取得后直到应用退出才释放”的方式。任务准备、媒体处理、发布及清理均持有引用；同进程共享根通过引用计数协调。没有活动任务、待启动或存活的媒体进程及进行中的清理/登记写入后，核对所有权 token 再释放根锁，并移除本进程的已持有状态，持久登记保留。任务取消或抛错也进入同一释放流程；尚有子进程存活或归属不明时保守保留占用并报告。
- 再次使用已释放的根必须重新获取锁、核对根标记并加载最新登记，不能因内存里存在旧根而跳过校验。取得引用、检查闲置、释放和再次获取通过同一串行边界协调，避免新任务与释放竞争。其他实例仅在根确实被占用时收到占用错误，不因桌面窗口保持打开而一直失败。此生命周期调整针对导出任务根，预览和索引根不无条件套用。
- 历史发现与新任务创建分开实现。只有新任务创建入口可以 mkdir 和初始化归属标记；历史发现仅检查已存在的路径、标记与登记，禁止递归建目录或补写缺失标记。路径缺失、目标盘离线、权限变化或归属异常时保留登记并报告，待可访问后再检查，不能重新生成用户已删除的成品目录。
- 重启只回收已登记、归属可证明且没有存活媒体进程占用的遗留任务。历史回收按需短暂取得根锁，完成检查或清理后按上述闲置条件释放；锁由其他实例持有时跳过，不在应用启动后持续占用全部历史成品目录，不扫描或删除用户目录。若发现与获取之间路径被删除，同样跳过，不能通过新任务创建入口补建。
- 旧程序侧已登记媒体缓存按原维护机制回收；不迁移旧缓存，不扫描认领未知目录。长期空受管根可以保留，避免为删除几层空目录增加风险。

## 空间与性能

磁盘空间检查改为面向实际任务所在卷，修复不再把程序盘与目标盘分别当成需要容纳完整副本的位置。同一目标卷只计一次可用空间，但应考虑切片、拼接、编码载体可能同时存在的峰值；不能把“一个成品的大小”当成通用峰值上限。

精确导出或压缩输出大小无法预先精确确定，不新增整片扫描来估算容量。已有可靠估算可用于前置提示，运行中 ENOSPC 明确失败并按归属清理中间文件，不转写其他盘、不改用复制。代表性验证记录实际空间峰值及耗时，不设置未经测量的性能承诺。

## 实施顺序与验收

1. 实现并验证目标侧任务空间和排他发布公共函数。
2. 接入普通导出、整片压缩、精确/画面处理路径，再接入时间轴修复，移除复制分支及失效参数和进度枚举。
3. 核对分散根的发现、取消、重启回收，更新架构文档及 CLI 方案。
4. 按 [README 验证与交付](../../../README.md#验证与交付)运行类型检查、相关既有测试及下列定向媒体验证，通过即停止。

必要验收：

- 程序与成品位于不同卷时，分别运行无损剪切、多段拼接、整片压缩、精确导出/画面处理，以及支持素材的时间轴修复。记录 FFmpeg 实际输出路径和受管目录，确认所有导出媒体中间文件在成品卷；程序侧可以有登记和索引，但不能有本次导出媒体副本。
- 成品与原片不同卷时同样成立；没有多卷环境时用依赖注入覆盖 EXDEV 失败，明确实盘验证缺失及对跨卷场景交付结论的限制，不能把模拟测试当实盘通过。
- 发布阶段无需读取并写出完整成品；成功后成品媒体可探测、可播放，必要流及剪切语义与既有行为一致。无损不以精确等于请求时长验收。
- 已有目标、竞争抢占、目标不可写、硬链接不支持、错误卷、磁盘满分别失败且不发生复制兜底；探针和临时文件可清理，原片与已有文件不受损。
- 在处理阶段取消/强杀并重新启动：不出现最终名称的半成品，登记任务可恢复清理；发布后取消/强杀保留完整成品。强杀验证仅结束本次测试进程。
- 多文件发布中途失败准确列出已完成产物；冲突重试不会删除他人文件。目标盘断开时保留登记，恢复后只处理可证明归属的文件。
- 未知同名临时目录、junction/符号链接重定向、其他进程占用根均不能被错误接管；原缓存已登记遗留项仍能安全回收。
- 桌面向某目录导出完成后保持窗口打开，另一实例能够向同目录开始任务；桌面启动仅检查历史登记后也不持续占用该目录。存在活动任务、待启动/存活子进程或清理时，竞争者明确收到占用错误。
- 同进程两个使用者共享根时，前者结束不能提前释放；最后一个使用者结束后可释放。模拟取消、异常和释放/再次获取竞争，验证旧内存记录不能绕过重新获取，也不能删除其他实例的新锁。
- 删除整个成品目录后重启，历史发现不得重新创建任何目录层级或归属标记；模拟路径在检查后消失、目标盘离线再恢复，验证缺失时保留登记且不建目录，恢复后仅回收身份匹配的遗留项。
- 修复进度不再显示复制阶段；交互预览及导出按钮的受影响流程做最小回归，不建立新 UI 测试体系。

一次性素材、测试脚本及报告放 `../videoCutTool_tmp/20261117-same-volume/`。实现与定向验证通过后，在本方案头部记录完成日期、验收结论和限制，再归档至 `archive/docs/方案/` 并修正相对引用。打包仅在需要实际交付候选包时进行；本次实施执行类型、相关测试、媒体验证与文档检查，不提交 Git。
