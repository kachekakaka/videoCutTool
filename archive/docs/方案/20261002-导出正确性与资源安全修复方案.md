## 1. 目标与修复顺序

首先保证用户选定的画面区域、分段处理配置与导出结果一致，防止“成功导出但遮罩丢失”；随后减少拖动、切换素材时的重复工作，并补齐异步竞争和主进程权限边界。

建议按四批实施，每批独立验收，前一批未通过不以后一批的检查结果替代：

1. **A：导出正确性**——分段配置随切点演进、规划合并、裁剪与遮罩滤镜、统一画幅。
2. **B：交互和资源使用**——视频显示区域坐标、拖动事务、遮罩列表刷新、历史容量、路径请求、扫描取消及限流。
3. **C：后台状态一致性**——保存重试去重、媒体工具初始化与切换。
4. **D：安全边界**——IPC 来源和参数、媒体文件访问范围、导航与窗口限制、沙箱和 CSP。

安全边界可提前准备，但必须完成开发态及便携包验收，不能仅修改开关就判定完成。

## 3. 技术路径

### 3.1 分段空间配置生命周期（A2）

采用**保留现有持久化格式、在草稿内部随区间迁移配置**的方案，避免为本次修复引入全库 ID 格式迁移。

- `RetentionDraft` 拆分前，按原区间索引获取独立配置；拆分出的两段各自深拷贝继承，后续分段同步重编号。
- 删除切点合并遵循 ADR-0007：继承左侧的配置。左侧没有独立覆盖时，合并后回到全局继承，不能误继承右侧覆盖。
- 移动切点不改变相邻区间的配置归属。
- 分段尚未独立覆盖时，界面展示的是继承自全局的配置；第一次局部修改、删除遮罩或调整裁剪前，先深拷贝整份生效配置到该分段，再执行修改。删除最后一个局部遮罩后保留显式空覆盖，不能自动回退到全局而使遮罩重新出现。
- 保存、回载、撤销、重做必须同时恢复切点、保留决策和空间配置；独立配置之间不能共享可变数组。
- 读取旧记录继续支持 `seg_N`；非法索引、越界切点和非法空间参数在进入执行前返回明确错误，不静默丢弃遮罩。

主要文件：`src/shared/RetentionDraft.ts`、`src/main/services/PlanRecordStore.ts`；必要的契约调整放在 `src/shared/types.ts`，不另造持久化协议。

### 3.2 规划、合并与执行窗口（A1）

纯时间无损模式保留原有关键帧向左吸附与重叠融合行为。涉及空间处理时，规划必须保留每个逻辑分段与其生效空间配置的对应关系，不能只留下第一个 `segmentId` 后再查配置。

- 在草稿生成计划时解析独立覆盖与全局配置，生成不可变的执行配置快照。
- 相邻、重叠分段只有在生效画面配置相同时才允许直接融合。
- 不同配置对应的执行窗口需要保留边界，并在转码路径落实该边界；音频继续遵守流复制约束。
- 不能仅关闭融合后逐段拼接，因为关键帧向左扩展可能使两段重叠，造成视频和音频重复。
- 对不同配置的重叠安全区间，按源时间覆盖的并集生成不重复的处理窗口：用户保留范围优先保持自己的配置，扩展进入舍弃间隙的部分归属于引入它的后续保留分段；不得削掉用户保留内容。
- 合并导出的推荐执行路径：先按安全覆盖并集生成无重复的流复制中间素材，再在同一转码命令中按配置窗口分离视频、处理画面、拼回视频；音频从未经画面滤镜处理的中间素材直接映射并流复制。避免每个配置窗口再次携带向左扩展的音频片段，也避免重复编码重叠视频。
- 窗口边界映射必须使用中间素材实测的展示时间、时间基与起始偏移；不能直接拿源文件毫秒数当拼接后时间，也不能把非关键帧窗口继续交给现有流复制 `cut()` 就认为边界已经精确。视频分窗需在解码后执行 `trim`/时间戳校准等实际处理。
- 具体解码/滤镜分窗与音轨拼接需在最小媒体实验中同时证明时长、画面配置边界和音画同步。未通过前阻止该组合执行并说明原因，不能回退成忽略配置的“成功导出”。临时阻止不算本项最终完成。

主要文件：`src/shared/RetentionPlanner.ts`、`src/shared/RetentionDraft.ts`、`src/shared/types.ts`、`src/main/services/MediaCuttingEngine.ts`。

### 3.3 裁剪、遮罩和统一画幅（A3—A6）

- 统一“是否发生实际画面处理”的判定：比较原始画面尺寸、裁剪框坐标尺寸及有效遮罩，而非根据比例标签。工作台提示、方案徽章、输出格式推导与执行引擎使用同一规则。
- `free` 表示不约束拖动比例，不表示关闭裁剪；只有无裁剪框或实际为全画幅时才可省略裁剪。
- “原片比例”由显示尺寸计算；界面比例选项、锁定状态随分段切换、方案回载及撤销重做同步。
- 马赛克通过“分离选区→模糊→叠回原图”处理，再裁剪与统一画幅。使用明确命名的滤镜输出，不能继续使用像素坐标 `enable` 表达式。
- 模糊半径按选区及色度平面的实际尺寸限制，不能把固定半径 10 原样用于最小 16×16 区域；亮度和色度半径分别校验。
- 滤镜构建返回明确结构，区分简单视频滤镜、复杂滤镜图及其输出标签；`buildCompressArgs` 统一负责装配并映射处理后视频，保留选中的音轨、封面及附加流。不能把 `['-filter_complex', graph]` 直接塞入现有只识别 `-vf` 的参数槽。
- 去水印选区保留算子所需的周围像素。界面限制与后端校验一致；不支持的贴边选区应说明原因，不静默缩小选区后留下未处理内容。
- 统一画幅处理独立于是否存在空间配置；没有遮罩或裁剪的分段也必须按合并目标画幅处理。
- 统一画幅先确定目标，再使各段等比缩放与居中补边；所有进入编码器的尺寸应满足偶数要求。单独导出时不增加无关补边。
- 有封面、多个音轨或其他保留流时，滤镜输出只替换实际需要处理的视频流，不丢失音轨、不把封面当作主画面编码。
- 压缩 A/B 仍定位为压缩质量比较，不默认扩展为完整空间效果预览；有空间配置时明确提示“比较不含裁剪与遮罩，最终导出会应用”，避免用户把未处理抽样当作最终效果。完整空间效果预览若后续单独授权，必须同时更新 IPC 契约、取样边界和前后端缓存键，不能仅改后端滤镜。

主要文件：`src/shared/spatialFiltergraph.ts`、`src/shared/compressPresets.ts`、`src/main/services/MediaCuttingEngine.ts`、`src/main/services/MediaFormatResolver.ts`、`src/main/services/ConfigService.ts`、`src/renderer/components/CutterPage.tsx`、`PlansPage.tsx`、`SegmentCardsGrid.tsx`、`SpatialOverlay.tsx`。

### 3.4 覆盖层与拖动事务（B1—B3）

- 从视频显示宽高和可用容器尺寸计算实际视频矩形，覆盖层与视频内容使用同一矩形；鼠标坐标先扣除黑边与偏移，再转换成源视频坐标。
- 显示几何与滤镜采样坐标分开处理：除旋转信息外还读取像素宽高比（SAR）和显示比例，不能将编码宽高直接当显示比例。统一计算显示矩形及其反向坐标转换，避免非方形像素素材再次发生选区漂移。
- 窗口缩放、Tab 恢复、横竖屏素材和兼容预览切换后重新计算，观察器及动画帧在卸载时清理。
- 鼠标按下记录一次草稿快照；移动时只更新临时选区；鼠标释放提交一次草稿操作。取消、失焦、切换素材或模式时结束事务；不产生变化时不压入撤销栈。
- 手势进行期间不能把旧素材/旧分段选区写入新草稿；提交校验素材代次及目标分段。
- 历史保留最近 100 次已提交操作，清除分支时释放重做记录。此限制只影响可撤销步数，不丢弃当前草稿。
- 删除遮罩后按最新草稿版本派生列表；不依赖原地修改对象的引用是否变化。
- 路径推导只依赖源文件、输出规则、标题、合并/封面选项及影响输出格式的配置；拖动坐标与播放进度不触发路径 IPC。
- 设置页避免同一次单选操作同时由 label 点击和 input change 重复持久化。

主要文件：`src/renderer/components/VideoPlayer.tsx`、`SpatialOverlay.tsx`、`CutterPage.tsx`、`SettingsPage.tsx`、`VideoCompareView.tsx`，以及 `src/main/services/MediaTools.ts`、`KeyframeProber.ts`、`src/shared/types.ts`；必要时调整 `src/shared/RetentionDraft.ts`。

### 3.5 探测任务取消、共享与限流（B4）

- 关键帧扫描拥有请求 ID、取消信号和并发预算，切换素材取消旧消费者，不能只忽略返回值。
- 同一文件身份的扫描可被多个消费者复用；一个界面取消不得误杀导出仍需使用的扫描。仅最后一个消费者退出时取消底层进程。
- 导出使用独立消费者身份；退出应用取消排队项与运行项，关闭期间禁止派生新扫描进程。
- `KeyframeProber` 显式参与应用关闭流程；服务先进入关闭状态，再取消全部请求并等待其结束。仅对当前子进程集合调用一次终止不足以覆盖正在等待元数据、随后才启动扫描的请求。
- 基础元数据按文件身份和工具身份短期缓存/复用，优先减少导入、输出格式推导与扫描之间的重复 FFprobe；缓存有容量上限，文件或工具变化后失效。
- 全解码回退扫描增量解析输出并只保留关键帧，不把全片帧文本先聚集为一个字符串；保留异常处理和资源上限。
- 避免同一个限流器名额内部再次等待该限流器，防止预算为 1 时死锁。一次请求的生命周期和实际占用进程名额分别管理。

主要文件：`src/main/services/KeyframeProber.ts`、`MediaTools.ts`、`ConfigService.ts`、`electron/main.ts`、`electron/preload.ts`、`src/vite-env.d.ts`、`src/renderer/components/CutterPage.tsx`。

### 3.6 后台恢复和工具一致性（C1—C2）

- 保存重试持有唯一进行中的 Promise；在进入异步保存前捕获待保存记录快照，完成后只清理对应记录。失败保留恢复状态，重复点击返回同一结果。
- 记录持久化成功后才能释放接受状态、广播完成及恢复队列；不能把不同任务的存储错误一起清空。
- 引擎、主探测器、压缩预览和播放预览在启动时使用同一组已解析工具路径。
- 工具切换作为串行状态变更处理：已有导出使用任务启动时的工具快照，新任务使用新配置；旧缓存与旧工具探测结果不得污染新代次。
- 工具配置保存失败不能广播成功；合法自定义工具继续受支持，不能为了安全边界直接移除该能力。

主要文件：`src/main/services/MediaCuttingEngine.ts`、`CompressionPreviewService.ts`、`PlaybackPreviewService.ts`、`KeyframeProber.ts`、`ConfigService.ts`、`electron/main.ts`。

### 3.7 主进程安全边界（D1）

- IPC 仅接受当前主窗口的可信主 frame；开发态验证精确开发服务器来源，打包态验证应用入口，不用宽松字符串前缀匹配。
- 对配置、方案、采样点、请求 ID、路径和压缩/空间参数进行运行时校验，并限制数组数量、字符串长度和并发请求规模。TypeScript 类型不作为运行时保护。
- 媒体协议只允许读取当前授权素材与服务生成的预览文件；请求路径规范化、确认普通文件并验证授权，不能只凭后缀或路径前缀放行。保存方案回载和文件拖入必须有合法的主进程授权来源。
- 不新增允许渲染层任意提交字符串路径的“加入白名单”接口。文件对话框由主进程直接登记；拖入文件由窄化的 preload File 入口解析并完成登记；方案回载由主进程从已验证记录解析素材；服务生成的预览由服务登记。必要时让拖入入口变为异步，等待登记成功后再开始探测。
- 取消接口只能取消同一调用方拥有的请求；共享后台任务按消费者管理。
- 限制页面导航和新窗口；启用沙箱前先验证 preload 仅依赖沙箱允许能力；配置生产 CSP，开发态只增加必要权限。
- 媒体响应保留流式读取和 Range 支持；不为授权检查而读入整个视频。网络盘或大文件检查不得同步阻塞主事件循环。
- 本项目标是限制不可信页面触达系统资源的能力，不宣称能完全防御已经控制可信主 frame 的攻击者。工具可执行路径变更需由主进程控制授权流程，而非仅靠扩展名识别。

主要文件：`electron/main.ts`、`electron/preload.ts`、`index.html`、`src/vite-env.d.ts`、`src/main/services/PlanRecordStore.ts`、`ConfigService.ts`、`PreviewCache.ts`；必要时增加一个职责明确的主进程参数/授权模块。

## 4. 验收矩阵

不新增 UI/E2E/CI 或成套测试体系。仓库内新写/调整的单测遵守 AGENTS.md 的唯一纯函数单测限制；其他验证采用一次性脚本、实际 FFmpeg 输出和人工界面操作，过程资产写到外部临时目录。已有其他测试可运行，但不扩展其体系，也不在本任务擅自删除。

| 场景 | 合格标准 |
| --- | --- |
| 纯时间无损剪辑 | 向左吸附不变量保持；已有音轨保留与输出防覆盖行为不回退 |
| 相邻段不同遮罩/裁剪 | 各自时间范围使用各自配置；输出无重复片段；不能只靠任务成功状态验收 |
