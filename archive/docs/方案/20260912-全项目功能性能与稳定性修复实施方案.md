首先保证导出的内容正确、已有文件不被覆盖、音轨不被静默丢弃；随后消除重复执行、状态失真和跨页面误操作；最后改善格式兼容、预览开销、大量方案读取和长视频时间轴表现。

1. 覆盖检测报告全部 17 项已复现问题，逐项验收，不以编译成功或单测通过代替实际媒体验证。
2. 报告中的 QSV、画质预览准确性、长视频时间轴、打包脚本四项补充问题先完成针对性验证。硬件不可用时如实记录验证范围，不把模拟结果当成实机通过。
3. 保持“先无损裁剪与合并，再按需压缩”的主流程。导出音轨继续使用流复制，不能通过重新编码音频掩盖容器不兼容。
4. 继续使用现有 React / Electron / FFmpeg 技术栈和 JSON 方案存储，不引入数据库、重型任务框架或测试体系。
5. 本方案已按后续指令实施；本轮打包仅构建外部候选包验证脚本，正式替换发布目录、提交与推送仍按后续发布指令执行。
6. 术语以 [CONTEXT.md](../../../CONTEXT.md) 为真源，协作红线与过程文件位置遵守 [AGENTS.md](../../../AGENTS.md)，文档职责按 [README.md](../../../README.md#文档导航) 执行。

## 三、技术路径

### A. 导出正确性

**A1 / F01：修正关键帧提取和缓存。**

- 关键帧索引以原始整数展示时间戳和流的 `time_base` 为寻址真源，优先读取 `best_effort_timestamp`，以有效 `pts` 补充；不再将跳帧解码后的 DTS 当作画面时间。`*_time` 的小数字符串仅用于显示与诊断，避免其中有限的小数位再次截断原始时间。
- 从 KeyframeProber、版本化缓存、MediaMetadata、Retention Planner / PlanSegment 到 MediaCuttingEngine，贯穿传递对应关键帧的整数时间戳、时间基及时间原点；序列化整数采用可无损往返的表示，不能先 `Math.round(... * 1000)` 再作为执行依据。界面和历史草稿可以继续使用毫秒，显示值不能反向替代精确寻址值。
- 过滤无效数据、排序去重和向左吸附比较均基于同一时间原点；源时间戳转换为播放器相对时间时统一处理非零起始时间。确实无法取得可验证精度的索引时明确报错，不伪装成精确切片。
- FFmpeg 参数生成必须一起修正现有 `toFixed(3)`：先按精确时间选定满足 `K <= userStart` 的关键帧，再在统一时间原点下将 K 向上换算为整数微秒，使用微秒精度字符串生成 `-ss`，使量化后的寻址时间不早于 K、且不越过下一帧；不能用扩大到整数毫秒的偏移补丁。换算使用整数/有理数运算，避免浮点误差改变舍入方向。
- `-t` / 结束时间与 `-ss` 使用同一时间基准和精度，不能由显示用整数毫秒重新相减或向下截断时长；实际导出必须同时核对起点与保留终点，避免修好起点后又截短尾部。
- 检查子进程退出码、标准错误和结果有效性。读取失败、无法解析或没有有效结果时返回可见错误，不再缓存伪造的 `[0]` 成功结果。确实只有一个关键帧的短视频仍属于有效结果，不能仅凭数组长度判失败。
- 缓存增加算法版本标识；旧格式或旧版本不直接复用，重新探测当前素材。只淘汰应用自己的关键帧缓存，不影响源文件或用户方案。
- 实测补充：缺失包 PTS 的 AVI 不能依赖跳帧扫描恢复展示顺序，改用完整解码扫描并升级缓存版本。此类素材导出前先在任务专属目录以流复制整理时间戳和索引，再按首个展示帧的精确时间差校准裁剪起止点；兼容播放副本使用相同的时间对应原则。源素材和用户切点不改写，但首次扫描及每次整理需要额外时间与临时磁盘空间。
- 引擎执行前要求取得有效关键帧索引；向左吸附和保留区间不缩短的约束继续由 Retention Planner 保证。修复后用源视频包对应关系核对实际导出起点，不只检查规划出的数字；跨容器导致包封装变化时，按实际展示帧时间和内容核验，不将封装字节变化误判为视频内容改变。

**A2 / F02：整批路径分配与落盘防覆盖。**

- 将时间戳、方案标题、源文件名、分段编号和递增后缀的组合规则收敛到共享的输出路径解析模块，供 ConfigService 和引擎复用，避免界面预定路径与执行路径长期分叉。
- 每次执行固定一个命名时间戳；无论第一段是否存在，都检查整批目标路径，包括与源路径的冲突，再确定统一的批次后缀。
- FFmpeg 在本次专属暂存目录使用拒绝覆盖模式，验证通过后以排他硬链接发布；跨卷则持有排他创建的文件句柄复制和刷盘。实际发布遇到新增同名文件时，撤回可确认属于本次冲突批次的文件并重新分配整批路径，有界重试，不能改回强制覆盖。
- 记录本次执行创建的文件，失败清理只作用于可确认属于本次执行的未完成文件。分段导出部分成功时，错误信息说明已产生的分段，不静默删除已经完成的产物。

**A3 / F03：统一流保留策略。**

- 基于探测结果明确本次需保留的视频和音频流，在单段切片、多段合并、整体压缩三个阶段使用一致的显式映射，不依赖自动选流。
- 全部应保留音轨均使用 `-c:a copy`，同时保留语言标签、默认音轨等必要元数据；封面的去留由现有选项单独决定。
- 导出完成条件包含文件可探测、目标视频流存在、应保留音轨数量一致。发现不一致应报告失败及原因，不能只凭 FFmpeg 返回 0 显示成功。
- 容器无法容纳所选流时进入 D1 的兼容性处理，不通过漏映射或偷偷转码解决。

### B. 方案生命周期

**B1 / F04：增加明确的排队状态与去重。**

- `ExecutionStatus` 增加 `queued`，其含义为已接受、尚未开始执行；`ready` 只表示尚未提交。状态转换为 `ready/failed/completed → queued → processing → completed/failed`。
- 引擎按 Plan Record ID 维护已接受任务集合，覆盖活动任务与等待任务。重复提交相同 ID 返回现有状态，不新增队列项、不覆写处理中记录。
- 入队时固定本次执行的方案快照；运行中的草稿编辑不改变已接受任务。更新原记录时由后端检查是否排队或处理中；这些情况下允许另存新方案，拒绝覆盖活动记录并给出说明。
- 方案中心显示“排队中”，该状态不属于待办批量提交范围；按钮状态与后端约束一致。状态事件同时覆盖入队、开始、结束及移出队列。

**B2 / F05：重启与异常恢复。**

- 先保证记录可恢复，再恢复执行状态。保存内容先在内存完整序列化并校验 ID、切点和必需字段，禁止直接截断唯一一份有效的方案 JSON 后再尝试写入新状态。
- 保留上一份完整记录：在 Data Directory 的独立 `plans_recovery/` 子目录保存带版本、ID、校验信息的恢复快照，属于长期用户恢复数据，不是临时日志或过程资产。旧主文件仍完整有效时，先更新恢复快照，刷盘并回读验证成功后才允许写主文件；快照准备失败时不修改主文件，主文件部分写入失败时保留已验证快照。若当前只能从快照恢复，先恢复并验证主文件，不能在恢复前覆盖这唯一的有效副本。
- 主文件新内容完整写入、刷盘并通过回读校验后，才向调用方确认保存成功、更新内存索引和发送已持久化的状态事件；入队接受与执行开始必须等待各自状态保存成功。失败时保留上一完整内容，明确返回保存错误，不报告假成功；新方案首次保存失败则保留界面草稿，不能作为已接受任务进入队列。
- 应用启动或手动刷新发现主文件损坏时，先校验并读取对应恢复快照，再修复主文件；无法修复时仍展示可读取的恢复记录及恢复失败原因，不能静默把它从列表移除。两份均无有效内容时列出受影响记录 ID 和文件位置，不凭空生成默认切点。恢复文件不能被普通方案扫描当成额外卡片。
- 记录内容恢复后，再检查持久化的 `queued/processing` 状态，将没有本次进程对应任务的记录转为 `failed`，注明“上次执行中断，可重试”；不自动重新导出。重试重新探测素材、重新分配输出路径。
- 删除时先持久化并验证删除标记，再清理主文件和快照；读取与启动恢复尊重删除标记，清理中断也不能将已删除方案恢复出来。已删除 ID 拒绝普通状态回写，重新另存使用新 ID；这部分与 B3 的排队移除统一协调。删除标记属于恢复数据，不能在主文件或快照仍可能被恢复时提前清除。
- 保存和状态转换的异常都必须进入 `finally` 并释放引擎占用。存储仍不可写时拒绝不能可靠保存的新任务；写入能力恢复后能继续处理任务，不能用不断重试错误写入代替状态恢复。
- 关闭应用时依据活动任务显示明确的退出影响；若结束任务，只终止本应用持有的子进程并等待退出，记录中断结果。异常退出仍依靠下次启动恢复。

**B3 / F06：明确删除行为。**

- `ready/completed/failed` 记录按现有确认流程删除。
- `queued` 记录删除时，由引擎先移除等待任务，再删除持久化记录，操作完成后不再执行、不再重建卡片。
- `processing` 记录暂不允许删除，界面说明“处理中，完成后可删除”，后端同步拒绝。避免本次同时引入完整的活动任务取消产品流程。
- 删除、开始执行和保存状态由同一调度入口协调，防止状态检查与实际删除之间再次发生竞争。

### C. 工作台与设置一致性

**C1 / F07：媒体载入以最新请求为准。**

- 统一 App 与 CutterPage 的文件载入入口，顶栏、拖拽、空白页选择和方案回载使用同一组“请求的视频 / 已生效的视频”状态。
- 载入请求递增代次；元数据、关键帧扫描、错误提示、加载完成及草稿重建都校验代次和源路径。较早请求不能改变较新请求的状态。
- 新媒体成功载入后再整体提交元数据、草稿和顶栏展示，防止标题为 B 而播放器为 A。失败时给出明确提示，保留可识别的旧会话，不混用新旧数据。

**C2 / F08、F17：统一快捷键与文件选择结束条件。**

- 工作台快捷键统一检查活动页面、当前弹窗、输入目标和 `defaultPrevented`。播放器、撤销重做、时间轴及画质对比遵守同一开关，补齐 C、空格、方向键、Ctrl+Z/Y。
- 隐藏页面及弹窗内操作不能修改背景草稿。已有 Delete 焦点约束保留并回归验证。
- 原生文件选择正常取消时立即结束；只有通道不可用或接口异常才进入备用选择器。备用入口通过 `getPathForFile` 获取路径，不能将文件名冒充物理路径；需要时重置 file input，使再次选择同一文件有效。

**C3 / F09、F10：播放位置与逐帧行为。**

- 播放位置由工作台持有，操作读取媒体元素当前时间，避免只依赖低频 `timeupdate` 缓存。
- 对比模式保留播放器实例，进入时暂停；返回后保持原位置且默认暂停，避免隐藏播放及无意出声。播放器、对比图和时间轴的可见性与快捷键权限分开管理。
- 对比模式下隐藏或禁用没有实际效果的播放、前后步进及试听控制；仍允许时间轴定位用于添加 Preview Sample Point。
- 保留分数帧率精度。固定帧率素材使用真实帧间隔；可变帧率或不能确定帧间隔的素材，按临近展示帧时间戳导航，缓存局部结果，避免为一次步进扫描全片。异步帧导航同样服从媒体请求代次。

**C4 / F13：配置单一状态与字段更新。**

- ConfigService 保存成功后广播配置变化；App 持有最新 Application Configuration，设置页与工作台订阅同一份已保存状态。
- 界面按实际编辑字段提交补丁，不将过时的完整配置对象写回。设置页尚未提交的文本输入保留编辑值，其他未编辑字段跟随最新配置刷新。
- Output Directory Policy 变化时重新解析工作台预定路径；实际提交和打开输出目录都使用最新配置。路径预显仍需在执行时再次做防覆盖校验。

### D. 格式与压缩能力

**D1 / F11：按输出编码与保留音轨选择容器。**

- 无损导出优先保持源容器；智能压缩不再机械沿用源扩展名。
- 执行前分别解析并固定 `intermediateContainer` 与 `outputContainer`：前者根据原始视频、全部应保留音轨及附加流选择，服务于无损切片和合并；后者根据压缩后的目标视频编码与仍被流复制的音轨/附加流选择。两者不能因扩展名相似或最后要输出 MP4 就被合并成一个选择结果。
- 中间容器优先沿用可容纳原始流的源容器；不适用于切片合并时选取经过验证、能容纳原始流的替代容器。所有待合并分段采用一致的中间容器和流布局，临时路径、扩展名与实际 muxer 匹配。无法无损承载所选原始流时提前报错，不在这里偷偷转码或丢流。
- 最终 H.264/H.265 与全部应保留音轨及附加流明确兼容 MP4 时使用 MP4；不兼容时优先选择可保留这些流的 MKV。没有已验证的最终兼容容器时，在执行前说明具体不兼容流并停止。两个阶段的容器兼容性都需要检查，不能只验证最终编码组合。
- 界面预定路径、Plan Record 的产物路径与正式导出使用 `outputContainer`；无损切片及压缩前合并文件使用 `intermediateContainer`。单段先切后压、多段合并后压、逐段独立压缩都遵循该分离规则；原始流进入中间文件时继续流复制，只有正式压缩阶段切换视频编码及最终容器。
- 补入 FLV1＋AAC 的验收组合：原始 FLV 流不能直接写入 MP4 中间文件，但编码为 H.264＋AAC 后可以输出 MP4。必须通过该路径证明容器选择依据的是各阶段实际流，而不是最终扩展名。
- WebM 输入的典型处理为压缩视频后选择兼容音轨的输出容器，不将 H.264/H.265 塞回 WebM。导出音频仍禁止重编码。

**D2 / F12：播放器失败可见及兼容预览。**

- 将 HTMLVideoElement 错误转成界面状态，显示原因、重试及适用的处理入口；黑屏时不继续呈现“可正常播放”的状态。
- 对编码可播放、仅容器不兼容的素材，先尝试生成无损改封装预览；仍不能播放时提供“生成兼容预览”，说明需要处理时间，并提供进度和取消。
- 兼容预览必要时可转成浏览器可播放的视频和音频，但必须位于外部临时目录；MediaMetadata 保持原始源文件信息，独立记录播放用路径，Retention Draft 和正式导出始终使用原始源文件。
- 验证预览与源文件的时间对应关系，不因改封装或转码后的起始时间偏移导致切点错位。缓存按源文件身份失效并限制占用。

**D3 / F14：统一限高语义。**

- `maxHeight` 按画面实际高度限制，保持比例、不放大较小素材，满足编码器对偶数尺寸的要求；考虑旋转元数据后的显示方向。
- `scale_1080p` 与高级“限高 1080p/720p”采用一致的高度语义。旧方案中的 `maxHeight` 字段继续读取，但执行行为修正为它所声明的含义。
- 现有 ADR-0006 中预设的“限宽 1920”与界面限高存在历史差异。实施时在该 ADR 的后续修订中说明这一行为调整，并同步预设说明；不将互相矛盾的两套语义继续保留。

**D4 / QSV 补充项：编码器选择按实际能力生效。**

- 针对目标 H.264/HEVC 分别做短编码能力验证。自动模式按 NVENC、QSV、CPU 顺序选择可用实现，不能仅看到编码器名称就认为显卡支持。
- 显式 CPU 及关闭硬件加速直接使用 CPU；显式指定 NVENC/QSV 不可用时明确报错。自动回退时显示本次实际使用的编码器。
- 能力缓存至少区分工具路径与目标编码格式，配置变化后失效；超时与失败必须释放子进程。
- 正式导出与画质预览共用解析结果。缺少对应显卡时先完成分支与回退验证，在验收记录中保留实机验证限制，不宣传未验证的加速收益。

### E. 性能与预览可信度

**E1 / F15：限制预览任务与资源开销。**

- 连续参数调整使用约 300 ms 防抖；手动首次打开预览与重试可直接执行。只在工作台可见且处于对比模式时启动抽样。
- 前后端共享请求 ID。参数变化、源视频变化、退出对比、隐藏页面或关闭窗口时取消旧请求；后端终止所持有子进程并等待退出，不能只丢弃返回结果。
- 预览服务设置全局并发上限，初始最多同时运行 2 个 FFmpeg 子进程；正式导出在运行时将预览预算降为 1，避免预览与导出争抢全部资源。
- 原帧缓存与压缩结果缓存分开：原帧按源文件身份和时间戳复用，结果再加编码器、参数及缩放条件；对条目数、总字节和过期文件设限。不同请求使用独立临时路径，取消不得删除其他请求文件。
- 先启动任务取消与并发控制，再复用已有帧，最后优化编码调用次数；每一步用相同请求序列复测，记录进程数量、峰值并发和响应时间。

**E2 / 预览准确性补充项：让对比结果能解释。**

- 与正式导出复用编码器、质量参数和缩放参数；代表性画格通过短视频窗口编码后按时间戳提取，避免只编码一张 JPEG 却当作帧间压缩结果。
- 原画与压缩画格采用一致、可控的图像输出策略，优先缓存无损画格，避免把 JPEG 二次损失误当成视频压缩差异。大画格传输优先使用应用管理的本地资源引用，避免一次 IPC 搬运全部 Base64；兼容已有 PreviewSample 消费入口。
- 界面明确这是局部抽样对比，无法保证与整片每一帧完全相同；截图字节数标为画格大小，不作为成片体积估算。
- 移除没有测量依据的固定“保真百分比”和承诺式体积缩减范围，改为用途、压缩倾向和实际采用的设置。更新 ADR-0006 中对应的历史预览描述，避免文档继续承诺固定延迟或绝对画质一致。

**E3 / F16：方案列表避免同步全量扫描。**

- PlanManager 建立轻量内存索引，启动及手动刷新使用受限并发的异步文件读取；保存、删除和状态更新直接更新相应索引项。
- 手动刷新重新检查外部新增、删除、修改或损坏的 JSON 文件，不能因引入缓存而失去已有读取能力。
- 状态广播用于更新单条记录和统计数量；合并完成事件的重复刷新。隐藏的方案页不为每条完成事件再次读整目录。
- 方案页采用分页呈现，避免一次创建数千张卡片；数量统计基于索引，保持筛选和最近更新时间排序正确。不引入数据库或第三方列表框架。

**E4 / 时间轴补充项：按可见范围与像素密度绘制。**

- 刻度间隔根据当前视窗时长与实际宽度选择，限制文字刻度密度；缩放后仍保持时间标签可读。
- ResizeObserver 只响应容器尺寸，不随播放时间重建；画布尺寸仅在尺寸真正变化时设置。
- 静态刻度、分段与关键帧背景和动态播放游标分离更新；同一帧内的多次更新合并处理。关键帧按可视区间定位，避免无谓绘制全片数据。
- 隐藏页面停止绘制，重新进入时重新量测。局部帧预览与拖拽仍需检查边界和取消逻辑，不能用性能优化牺牲交互正确性。

### F. 发布可靠性与闭环

- 打包脚本先在 `../videoCutTool_tmp/` 下生成候选包，检查编译、主程序、preload、资源和启动器均成功后，再切换到便携发布目录。构建失败保留上一版可用产物。
- 不再按进程名强制结束所有 VideoCutTool 实例。遇到目标目录被占用时保留候选包，清楚报告占用，待关闭相关实例后完成切换；只清理可确认属于本次打包的临时内容。
- FFmpeg/ffprobe 资源路径改为可配置并在构建前验证；不能在缺少工具时生成看似成功但无法处理视频的包。
- 保持根启动器加 `app/` 的便携结构，保护已有 `workspace.json` 与 Data Directory 指向。对候选目录和替换目标先校验绝对路径范围，替换失败时恢复上一版，不清理用户数据。
- 经用户要求发布时，执行真实便携启动和一次媒体导出冒烟验证，核对包内源码产物与本次构建一致；再按授权提交、推送。

## 五、兼容性与回退

1. 历史 Plan Record 无需批量重写；读取缺失可选字段时使用默认值。新增 `queued` 只在新版本提交后产生，旧 `processing` 通过启动恢复转为可重试状态。
2. 关键帧缓存可以按版本失效重算，不能将错误旧缓存继续当成兼容要求；源素材与用户切点保持原样。
   精确时间戳需要在缓存和执行契约中无损往返；旧缓存只有整数毫秒时重新探测，不能将其补零后当成具备微秒精度的数据。
3. `maxHeight` 修正及压缩输出容器变化应在界面预定路径和本次执行详情体现，用户保存的源路径和草稿不被迁移成预览路径。
4. 配置保存、启动恢复和队列变化可能同时影响界面与主进程，契约改动必须在同一阶段更新全部生产端、消费端和类型声明，避免半套协议运行。
5. 编码参数和资源限制先设保守默认值，依据同条件测量调整；没有完成正确性验收的路径不启用性能替换。
6. 每阶段保留可定位的改动边界，失败时回退该阶段代码及候选构建。历史配置和方案只在隔离副本上演练，禁止靠删除用户数据解决兼容问题。
7. 恢复快照和删除标记随 Data Directory 保留，不进入便携包或 Git。回退旧代码前先用新版本恢复出完整主记录并完成已标记删除的清理；旧版本不理解恢复协议时不能直接替换运行后再声称数据兼容。
