# 方案：工作台布局重塑与操作体验升级

- **方案编号**：`20260904-工作台布局重塑与操作体验升级`
- **创建日期**：2026-09-04
- **完成日期**：2026-09-04
- **当前状态**：已实施并验收通过 (Archived)
- **验收结论**：
  1. 工作台彻底摆脱固定高度与纵向滚动条束缚，实现随窗口高度弹性自适应（865px 默认窗口下高度为 374px，一屏完整展现时间轴、分段列表与 Dock 栏；1200px 窗口下拉伸至 709px，画面大幅放大清晰锐利）；
  2. 顶部 Header 与底部 Dock 栏均已常驻 `📁 打开输出目录` 快捷入口；
  3. 剪辑执行通知重构为底部 Dock 上方就近浮动的 Toast 气泡，支持一键定位产物；
  4. 启动脚本 UTF-8 声明与 Chromium GPU/HTTP 缓存锁死警告已彻底根治。

## 1. 背景与现状诊断

### 1.1 现状核心问题
1. **播放器占满屏幕，操作区全部被挤出视窗**：
   - 当前 [`VideoPlayer.tsx`](../../src/renderer/components/VideoPlayer.tsx) 中视频容器设置了 `w-full aspect-video`。在标准窗口宽度（1360px）下，视频播放器高度膨胀至约 `730px`，加上控制栏达到近 `800px`；
   - 导致时间轴、分段列表、底部的【存为方案】和【立即执行剪辑】等全部被挤到下方不可见区域，用户必须大幅度滚屏才能操作。
2. **剪辑执行反馈被割裂，用户误以为“没反应/失败”**：
   - 操作按钮在最底部，而成功/失败的提示条横幅却固化在页面最顶端（[`CutterPage.tsx:535`](../../src/renderer/components/CutterPage.tsx)）；
   - 用户在页面底部点击“立即执行剪辑”后，由于视窗停留在下方，无法察觉顶部的提示变化，产生“剪辑没成功”的误判。
3. **缺少常驻的输出目录打开入口**：
   - 目前只有在剪辑成功后的绿色浮动条上有一个小按钮，平时用户无法随时在工作台直接一键唤起 Windows 资源管理器查看目标 `_cut` 目录中的文件。
4. **控制台日志中文乱码与 Chromium 缓存锁死警告**：
   - 批处理脚本未显式声明控制台代码页，Node/Electron 控制台 UTF-8 中文字符在 Windows GBK 环境下乱码；
   - Chromium GPU 缓存因 Windows 临时目录偶发锁死产生红字警告。

## 2. 目标与非目标

### 2.1 目标 (In-Scope)
1. **工作台基于窗口尺寸动态自适应（拒绝写死固定高度）**：
   - 采用专业桌面剪辑软件（如 Premiere/剪映）的弹性填充（Flexbox Dynamic Stretch）模式：
     - 底部的**时间轴（约 56px）**、**分段列表（约 110px）**和**底部操作栏（约 56px）**固定高度锚定；
     - **视频播放器（flex-1 min-h-[280px]）动态吃满窗口全部剩余垂直空间**；
     - 视频画面配合 `object-contain` 保持原片纵横比等比缩放、居中呈现，既不拉伸也不变形；
   - **实际效果**：
     - 用户在大屏幕或全屏窗口下拉大软件时，视频播放区自动拉满变大，清晰锐利；
     - 软件处于默认 900px 窗口高度时，视频播放区自动适度收缩，但下方的时间轴、分段列表和执行按钮**100% 完整可见，实现 0 滚动条的一屏全景工作台**；
   - 播放栏提供辅助的画面比例快速切换（`自适应` / `16:9` / `1:1`），方便特定视频比例检查。
2. **增加常驻【打开输出目录】按钮**：
   - 在工作台顶部标题栏（【打开视频文件】旁）以及底部 Dock 操作区，常驻增加 `📁 打开输出目录` 按钮，调用 `window.electronAPI.showItemInFolder(outDir)` 随时直达 `_cut` 目录。
3. **通知反馈就近可见**：
   - 将剪辑成功/失败提示重构为底部 Dock 上方就近弹出的浮动 Toast 气泡，不再占位挤压高度，并带有一键在资源管理器中定位产物按钮。
4. **启动脚本与主进程缓存加固**：
   - `启动桌面端.bat` 显式声明 `chcp 65001`，彻底根除 Node/Electron 控制台中文乱码；
   - 主进程增加 Chromium 缓存锁死免疫开关，防御 Windows 临时目录偶发权限报错。

### 2.2 非目标 (Out-of-Scope)
- 不破坏现有的底层向左吸附关键帧无损剪辑算法与 HTTP 206 媒体流传输协议；
- 不引入任何外部重型 UI 库或弹窗依赖，纯原生 TailwindCSS 实现。
