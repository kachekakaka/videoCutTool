## 1. 业务痛点与用户诉求

1. **痛点 1（冷启动过慢）**：
   原单文件绿色版（`target: portable`）本质上是一个 7-Zip 自解压包，每次运行必须在后台将 450MB+ 未压缩文件（Electron 核心 + 静态 FFmpeg/FFprobe 二进制）解压至系统临时目录 `%TEMP%`，造成 5~15 秒的黑洞等待期，且极易触发 Windows Defender 实时拦截。
2. **痛点 2（目录整洁度与极简分发）**：
   用户要求最终交付形态极简：`release/` 根目录下只看到一个 `VideoCutTool.exe` 和一个 `workspace.json`，其余所有几十个底层 DLL、资源包和二进制全部整齐归拢在唯一的子文件夹 `app/` 中。
3. **痛点 3（概念清晰与命名统一）**：
   启动程序时用户指定的目录为工作数据目录（存放配置与方案 `plans/`）；而在 exe 同级目录记录这一指向关系的路标文件原先被命名为 `config.json`，极易与实际配置混淆，需规范统一正名为 **`workspace.json`**。

## 2. 总体架构设计（Clean Root Architecture）

### 2.1 最终发布目录结构 (`release/`)
```
release/
├── VideoCutTool.exe          # 🚀 外层原生跳板启动器（4.6KB，无黑框，瞬间拉起）
├── workspace.json            # 📄 工作区指针文件（记录用户选定的数据存储目录）
└── app/                      # 📁 完整的核心运行时目录（全部杂项收拢于此）
    ├── VideoCutTool.exe      # 内部真实 Electron 核心程序
    ├── resources/bin/        # 内嵌的静态 ffmpeg.exe 与 ffprobe.exe
    ├── *.dll & 资源包        # Chromium / Node 底层动态链接库
    └── ...
```

### 2.2 核心技术实现路径

#### 1. 原生无黑框跳板启动器 (Launcher Trampoline)
- **零额外编译器依赖**：直接调用 Windows 10/11 系统自带的 `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`；
- **纯原生 GUI 子系统**：指定 `/target:winexe` 编译，**绝无黑色 CMD 命令行控制台弹窗**；
- **瞬时拉起与环境变量注入**：
  - 运行时读取同级 `app\VideoCutTool.exe`；
  - 注入环境变量 `VCT_WORKSPACE_DIR` 为启动器当前所在目录；
  - 调用后启动器进程立即静默退出，内存常驻为 0，拉起延迟 < 5 毫秒。

#### 2. 主进程工作区优先探测 `workspace.json`
- `electron/main.ts` 读取工作区基准目录时，优先提取 `process.env.VCT_WORKSPACE_DIR`；
- `ConfigService.resolveDataDirectory` 优先检测并读取基准目录下的 `workspace.json`，保留对历史 `config.json` 的向下兼容；
- 当首启或重新指定数据目录时，指针文件统一规范化写入同级的 `workspace.json`。

#### 3. 主进程秒开时序加固
- **单实例互斥锁**：在主进程入口首行执行 `app.requestSingleInstanceLock()`，拦截重复双击导致的并发多开冲突；
- **消灭闪烁（Smooth Launch）**：`createWindow()` 初始配置 `show: false`，监听 `mainWindow.once('ready-to-show')` 后平滑展现窗口，彻底消除黑白框视觉闪烁。
