# 方案索引关联简化方案

> 完成日期：2026-10-29。状态：已实施并归档。
> 验证结论：类型检查、17 项模块定向测试及 4 组 Electron／StrictMode 诊断时序通过；无新增扫描或等待，短样本性能对比未见稳定退化。详见[验收报告](../../../../videoCutTool_tmp/20261029-方案索引关联简化/验收报告.md)。
> 源码基准：`11933e7`。

## 1. 目标与范围

采用**以源版本表达索引关系，取消索引发布后的方案补写**。方案保留已确认的 `sourceIdentity` 和 `contentRevision`；媒体使用者沿用现有 `find(file)`，按当前文件身份查找共享索引。

当前 `mediaIndexId` 没有播放、定位或导出读取者，取消它及其维护流程，消除索引发布后的方案遍历、逐原片属性检查和方案落盘。保留来源校验、索引诊断、现有方案串行队列及媒体读取算法；不新增反向表、解析服务、扫描、探测或正常等待。

成本边界遵循[架构](../../../docs/架构.md#媒体检查的耗时边界)，验证范围遵循 [README](../../../README.md#验证与交付)。

## 2. 技术路径

1. **方案只维护自身内容和状态。** 删除 `mediaIndexId`、`reconcileIndexes`、`indexForSave`、索引发布订阅及启动／刷新补关联；删除 `persist` 中专门保全索引 ID 的合并规则。保存和确认来源不再查询索引。保留来源确认令牌、源身份校验、内容修订冲突检查，以及提交和排队执行时的原有校验。
2. **索引发布只完成索引自身落盘。** 删除 `MediaIndexStore.onPublished`；发布仍按原顺序完成数据写入、源身份复核、目录发布和内存表更新。删除已无调用者的 `waitForPublication` 选项，`find(file)` 保持媒体读者原有的等待在途发布行为。重复、损坏、缺失及归属不明的索引继续明确报错，不把错误当成未命中后重新扫描。
3. **异步补送初始化诊断。** `PlanChange` 增加可选 `issuesToAdd`，只表示索引诊断追加项。索引初始化完成且有问题时，由 `PlanManager` 通过现有通知发送一次数组副本；不等待方案初始化、不进入方案串行队列、不调用 `find`。初始化失败由索引存储登记诊断，并保留 `ready` 的拒绝语义；通知观察成功和失败两条路径，避免未处理的 Promise 拒绝或吞掉媒体读取错误。
4. **复用前端现有事件缓存。** 实时追加诊断时去重；详情／刷新响应以返回的诊断为准，再合并读取期间 `journal` 中的追加项。事件不携带聚合诊断快照，避免旧方案诊断覆盖刷新结果。纯诊断事件直接保留方案数组，不执行筛选或排序。复用现有 IPC 和状态，不新增接口、轮询、再次请求详情或启动屏障。

不增加旧字段迁移、批量清理或兼容分支；旧文件中的多余字段不参与业务判断。方案恢复与删除继续由 `PlanRecordStore` 负责。

## 4. 行为变化

- 索引发布不再修改方案及其恢复文件，不改变方案修订、更新时间或执行状态，也不产生方案记录变更通知；保存切点和确认来源不依赖索引查询成功。
- 启动／刷新不再为关联索引逐个检查原片是否存在。原片缺失或变化仍在回载、保存和执行的原有校验入口报错；索引初始化诊断可能晚于首屏到达，由一次通知补齐。
- 恢复快照只随实际内容／状态保存推进，不再由索引补写顺带滚动。整份记录恢复规则不变，但首次保存后不再因索引发布附带生成首份恢复快照；不能承诺所有损坏时刻恢复出的版本与改动前完全相同。

## 5. 验收点

| 场景 | 通过标准 |
| --- | --- |
| 同源多个方案及无关方案 | 索引发布后，方案文件、恢复文件、内容修订、更新时间、执行状态和方案记录通知次数均不变；发布引起的方案遍历、原片属性检查及方案写入为零。 |
| 来源与修订保护 | 缺失／变化的原片、未确认来源及过期修订仍被原有入口拒绝；确认取消不改方案，正常保存及提交有效。 |
| 索引与方案独立 | 启动、刷新、保存和确认来源不调用索引 `find`；索引损坏不阻止保存合法方案或确认来源，但媒体读取仍明确失败，不自动重扫。 |
| 初始化诊断 | 覆盖订阅前、详情请求中、响应后完成，以及初始化失败；提示不丢失、不重复、无未处理拒绝。刷新期间的追加事件不恢复已清除的旧方案诊断，纯诊断事件不重建方案列表。 |
| 既有索引与恢复 | 实际媒体读取仍复用已有索引、等待同一在途发布；方案损坏恢复后，切点、内容修订和已确认来源来自同一份记录，恢复到未确认版本时仍需确认。 |
| 成本与性能 | 对比实施前后的受影响入口调用计数及短代表性样本耗时；不新增目录遍历、原片属性检查、媒体扫描／探测或启动等待，缓存复用保持，耗时无稳定退化。保存减少索引查询成本，不因诊断通知再次读取方案。 |

实施后仅做类型检查、上述两份既有测试、诊断时序与受影响路径的定向验证，以及文档链接检查；通过即停止。诊断时序使用一次性脚本或现有页面核对，不引入组件测试框架、全量回归、正式打包或额外长片扫描。验证脚本、调用计数和耗时证据放入仓库同级 `../videoCutTool_tmp/20261029-方案索引关联简化/`。
