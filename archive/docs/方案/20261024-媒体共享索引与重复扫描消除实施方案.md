## 1. 已确认的目标与边界

- 正常视频继续直接编辑；正常 FLV／TS 不新增整片 MP4 播放缓存。
- 异常素材由用户确认后修复时间轴并无损另存新 MP4，保留原片、已保存方案及全部验收资料，不自动迁移切点。
- 同一视频版本只维护一份可共享的已验证索引，编辑、播放、方案回载和导出复用。重启后仍能使用，不依赖短期内存缓存存活。
- 索引放在用户数据目录，方案引用索引；不向每份方案复制一整份数组。完整索引不按容量、份数、闲置时间或引用数量删除；本次只设计方案引用与复用，不设计索引删除功能。
- 发现时间轴异常后立即提示，继续完成正在进行的只读分析并提供停止操作；用户确认修复后接上同一次分析，确认前不生成 MP4、不改原片。
- 保存方案不得触发媒体扫描；未完成的扫描不能冒充完整索引。完整结果可供后续消费者继续使用，失败、取消和未完成状态必须可区分。
- 优化以减少实际整片读取、解码与重复等待为目标，不以隐藏提示、把工作挪到后台或删除必要校验代替。

## 3. 已确认的技术路径

### 3.1 一个共享入口，明确结果能用于什么

新增媒体索引服务与持久化存储，集中负责源文件身份核对、完成状态、并发任务合并和结果发布；现有播放与导出模块通过它取得结果，不继续各自建立同类全片索引。

索引至少描述：源文件版本、轨道和整数时基、公共时间起点、精确时长、关键帧展示时刻；流式素材另带原文件字节位置，逐帧需要的展示顺序按已验证支持范围提供。明确是否可用于播放定位、逐帧、无损边界和修复，不能把“包含时间数组”当作全部能力都已验证。

已有包级索引与解码关键帧信息不能未经验证就视为等价。对 B 帧、非零起点、可变帧率、重复时间戳、关键帧标记异常及多画面包做针对性验证，使用原始整数时间戳和时基，避免微秒取整后再反推原始精度。已有不支持的素材边界不因复用而默默放宽。

对受支持素材，共享结果足够时不启动第二次全片扫描；需要核验切点时仅读取有限范围。证据不足则明确返回缺少的能力及原因，暂停依赖该能力的操作，不隐式退回第二轮完整解码。本次不新增补充全片分析回退入口，不以此掩盖正常路径性能退化。

### 3.2 持久化和方案引用

建议数据目录布局为 `media-index/`，完整索引使用随机 ID 命名，另维护文件身份到索引及方案到索引的关联。完整索引自身保存源版本、格式版本、能力和完成状态，作为分析结果的权威记录；查找目录和方案关联只作为可重新构建的引用，不保存第二套分析结论。索引采用一种权威格式；各功能只转换视图，不再存各自内容相同的副本。

文件身份采用规范路径及文件系统可获得的文件标识、大小、修改时间；不得为确认缓存有效而读取全片计算内容摘要。该检查不能承诺发现保留全部属性的外部篡改，应明确这一边界。不同路径的拷贝不自动当作同一文件合并；本轮不做跨路径内容去重、自动重定位或切点迁移。

引用绑定具体源版本及索引格式版本，不能只凭文件名复用。方案记录负责保存已确认的源版本及方案内容修订标识，并让它们随现有方案恢复快照一起保存／恢复；索引关联不能代替这份绑定依据。内容修订标识采用随机 ID，在源绑定或编辑内容成功保存时更新，纯执行状态更新不制造新的内容修订。生成前后核对身份，执行时重新做轻量核对，并将已确认结果贯穿本次执行，避免中途因 30 秒缓存过期重新探测。文件发生变化时暂停使用旧索引，保留原方案，不把旧切点静默套到新时间轴。

方案保存／另存时关联已完成结果；索引尚在生成时，保存不等待扫描、不触发扫描，后续完成后由后台关联。后台任务记录请求时的方案 ID、内容修订标识、已确认源版本和索引能力要求；关联提交与方案修改／删除放在同一串行操作边界内，重新核对当前方案、删除标记、源版本及索引完成状态。条件不符就不写入旧关联，完整索引仍保留；只有当前方案的最新请求可重新关联，迟到结果不得覆盖新方案或使已删除方案重新出现。关联失败应明确显示待关联或索引不可用，不能把方案保存失败与媒体分析失败混为一谈。

完整索引先持久化，再发布可用状态或关联方案；使用临时文件、刷盘和原子发布，消费者只读完整版本。方案保存失败时保留已经完成的索引。删除方案成功后仅解除该方案的关联，不删除索引、不影响其他方案及活动任务；不添加引用归零后的回收逻辑。

重启先按现有恢复规则确定有效方案及删除标记，再以恢复后的源绑定和内容修订验证关联；较新方案的关联不能套到较旧恢复快照上。关联缺失、损坏或目录写入中断时，先查找已完整发布的索引记录，通过有界并发枚举和按需读取索引元数据重建查找目录，再按有效方案绑定重新关联；只读取索引及方案文件和必要的源文件属性，不启动 FFprobe／FFmpeg，不因丢失查找目录就重扫媒体。无法确认唯一有效结果时保留文件并报告待处理，不按“最新文件名”猜测。旧快照没有可信源绑定时回到下述首次确认状态。

明确覆盖三个中断窗口：索引完整发布但查找目录未更新、目录更新但方案关联未完成、方案回退恢复但旧关联仍在。前两种通过已完整发布的索引恢复引用，第三种按恢复后的方案重新核对；未完成索引不能参与恢复。方案或索引记录本身不可读时说明受影响范围，完整文件仍保留。完整索引存储不接入媒体缓存的自动淘汰；不存在未引用索引的过期、容量或数量清理任务。

现有方案、恢复记录与删除标记都保留，不批量重写或迁移历史文件。没有索引关联需区分以下状态，不能统一按路径自动绑定：

| 方案状态 | 处理规则 |
| --- | --- |
| 已记录可信源版本，索引关联缺失 | 先核对当前文件身份，再查找和恢复已有完整索引；确实没有可用结果时才按需建立一次，不为关联缺失直接重扫 |
| 从未记录源版本（包括现有旧方案） | 显示“素材对应关系待确认”；路径、时长甚至文件大小相同也不能证明是原素材。在用户通过应用内提示确认当前素材与方案对应前，不自动绑定、不执行旧切点导出；可以查看方案或单独预览素材 |
| 已记录源版本，但当前文件不匹配 | 停止依赖旧时间轴的执行，保留方案和索引；不能套用首次确认流程静默覆盖已有绑定 |

首次确认展示方案名、源路径、原记录时长和当前可取得的文件信息，说明软件没有该方案创建时的文件身份，不能自动证明素材未被替换；用户确认只表示认可当前对应关系，不代表软件验证了历史同一性。确认前后轻量核对文件身份，条件一致才将当前源版本与新内容修订一起保存到该方案，再关联共享索引。取消确认不改方案或切点。批量执行时此类方案保持待确认，不自动接受；不新增系统弹窗，不启动整片扫描来尝试证明历史身份。

不得启动后台全库媒体扫描。索引格式变更只使不能解释的索引失效，不令原方案丢失；不增加旧格式转换层。失效索引保留原文件，按需生成的新结果使用新的版本记录，不以重建为由删除原索引。

### 3.3 正常 FLV／TS

首次仍先有限探测并允许已有支持范围内的流式播放。随后一次顺序分析同时取得播放、逐帧和导出所需信息。文件未变化时，打开、编辑、回载和导出不再分别扫描；原非零起点 FLV 精确时长计算也消费这一结果。

同一源版本同时被工作台和导出请求时共享正在进行的任务；一个消费者退出只释放自身引用，仍有导出消费者时不得取消。全部消费者离开时允许取消尚未完成的任务；重试时不得误读为完整结果，亦不承诺跨进程恢复半次 FFprobe 扫描。

#### 导出工具必须实际消费位置索引

应用中的索引不会自动进入新启动的 FFprobe／FFmpeg。当前 `MediaCuttingEngine.cut` 仍用 `-read_intervals` 查询切点和 `-ss` 定位输入；缺少内置索引的 FLV 可在工具内部从较早位置顺序读取到目标时间，命令指定两秒时间范围也不代表只读取两秒内容。[FFmpeg 6.0 通用寻址实现](https://github.com/FFmpeg/FFmpeg/blob/n6.0/libavformat/seek.c#L480-L545)明确包含索引不足时继续读包寻找目标的路径。

实施前段须验证可行的输入适配，使边界核验和实际导出都消费已知关键帧位置、PTS／DTS、所需初始化数据及音视频读取范围。优先评估按共享索引提供可寻址的局部输入；在复用现有流式读取能力时核对 FFmpeg 可访问的入口，不能假定 Electron 播放器的协议可直接用于子进程。FLV 需补齐文件头、轨道初始化信息及有效 Tag 边界；TS 需保证必要的节目／轨道信息、包边界和音视频预留范围。不得把任意字节偏移直接作为可解码片头，也不得破坏原时间起点或丢失参考帧。

该适配的具体实现须由小范围可行性验证选定，不能只把关键帧时间传给原有 `-ss` 就视为完成。本轮不预设新增原生依赖或改写原片，也不通过生成整片 MP4 缓存绕过问题；若候选适配不能同时通过位置、音画同步与读取量验证，则该性能目标仍未完成，需说明技术限制后修订路径。

先验证无内置索引的正常长 FLV：在前段和后段分别导出相同时长短片，并在后段连续导出多个短片。边界核验、输入寻址、实际保留内容复制分别记录逻辑读取范围、读取字节数和耗时；验收要求前两者不随切点离片头的距离线性增加，多次导出不重复读取片头到切点的大段数据。覆盖原 FFprobe 局部检查及 FFmpeg 实际导出两个入口，不能仅统计是否出现 `-show_packets`／`-show_frames` 全片命令。正常 TS 同样验证工具自身寻址成本；输出包含整片内容时，其必要读写量另行计算。

### 3.4 异常原片与新 MP4 的交接

原片分析应同时收集修复所需的音视频整数时间戳、包时长、断点和关键帧信息；仅缓存播放所需字段不足以可靠修复。发现时间轴异常后，立即提示并暂停依赖正常时间轴的编辑，原只读分析继续收集到片尾，界面显示真实进度并允许停止。异常标记与分析任务失败分开：已知时间轴异常不再直接终止扫描；文件无法读取、数据无法可靠解析等实际失败仍需停止并报告。

用户确认修复后，使用已经完成或正在进行的同一次原片分析；不从零调用另一套全片包扫描。分析中的修复请求取得自己的使用引用，防止页面状态切换误取消共享任务；分析完成但尚未确认修复的结果保留供后续使用，不能作为正常时间轴直接编辑。用户主动停止、异常退出或源文件变化可能使尚未完成的分析需要重做，明确显示原因，不承诺半次扫描可以恢复。无损换封装仍需完整读取原片，不把它伪装成可以省去的“重复检查”。不在用户确认前生成新 MP4。

改写 MP4 时间表时保留对应的样本映射，并在最终时间表及轨道、样本数核验后构建新文件自己的索引。原片字节位置不能写成新 MP4 的字节位置；通过成品采样表获取位置，时间需考虑编辑表、音视频共同起点和解码／展示顺序。已有 `Mp4TimelineRepair.ts` 能跳过媒体数据读取元数据，但尚不是通用索引读取器，需补充实现和正确性验证，不能直接宣布复用已可行。

优先限定本工具修复器生成的非分片 MP4，依据已知结构和修复时间表生成索引，保留必要的首尾、断点附近局部解码核验；不额外整片解码来生成同一份关键帧目录。该路径的时间、位置和无损边界必须与现有参考结果对照。

新 MP4 安全发布并确认最终身份后才发布新索引。跨盘复制改变文件身份，需要绑定最终文件，而非任务中间文件；复制取消时不发布任何完成索引。媒体已发布但索引落盘失败时保留新 MP4，明确提示“视频已保存，编辑准备未完成”，允许从成品时间表恢复准备，不再次修复原片。

### 3.5 普通 MP4 与其他既有格式

已具备有效共享索引时直接使用；已有 MP4 没有索引时，优先评估从容器时间／采样表建立所需信息，局部核验关键帧。不能把只支持本工具生成文件的解析器直接用于任意 MP4。对于尚不支持的容器结构，保留一次明确显示的分析路径，完成结果进入同一存储；后续执行不再重复。

本轮不新增所有格式的时间轴修复支持，不改动精确导出重新编码的语义，也不以容器关键帧标记代替已验证的无损边界保护。

### 3.6 工作量、进度和限制

显示实际阶段：首次建立索引、复用已保存索引、修复时间轴、无损封装、局部边界核验、导出。能取得读取位置时显示实际扫描进度；未知时明确表示进度未知，不显示具有百分比含义的固定三分之一条。

长视频的等待上限不能靠截短索引或拒绝超过固定文件大小来实现。字段采用紧凑表示、按需加载与有界工作缓冲；处理实际长片记录内存峰值和索引体积。不重复保存完整包表和多套等价 JSON；是否需要保留修复专用包字段，应区分原片修复准备与成品长期索引。

## 5. 必要验证与验收标准

以实际进程调用、阶段计时及读写量记录为依据；操作系统已缓存文件导致变快，不算消除了重复扫描。区分索引扫描、局部校验、换封装、输出读写和重新编码。

| 场景 | 必须证明的结果 |
| --- | --- |
| 正常长 FLV／TS，首次编辑后导出 | 首次仅一次所需全片分析；导出不新增全片关键帧／精确时长扫描；不生成整片播放 MP4 |
| 无内置索引长 FLV，前／后段等长短片及后段连续多次导出 | FFprobe 边界核验与 FFmpeg 输入寻址都使用已有位置结果；读取量不随切点距片头距离线性增加，不重复读片头到切点；输出正确，缓存命中不能掩盖逻辑重复读取 |
| 同片多个方案与重复执行 | 共享同一源版本的完整索引；不因短期缓存过期再扫描 |
| 重启、回载、常规自动清理后导出 | 已关联且有效的索引仍在，完整媒体扫描次数为零；允许轻量属性和有限局部核验 |
| 异常长片修复、新 MP4 编辑和导出 | 源文件未变、未主动停止且无实际读取故障时，发现异常前后共享一次原片分析；成品不重新全片解码建立索引；断点前后时间、样本位置与画面匹配 |
| 异常提示后立即确认、延迟确认或停止 | 立即确认复用在途任务，延迟确认复用完整结果；确认前没有 MP4 输出；主动停止能取消无其他使用者的分析，不发布假完整结果 |
| 关键帧、B 帧、非零起点和可变帧率 | 定位与正反逐帧正确；快速无损保持既定边界余量语义；精确导出首尾和多段音画同步无退化 |
| 保存／另存方案 | 媒体扫描进程次数为零；索引未完成、完成回执与保存竞争均不丢方案 |
| 分析完成回调迟到，期间方案被修改或删除 | 旧内容修订不能提交关联；当前方案内容和删除标记有效，完整索引保留，删除方案不复活 |
| 完整索引发布后、查找目录或关联写入前中断 | 重启仅通过方案／索引记录恢复查找与引用，不重新扫描媒体、不重复生成完整索引 |
| 方案从恢复快照回退，外部关联仍为新版本 | 根据恢复后的源绑定和内容修订重新匹配，不沿用错误关联；缺少源绑定时进入待确认 |
| 同片两个方案，删除其中一个 | 索引保留，另一方案仍可免扫描执行 |
| 删除最后一个方案、完整索引长期未引用 | 仅解除方案关联，完整索引仍保留；自动维护不得因闲置、容量、份数或无引用删除它 |
| 方案或关联读取失败 | 不误判无引用、不删除索引、配置、方案、原片、验收记录及附件 |
| 取消、窗口关闭、异常退出 | 不将半成品当完整索引；仍有使用者时不中断共享分析；无引用临时产物可回收 |
| 跨盘修复与发布窗口崩溃 | 索引绑定最终文件；已发布视频保留；无最终文件的记录不可用；恢复不自动重修原片 |
| 文件变化、同名替换、损坏索引 | 旧结果拒绝使用，原方案和切点保留；不静默换时间轴；不进入无限重复扫描 |
| 旧方案首次关联，同路径同长度／同时长素材被替换 | 不能自动判为匹配；确认前不执行旧切点导出；取消不改方案，确认前后身份变化则不绑定 |

使用已有真实异常 TS 原片及修复 MP4，补充可控正常 FLV／TS、B 帧／非零起点样本。真实正常高码率长 FLV 仍无用户素材，继续保留待办，不用合成样本冒充覆盖。记录首轮与复用路径耗时、全片分析次数、实际读写量、内存峰值与索引大小；具体秒数目标需基于同机同素材基线，不承诺所有介质固定秒开。

所有实际运行记录、失败记录及附件保留在仓库同级临时目录；跨盘验证的生成文件另保留在目标盘，并在报告中记录路径。本轮已运行类型检查、受影响测试、界面及媒体验证和源码构建，未打包。

## 6. 实施顺序

1. 先用已有长片建立分阶段耗时、扫描次数与读取量基线，并验证无内置索引 FLV 的局部输入适配；此处不通过，不宣布消除重复寻址读取。
2. 接通共享索引存储、方案源绑定及条件关联，验证完整索引发布中断后的免扫描恢复、旧方案首次确认和恢复快照回退。
3. 接通正常 FLV／TS 播放与导出消费链，验证工具实际寻址、重启和常规维护后的复用。
4. 接通异常原片分析复用、修复 MP4 索引交付，重点校验时间表与最终文件身份。
5. 收敛普通 MP4 及其他现有入口，移除已被替代的重复路径，补齐取消、恢复和跨盘保护。
6. 仅运行受影响回归并记录性能对比；不提交、不打包，除非另获用户明确要求。

## 8. 实际接入与验证摘要

- `IndexedFlvInput` 在本地回环地址提供只读虚拟 FLV 文件头，注入 FFmpeg 能识别的关键帧位置目录；原片 payload 按 Range 直读，无整片缓存文件。FFmpeg 6.0 对无原生索引长 FLV 的 7000 秒位置，边界检查由约 4.39 GB 降至约 4.65 MB，三秒流复制由约 4.39 GB 降至约 5.57 MB；这是工具寻址对照，不代表应用全部处理阶段仅需相同耗时。正常一小时 TS 的三处取段也验证了有限寻址读取。
- 完整记录和数据在同盘受控临时目录刷盘后，使用目录重命名一起发布。启动有界枚举记录，不依赖可丢失的独立目录文件；重复版本停止复用。方案引用直接随源绑定、内容修订保存在 Plan Record 内，不额外维护可错配的独立关联库。旧临时索引入口已移除，未迁移或删除旧索引文件。
- 原片未变化时，播放、回载、导出和修复复用同次分析；修复成品发布自身索引。正常素材不长期保存修复专用包表；异常素材保留所需整数时间表。两份真实异常 TS 的索引约 76.4 MB、105.1 MB，验证进程峰值内存约 827 MiB（连续处理两份的进程峰值）；它们不是几 MB 的普通定位目录。没有以文件大小或缓存容量截断长片。
- 原片及已有方案保留；首次确认是用户认可当前对应关系，不宣称能证明历史文件相同。删除方案仅移除引用；完整索引不会因引用数或闲置时间被清理。
- 取消与共享使用者、发布前后进程退出、迟到关联、删除防复活、旧修订防覆盖、恢复快照回退和跨盘发布验证见报告。多段快速无损与精确导出分别与未使用虚拟索引的参考路径对照，解码视频、音频及时间戳一致。
