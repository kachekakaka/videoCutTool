## 1. 已确认的使用效果

### 1.1 播放倍速

- 工作台播放控制区提供 0.5、0.75、1、1.25、1.5、2 倍选择，默认 1 倍。
- 切换视频、回载方案和切换页面沿用本次应用会话选择；重启应用恢复 1 倍。
- 仅影响预览播放，不改变切点时间、逐帧步进、快进快退的源视频时间单位、保存方案或最终导出内容。
- 原片播放与兼容播放预览使用相同倍速。暂停时可以更改速度，但不会因此自动开始播放。

### 1.2 裁剪与转码进度

- 方案中心的执行中方案显示当前阶段、整项任务百分比及进度条，例如“转码中 · 65%”。
- 排队方案显示“等待处理”；尚不能计算进度的准备过程显示阶段和不定进度指示，不编造百分比。
- 单段、多段、合并导出、智能降码及由空间编辑触发的转码都纳入同一任务进度。
- 百分比表示整项任务已完成的处理工作比例，不代表已消耗的时间比例；本轮不估算剩余时间。
- 只有输出文件发布成功且完成状态持久化成功，才能展示完成和 100%。

本轮不增加任务取消入口，不扩展完整空间效果预览，不承接其他活动方案尚未完成的验收。现有兼容播放预览进度仍用于其原有用途。

## 2. 当前代码事实

1. `VideoPlayer.tsx` 使用 HTML 视频元素，尚未设置播放倍速；播放控制按钮位于 `Timeline.tsx`，由 `CutterPage.tsx` 连接。
2. `MediaCuttingEngine.ts` 串行执行队列，导出过程包含可选时间戳整理、裁剪、合并、转码、产物校验、发布和结果保存。执行使用工具路径快照，需要将本次执行的进度回传给持有队列的主引擎。
3. `runMediaTool` 已提供 stdout 分块回调及关闭完整 stdout 收集的选项，可承接 FFmpeg 进度输出。当前导出调用没有接入它们。
4. `EngineState` 已通过 `engine:state` 和 `engine:stateChanged` 传到 `AppDataContext`，可以直接扩展该状态快照，不增加另一套通知通道。
5. 方案中心目前只展示生命周期状态；已有 `PreviewProgress` 是兼容播放预览的请求进度，不能用于表示方案执行进度。
6. 调查时工作区已有 `AGENTS.md`、`MediaTools.ts`、`PlaybackPreviewService.ts` 的修改和未跟踪待办文档。实施以当前内容为基线，保留这些变更；触及相关文件前重新检查差异。

## 3. 技术路径

### 3.1 倍速状态与控制入口

- 在常驻的 `CutterPage` 中保存本次会话倍速，不写入应用配置、草稿或方案记录；素材切换及草稿重置流程不重置该状态。
- `Timeline` 接收当前倍速和变更回调，在现有播放控制组旁增加紧凑选择框，选项明确显示“0.5×”等标签，并提供可访问名称“播放速度”。无素材或不能播放的视图沿用已有播放控件可用性规则。
- `VideoPlayer` 接收倍速属性，在属性变化、视频元素重建及媒体元数据就绪时应用到 `playbackRate`；默认播放速度同步设置，避免原片切换为兼容预览后回到 1 倍。
- 保持浏览器支持的音调保留行为。切换速度不调用播放、跳转或草稿修改操作。
- 检查原有绝对居中的控制组与左右内容是否重叠，必要时只调整该控制条布局。原型更新仍在唯一真源 `docs/prototypes/prototype.html` 的现有工作台内完成。

### 3.2 进度数据与生命周期

在 `types.ts` 定义 `ExecutionProgress`，包含：

- `planId`：所属方案。
- `stage`：准备、整理时间戳、裁剪、合并、转码、校验、发布、保存结果等有限阶段。
- `percent`：整项任务百分比；准备阶段无法计算时为 `null`。
- 当前阶段可选的分段序号和总数，用于“裁剪中（2/3）”等展示。

`EngineState` 增加 `progress: ExecutionProgress | null`。它是主进程内存中的运行快照，不写入 `PlanRecord`，不随每次百分比更新触发方案写盘或列表重新排序。

- 主引擎为每次执行创建独立进度上下文，并通过回调传给执行快照；回调同时校验本次执行身份，避免相同方案再次执行时收到上一次的迟到事件。
- 开始任务建立准备状态；正常完成或失败在最终记录持久化、通知后清除运行进度。完成项的 100% 由持久化的 `completed` 状态派生。
- 输出成功但结果写入失败时保留“等待保存结果 · 99%”，即使 `activePlanId` 已清空，仍通过 `progress.planId` 关联该方案；保存重试成功后再显示完成。
- 导出失败且失败状态尚未保存时保留实际最后进度，并结合现有存储错误提示说明“处理失败，等待保存结果”，不得显示成功或推进到 99%。
- 下一项任务、同一方案重新执行及应用重启建立新进度；不恢复上次会话的百分比，不改变既有执行状态恢复规则。

### 3.3 FFmpeg 进度读取

新增职责集中的 `src/main/services/ExecutionProgress.ts`，提供 FFmpeg 进度解析和本次任务的步骤汇总辅助逻辑，不引入新依赖。

- 媒体处理命令通过 `-progress pipe:1`、`-nostats` 输出进度，复用 `runMediaTool` 的 `onOutput`，并设置 `captureOutput: false`。普通 FFprobe JSON 输出保持原调用方式。
- 采用带尾部缓冲的逐行解析，处理一行或一个进度块被拆到不同 stdout chunk 的情况；尾部缓冲有长度上限。
- 使用有效的 `out_time_us` 计算当前命令完成比例；忽略未知键、无效值和负值，裁剪越界比例，避免错误时间戳产生负数、NaN 或超过 100%。
- 明确每类命令的输出时间原点；带时间戳保留或非零起点的命令用已探测的输出时间基准校准，不能把绝对时间直接当已处理时长。
- `progress=end` 只表示该命令输出结束；该步骤须等进程成功退出后才能标记完成，整项任务仍须继续校验、发布和保存。
- 进度刷新最多每 200ms 通知一次；阶段切换、错误及结束立即通知。不设置用时间自动上涨的假进度，不为显示进度额外完整扫描媒体。

### 3.4 整项任务百分比

采用按实际执行步骤及处理媒体时长加权的统一计算，保持简单、可解释：

1. 准备阶段完成元数据、关键帧和执行路径判定后，列出本次真正需要的 FFmpeg 步骤，固定其权重。
2. 每次裁剪按该安全区间时长分配权重；合并和转码按输入媒体预计总时长分配；可选的整片时间戳整理按原片时长分配。一次实际处理只计入对应步骤一次。
3. 媒体处理占总进度的 0—95%。若步骤权重为 `w_i`、本步骤完成比例为 `r_i`，则该部分为 `95 × Σ(w_i × r_i) / Σ(w_i)`。预计时长使用已掌握的安全区间与元数据；当前步骤实际输入探测结果只用于修正其内部比例，不改动已冻结的全任务权重。
4. 产物校验和文件发布占 95—99%，按实际产物的校验、发布操作完成数推进；跨卷复制期间显示“发布中”并保持当前值，完成后推进，不新增字节级复制计量。独立导出的编码与校验原本交错执行，提前完成的校验只记账，在全部媒体步骤成功前不进入 95—99% 区间，避免第一段校验后就跳到收尾进度。
5. 结果持久化期间保持 99%，保存成功后由完成状态展示 100%。失败保持最后有效值并显示失败原因。

为避免不同步骤或重试造成倒退，在同一次执行中使用进度高水位；自动硬件编码失败回退 CPU 时显示“转码中（CPU 重试）”，重试重新计算本步骤进度，但总体值在追上之前保持不变，不重复累计工作量。发布遇到同名竞争重试同样不重复累计。

百分比不拟合运行耗时，所以流复制阶段可能跳得很快、转码阶段较慢。极短任务允许直接从准备跳到完成，不人为延长处理。未知或无效时长不做除法，显示不定进度阶段直至能够确定。

### 3.5 方案中心展示

- 在执行中方案现有状态区域展示阶段文案、整数百分比和进度条，按 `progress.planId` 精确匹配；只有当前执行方案显示其运行进度。
- 排队显示“等待处理”；准备阶段显示不定进度；失败继续展示现有错误信息；完成显示完成状态及 100%。
- 进度条提供可访问名称及有效范围；不定进度不设置虚假的数值。百分比刷新不让辅助阅读工具每 200ms 播报。
- 使用既有引擎状态订阅与首次快照获取机制，确保切换页面、重新打开方案中心后立即得到最新进度；更新类型默认值并保留现有防止旧快照覆盖新事件的逻辑。
- 调整工作台入队提示，使“实时进度”明确指向方案中心；本轮不在工作台重复放第二套进度面板。
- 原型中的方案中心同步阶段、进度条、排队和保存等待状态，不新增 HTML 副本。

## 5. 实施顺序与验收

先完成倍速控制及播放器接入，再实现导出进度解析、步骤汇总和状态传递，最后完成方案中心及原型展示，两项统一验收。

| 场景 | 验收标准 |
| --- | --- |
| 六档倍速与暂停切换 | 真实视频元素速率正确；播放时速度变化，暂停时不自动播放 |
| 会话延续 | 换视频、回载方案、切换页面、原片转兼容预览均保持选择；重启恢复 1 倍 |
| 剪辑时间语义 | 逐帧、快进快退、插入切点及试听结束仍按源视频时间；倍速不写入方案或改变导出时长 |
| 控制条布局 | 常用及最小支持窗口尺寸下，选择框不遮挡播放、时间码、缩放和切点按钮 |
| 纯无损单段、多段、合并 | 阶段正确；多段以整项任务为口径；百分比不倒退、不提前到 100% |
| 智能降码、空间处理、时间戳整理 | 对应实际命令均接入进度；无遗漏或重复累计；非零起点和 VFR 样本进度有效 |
| 硬件自动回退 CPU | 阶段说明重试，整体进度不倒退，成功前不显示完成；无硬件时用外部一次性脚本验证回退回调边界并如实标明覆盖限制 |
| 输出及存储异常 | 导出失败不报成功；发布重试不重复累计；成功产物遇保存失败保持 99%，重试保存成功后才到 100% |
| 队列、导航与重新执行 | 等待项无伪百分比；切换页面取回实时进度；任务之间及同一方案重复执行不串进度 |
| stdout 分块与异常数据 | 半行、跨块、缺失时间、无效值、负值、超长尾部、进程失败均有明确处理；不积累完整进度输出 |
| 实际产物回归 | 导出时长、音轨、裁剪及遮罩效果符合原规则；进度功能不改变媒体处理结果 |

- 运行 TypeScript 检查和现有构建；必要时运行相关已有检查，不新增测试体系，也不新增进度或 UI 单测文件。
- 进度解析、加权及失败边界采用一次性验证脚本；使用实际 FFmpeg 导出覆盖代表性路径。脚本、媒体、日志及截图统一放到仓库同级 `../videoCutTool_tmp/`。
- 界面验证先检查可用 Playwright 能力及其 Electron 连接支持，再进行实际窗口操作；只有原生交互或确认 Playwright 无法覆盖时才补充 Computer Use，并记录原因。
- 验收记录区分真实媒体、模拟异常和未覆盖硬件，不以静态检查替代运行验证。

## 7. 实施与验收结论（2026-10-17）

- 六档倍速、会话内保留与重启恢复已实现；原片、自动改封装预览、转码兼容预览使用相同速度，切点和导出内容不随倍速改变。
- 导出通过既有引擎快照通道发送阶段和整体进度，覆盖多段、合并、转码、空间处理及时间戳整理；结果保存失败保持 99%，重试完成后才展示 100%。运行进度不写入方案记录。
- FFmpeg 输出采用有界分块解析，常规更新节流；合并时逐个探测切片元数据，避免为计算进度产生大量并行探测进程。
- 控制条改为参与正常排版，1080×700、1360×900 实际窗口检查通过。原型同步两项功能，并修正验证中发现的虚拟画布网格引用未定义坐标的既有笔误。
- `npm run build` 通过；现有 5 个测试文件、22 项用例通过。未增加仓库测试文件或测试体系。
- 后台 13 组场景通过：单段无损、多段合并、多段独立、合并转码、独立转码、合并空间处理、独立空间处理、成功结果保存重试、失败结果保存重试、硬件初始化失败后 CPU 回退、非零时间戳、VFR、AVI 时间戳整理。成功产物经元数据与音轨检查；另核对裁剪尺寸、遮罩区域黑色像素。
- Playwright 验证实际 Electron 窗口：六档倍速、0.5/2 倍播放时间推进、逐帧与快进一秒、页面切换、素材切换、兼容预览换源、方案回载、实际双任务队列、完成状态、重复执行重置及重启恢复均通过，无页面运行错误。原型阶段演示复验无脚本错误。
