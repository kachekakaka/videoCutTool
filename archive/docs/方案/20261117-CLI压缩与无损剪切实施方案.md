## 目标与首版边界

让本机其他程序通过命令行传入原片完整路径、成品完整路径和处理参数，执行整片压缩或无损剪切；不打开窗口，等待完成后通过 JSON 和退出码返回结果。

首版面向 Windows x64 便携包，每次调用处理一个原片、生成一个成品。剪切支持一个或多个按时间排序的保留区间，多区间按顺序合成一个文件。使用现有关键帧无损策略，不提供逐帧精确导出、画面处理、覆盖已有文件、后台脱离进程运行或远程服务。

CLI 与桌面界面复用处理服务和媒体引擎，但首版不共享任务列表。CLI 使用独立数据目录，避免恢复桌面的排队任务或干扰其状态。后续 HTTP 可复用公共任务入口；监听服务、鉴权、文件传输及远程路径映射届时另行实现。

## 命令契约

便携根目录新增控制台入口 `VideoCutTool-cli.exe`，原桌面入口保持用途不变。以下为拟实现接口，当前尚不能执行：

```powershell
.\VideoCutTool-cli.exe compress --input "D:\素材\原片.mp4" --output "E:\成品\压缩.mp4" --preset balanced --data-dir "D:\VCT-CLI数据"
.\VideoCutTool-cli.exe compress --input "D:\素材\原片.mp4" --output "E:\成品\压缩.mp4" --preset custom --crf 24 --max-height 1080 --encoder cpu --data-dir "D:\VCT-CLI数据"
.\VideoCutTool-cli.exe cut --input "D:\素材\原片.mp4" --output "E:\成品\剪切.mp4" --range 10000:30000 --range 60000:90000 --data-dir "D:\VCT-CLI数据"
.\VideoCutTool-cli.exe --help
.\VideoCutTool-cli.exe --version
```

- `--input`、`--output`、`--data-dir` 必填且要求绝对路径，避免启动器工作目录改变含义；支持中文、空格和合法特殊字符。数据目录是 CLI 专用的持久目录，不是成品目录。
- `compress` 默认使用 `balanced`，预设枚举和参数合法范围复用 [CompressConfig](../../../src/shared/types.ts)及现有校验。`--crf`、`--max-height` 仅在 `--preset custom` 时接受，其他组合报错，不静默忽略。`--encoder` 支持 `auto/cpu/nvenc/qsv`，默认 `auto`；实际编码器在结果中返回，自动选择及回退规则复用引擎。
- `cut` 的 `--range 起点:终点` 使用非负整数毫秒，可重复。必须起点小于终点、顺序递增且不重叠，终点不得超过媒体有效时长。相邻区间可合并；无范围、空范围和越界均报错。首版只做无损剪切，不接受压缩参数。
- 原片封面默认沿用当前导出的去除策略，可用 `--keep-cover` 请求保留；流与容器不兼容时明确失败，不静默丢弃或转换模式。
- 未知选项、除 `--range` 外的重复选项、缺失值均报参数错误。首版不增加独立 JSON 请求文件语法，程序直接使用子进程参数数组调用即可。
- `--help` 和 `--version` 不启动媒体处理、不创建数据目录。

无损剪切仍按关键帧保全内容，实际起点可能提前、片尾可能扩出，不承诺精确等于请求区间。请求区间之间可能因关键帧扩展而重叠，规划继续复用现有 Retention Draft / Retention Plan 规则；帮助与结果警告必须解释此边界。

## 输出与进程生命周期

默认等待当前任务结束，不提供 `--detach`。stdout 只输出一行最终 JSON；诊断和节流后的进度写 stderr，不混入 JSON。帮助与版本命令输出普通文本。全部文本使用 UTF-8。

CLI 分支在加载处理服务之前安装日志适配，将 console.log/info/debug/warn/error 全部导向 stderr，覆盖现有 CacheMaintenanceService 的 console.info；最终结果使用独立输出函数，不借用 console。该适配仅作用于 CLI 进程，桌面日志行为不变。启动器并发读取子进程 stdout/stderr，避免重定向管道写满导致阻塞；stderr 持续转发，stdout 的最终结果缓冲至子进程退出并核对后只写一次。正常业务结果与退出码必须一致，重复结果、非法 JSON、缺失结果或退出码矛盾均作为协议/进程错误返回，原始诊断放 stderr，不将零退出码等同于处理成功。缓冲设置上限，超限终止并报错，不无限占用内存。

帮助与版本使用明确的文本输出分支。启动器自身启动失败也返回约定的错误 JSON 和非零退出码，不弹 MessageBox。无法确认是否已经发布成品的异常退出，错误 code 使用 PROCESS_EXITED，附带 requestedOutputPath 与 outcomeUnknown: true；不能根据目标文件存在就认定它是本次完整成品。

成功示例：

```json
{"ok":true,"taskId":"生成的ID","operation":"compress","status":"completed","outputPaths":["E:\\成品\\压缩.mp4"],"resolvedEncoder":"cpu","warnings":[]}
```

失败示例：

```json
{"ok":false,"operation":"cut","status":"failed","error":{"code":"OUTPUT_EXISTS","message":"目标文件已存在"},"outputPaths":[]}
```

任务创建前失败可省略 taskId；没有完成的成品不得作为成功输出返回。发布完成但状态保存失败时，返回明确错误以及已完成产物路径，不能让调用方误以为没有产物而盲目重试。记录与最终结果仍须遵守现有保存成功边界。

### 存储故障与完成判定

- 为 MediaCuttingEngine 增加只读的单任务执行结果快照接口，返回已知执行阶段、已发布完整产物、存储故障及待保存最终结果的副本。不能要求适配层读取私有 pendingFinal，不能把请求路径当成已发布路径，也不能由接口触发重新执行。
- ProcessingTaskService 在提交前订阅任务状态与存储故障，提交后再次读取快照，关闭先完成后订阅的竞态。只靠 completed/failed 通知不足以结束等待，因为当前引擎保存失败会暂停队列而不发送最终完成通知。
- CLI 首版遇到存储故障立即停止本次后续派发，不自动重试、不等待桌面人工操作。取得结果快照后进入专用故障收尾：停止本次仍在运行的媒体工作，等待或按退出超时规则结束，保留已发布成品和可用记录，再返回 error.code=STORAGE_FAILED、退出码 5。不得调用会清空待保存结果或遗漏已发布路径的普通取消流程代替故障收尾。
- 分别处理提交/开始处理前、压缩准备信息保存时、最终成品发布后保存失败；即使失败记录本身无法落盘，也必须向调用方返回错误，不能因为“未收到最终状态”无限等待。已发布路径通过独立快照保留到最终回执，收尾错误附加到错误详情，不覆盖它。
- 桌面继续保留现有人工重试保存能力；CLI 策略由公共任务服务的调用模式决定，不全局改变引擎的桌面恢复行为。下一次 CLI 启动不自动重跑失败或中断的历史任务。

| 退出码 | 含义 |
| --- | --- |
| 0 | 成功，或帮助/版本正常输出 |
| 2 | 命令或参数错误 |
| 3 | 环境、路径、工具、容器不支持、目标已存在等前置检查失败 |
| 4 | CLI 数据目录或目标侧任务根正被占用 |
| 5 | 执行、结果持久化、内部通信或收尾失败 |
| 130 | 用户中断 |

### 取消与退出通道

控制台启动器截获 Ctrl+C，通过专用的子进程 stdin 管道发送一行内部取消消息；CLI 子进程监听该消息并调用公共任务取消入口。该管道由启动器独占，不转发调用方 stdin，不新增公共标准输入协议。重复取消只进入一次收尾；控制管道 EOF 表示启动器断开，子进程主动终止本次工作。不能仅依赖 Windows 将 SIGINT 自动传给无窗口 Electron。

正常取消依次停止本次媒体进程、等待引擎取消及状态保存、清理受管任务、释放根和数据目录占用，然后返回取消结果及退出码 130。已发布完整成品必须保留并写入结果；若成功结果已持久化则保留成功结论，不能由迟到的 Ctrl+C 改成失败。取消期间出现存储或收尾故障返回对应错误和退出码 5，不假报清理成功。

启动器收到取消或检测到异常后给予 15 秒收尾期限；正常媒体处理不设这个总时限。超时使用本次进程专属的 Windows Job Object 终止所属进程树，返回 CLEANUP_TIMEOUT 和退出码 5，并明确哪些产物状态未确认。子进程先挂起创建、加入 Job 后再恢复，确保 Electron 和媒体后代都受约束；Job 使用关闭即结束所属进程的策略，启动器异常退出也不遗留本次进程。无法建立进程归属控制时在处理开始前失败，不回退到按名称杀进程。正常退出先等子进程清理完成，再关闭 Job 和控制管道。

强制结束不承诺即时清理磁盘文件，后续启动按既有登记恢复，不能自动重跑上次任务。最终回执在收尾与子进程退出核对后输出；超时或崩溃导致结果不可确认时使用 outcomeUnknown，不能伪造成功或空产物结论。

## 数据与并发边界

为保持首版简单，`--data-dir` 显式指定独立 CLI 数据目录，首次可自动建立配置、方案与索引。它不写桌面 `workspace.json`，不修改桌面配置，也不自动导入桌面任务。

CLI 目录使用用途标记，并在读取或写入配置之前取得独占锁；已有未标记且非空目录拒绝直接认领，桌面已使用的数据目录拒绝作为 CLI 目录。桌面初始化同样识别 CLI 用途标记并拒绝绑定，防止反向误用。锁使用进程持有的操作系统互斥资源或保持句柄的排他锁，不以单个残留文件是否存在判断占用；规范化真实路径，处理大小写和目录别名。

### Electron 启动隔离

在主入口最前面识别 CLI 标志；桌面模块必须在分支内加载，不能用顶层静态导入提前执行桌面单实例锁、协议、窗口或对话框副作用。纯参数检查、帮助和版本先处理；有效任务在取得 CLI 数据目录锁后才读取或初始化业务配置。

CLI 在 app.whenReady 之前设置独立的 userData 和 sessionData，使用仓库/便携目录同级临时空间下、按本次调用随机 ID 分隔的 CLI 运行目录；不复用桌面 electron_userdata，也不调用桌面的 requestSingleInstanceLock。CLI 并发约束由数据目录锁负责，而非桌面窗口锁。运行目录不存方案、索引或导出媒体，退出后按归属清理；无法设置隔离路径时明确失败，不回退默认用户目录。帮助/版本分支在 Electron 就绪前退出，不创建业务目录或运行配置。

同一 CLI 数据目录同时只运行一个进程，第二次调用立即返回占用错误。不同目录可独立运行，但不承诺资源调度；GUI 与 CLI 可以同时运行，各自使用独立队列、索引及缓存登记空间。

CLI 启动只执行本次新任务，历史记录用于诊断，不自动恢复历史排队项。为 PlanManager 增加明确的启动策略，CLI 模式不加载或派发历史队列，且不能将历史排队项混入本次队列快照。桌面维持原队列恢复语义。

持久配置、方案和完整索引归入 CLI 数据目录。导出媒体中间文件遵循[架构真源](../../../docs/架构.md#同卷处理与发布)，置于成品目录中的专用受管空间；其他运行缓存按既有临时空间规则存放。CLI 使用独立且可跨重启发现的维护登记，与桌面共享目标侧受管根时必须遵守所有权互斥，不得相互清理存活任务；实际占用时明确失败，不转移到其他盘。导出根锁按任务及清理的使用期间持有，闲置后释放，不因桌面保持打开而阻止 CLI；这与整个 CLI 调用期间持有的数据目录锁分别管理。历史发现不创建缺失目录，具体生命周期与恢复规则统一引用架构真源，不在 README 复制。

## 实现结构

1. 新增 `electron/cli.ts` 作为无窗口执行入口，按上述启动隔离顺序完成前置工作，等待 Electron 就绪后只初始化必要处理服务；不构造 BrowserWindow、播放器、预览服务或文件选择对话框。继续随便携包分发 Electron 和媒体工具，不要求使用者安装 Node.js。
2. 新增 `src/main/cli/arguments.ts`、`src/main/cli/run.ts`，分别负责命令解析和标准流/退出码/取消适配。启动器通过明确内部标志进入 CLI 分支，`electron/main.ts` 在执行桌面模块副作用前完成分流；桌面初始化可拆入 `electron/desktop.ts`。构建必须保留 CLI 所需模块。
3. 新增 `src/main/services/ProcessingRuntime.ts`，集中构造配置、索引、引擎、方案管理器及关闭流程，显式传入数据目录、缓存空间与启动策略。桌面事件转发和 CLI 标准流处理留在各自适配层。
4. 新增 `src/main/services/ProcessingTaskService.ts` 与 `src/shared/processingTask.ts`，定义独立于 Electron IPC、命令行、HTTP 的请求、结果与进度契约。公共入口接收规范化路径、压缩或保留区间及输出要求，提供提交、等待、订阅进度和取消；通过既有 PlanManager 和 MediaCuttingEngine 执行，不再写另一套 FFmpeg 命令生成器。
5. CLI 显式路径经规范化、可读性和格式校验后进入公共入口；桌面继续保留可信窗口及 FileAccessRegistry 检查，不能为了 CLI 放宽现有 IPC 来源限制。将必要的纯业务参数校验从 IpcSecurity 中抽出复用。
6. 剪切请求通过共享媒体索引准备时长、源版本和关键帧信息，转换为 Retention Draft、保留决定及单个输出分组，再提交现有执行流程。压缩复用轻量检查与执行时探测，不先建立裁剪完整索引。源版本绑定和发布前检查继续复用现有机制。
7. 引擎增加明确的输出意图：桌面使用自动命名，CLI 使用指定完整路径。将请求目标与执行后 outputPath/outputPaths 分开保存，避免压缩准备阶段清空结果字段时丢失目标。指定路径分支必须在创建 OutputTaskWorkspace 前确定目标父目录，最终发布时直接使用请求文件名，不再调用自动命名器；桌面分支保持自动命名。同步调整类型、记录存储校验、请求校验及引擎计划构造，不做旧数据迁移或历史兼容分支。
8. 引擎、公共任务服务及 CLI 适配层按“存储故障与完成判定”分工：引擎提供事实快照和可等待的停止能力，服务决定当前调用的失败策略，CLI 仅转换结果/退出码。请求参数、准备失败、执行失败、存储故障、取消和崩溃均有结束路径。

## 指定输出路径

- 首版只生成一个输出文件，因此 `--output` 始终是完整文件路径，不自动改名或加序号。
- 要求父目录已存在且可写；输入和输出不得是同一个文件，校验规范路径以及已有路径的文件身份/链接关系。
- 后缀必须与现有格式解析器选择的输出容器一致；不支持的组合在执行前报错，不能自动换后缀、转码或生成别处文件。
- 已有目标立即失败，不提供覆盖开关；发布时仍进行排他创建，防止预检后另一调用抢先创建。CLI 遇到目标冲突直接报错，桌面自动命名仍按原逻辑重试。
- 导出媒体从开始就在成品所在卷内处理，验证完成后排他发布；不再跨盘复制或以最终名称写半成品。复用全项目同盘发布入口，文件系统不支持时明确失败，不能回退复制。成功回执仍以成品发布及结果保存完成为界。
- 不能将任意用户输出目录登记为可整体清理的缓存目录。

## 实施顺序与验收

1. 先打通最小启动链路：参数解析、控制台启动器、无窗口入口、Electron/数据目录隔离及最终回执。用仅测试可注入的短任务验证标准流、退出码、取消与进程归属控制，不增加产品测试命令。先证明桌面与 CLI 可共存，再接媒体处理。
2. 建立公共任务服务和请求/结果契约，先接通整片压缩，再接单区间和多区间无损剪切；落实明确输出意图，复用现有同盘任务空间与发布入口。
3. 补齐存储故障、结果快照、目标冲突、目录占用、取消及异常退出分支，完成相关服务测试和代表性媒体执行。
4. 完成一次 Windows 便携候选构建，用真实控制台入口与子进程调用验收；完成桌面受影响流程最小回归。补充用户文档并按 [README 验证与交付](../../../README.md#验证与交付)交付。

验收必须覆盖：

- 类型检查及本次涉及的既有测试通过；新增测试重点覆盖未知/重复参数、范围非法、指定路径不被重命名、输出冲突及历史任务不被误启动。
- 代表性 MP4 整片压缩、单区间和多区间无损剪切成功；使用 ffprobe 核对视频/音轨、成品可读性与实际时长。无损验证确认使用流复制及关键帧策略，不以时长恰好等于请求区间作为通过标准。
- 代表性正常 FLV 非零起始时间戳素材：索引准备、非零位置剪切和源版本复用正确；不将整片索引扫描带入压缩参数校验。没有原素材时明确替代样本的覆盖限制。
- 中文、空格和特殊字符路径，源文件不存在，源目标相同，已有目标、容器不兼容、工具缺失、编码器不可用均给出非零退出码及明确错误。
- Ctrl+C 在素材准备、处理中及发布后分别验证；正常取消回收中间文件、保留完整产物并返回 130，已持久化成功结果不被迟到取消改写。重复取消、控制管道断开、启动器/子进程异常退出及 15 秒收尾超时均有最终回执和约定退出码，确认本次进程树退出且没有结束无关进程。
- 分别注入提交/开始处理前、压缩准备信息保存时、最终成品发布后的存储故障：CLI 不无限等待、不自动重做媒体处理，返回 STORAGE_FAILED 和退出码 5；发布后的失败回执包含准确成品路径。另覆盖取消时保存失败、失败发生在订阅前后的竞争及无媒体进程可停止的前置失败。
- 制造缓存维护日志与高频 stderr 输出，确认 stdout 仍可一次解析为唯一 JSON，不因管道背压挂起；启动失败、子进程无回执/非法或重复回执、崩溃及重定向输出的 UTF-8 均有覆盖，不能输出假成功。
- 同一 CLI 数据目录并发调用被拒绝；桌面目录不能作为 CLI 目录，CLI 目录不能被桌面绑定；CLI 不执行历史任务、不改变桌面队列及 workspace 绑定。
- 桌面保持打开时运行 CLI，两者运行目录、单实例行为和队列互不干扰；不同 CLI 数据目录可同时运行且 Electron 运行目录不同。共享成品目录时活动任务占用仍失败，前一任务收尾后可再次取得。同一数据目录通过别名访问也不能绕过锁；帮助/版本不创建业务数据及运行目录。
- 程序与成品不同卷时，媒体中间文件仍位于成品卷，同卷发布无复制兜底；失败回收不删除原片或抢占者文件。结果保存失败时返回已发布产物信息，不能误报成功。
- 对桌面原有自动命名及压缩/剪切受影响路径做实际最小回归，确认启动、任务状态通知及原有保存重试行为没有被 CLI 策略改变；记录操作与结果，不能仅用类型检查替代。
- 一次 Windows 便携候选构建后，从根控制台入口及 PowerShell 子进程重定向两种方式实际验证等待、stdout JSON、stderr、退出码和不弹窗。此项不能仅靠开发模式测试代替。
