# 缓存与旧包自动清理实施方案

- 日期：2026-10-19（Asia/Shanghai）。
- 状态：2026-10-19 实施完成并归档。用户在方案确认后授权实施与必要验证，明确不提交、不打包发布。
- 验证结论：类型检查、20 项缓存专项测试及 10 项相关既有测试、真实媒体、异常退出、PowerShell 产物夹具与开发态 Electron 窗口验证通过；既有受保护资产核对通过。按最新指令未运行安装包构建或包内冒烟，当前 r9 不包含本次代码。
- 目标：控制闲置大视频缓存，回收可确认的异常残留，淘汰受管理的旧包；不误删配置、已保存方案与验收记录，不以缓存容量限制长视频正常使用。
- 术语依据：[CONTEXT.md](../../../CONTEXT.md)。媒体调用边界依据：[架构方案 4.4](../../../docs/方案/视频裁剪工具架构与实施方案.md#44-媒体检查的耗时边界)。验证与交付按 [README](../../../README.md#验证与交付)。

## 1. 已确认的问题与改动范围

| 当前实现 | 已确认的缺口 |
| --- | --- |
| `PlaybackPreviewService` 使用最多 3 份、字节数不限的播放缓存 | 几份整片播放副本就可占几十 GiB；生成成功后才触发淘汰，闲置目录可能长期不再触发 |
| `PreviewCache` 提供数量、容量和 24 小时规则 | 没有独立维护入口；删除失败被忽略；生成失败可能绕过淘汰；当前输出受保护不等于整个展示期间受保护 |
| 预览与导出用 `finally` 删除本次 `request_*`、`job_*` | 强制退出、断电或删除失败后，没有下次启动补扫；主进程消失不代表其媒体子进程已结束 |
| 缓存路径随程序宿主位置计算 | 仓库同级、`release` 内及隔离验证目录可能各自留下一份，单目录规则约束不了总量 |
| 打包脚本每次新建 `portable-*`，并可能保存 `previous` | 无统一保留策略；`-BuildOnly` 的成功或失败候选均可能积累；历史 ZIP 和解压目录无登记 |
| 临时空间同时存放缓存、配置、方案、报告与验证素材 | 不能按整个临时目录、后缀、目录年龄或“名字像测试”进行递归删除 |

本次实施覆盖应用运行缓存与开发打包产物两条独立清理链。应用不负责删除安装包；打包清理脚本不负责删除工作数据或遍历任意用户目录。

不新增系统计划任务、后台常驻程序、数据库、组件测试或 E2E 工程；不改剪辑算法、方案记录格式、输出策略和媒体检查精度。不自动迁移历史数据，不新增文件内容摘要算法。

## 2. 使用效果与默认策略

### 2.1 软目标，不是生成门槛

推荐采用“优先保留正在使用的文件，空闲后回落到目标占用”的策略。容量只用于决定回收顺序，不用于拒绝、截短、降低分辨率或改变长视频预览的编码方式。

| 资产 | 拟定默认策略 | 超标时的行为 |
| --- | --- | --- |
| 已完成的播放缓存 | 总量软目标 8 GiB；最近使用最多 3 份；未使用满 24 小时可回收 | 先回收未被使用且最近使用时间最早的缓存；单份超过 8 GiB 也允许生成和使用 |
| 画质对比图片缓存 | 总量软目标 512 MiB；最多 128 份；未使用满 24 小时可回收 | 所有当前展示图片受保护；不因总量超标让本次合法预览报错 |
| 关键帧索引 | 总量软目标 256 MiB；最多 512 份；未使用满 7 天可回收 | 只回收已登记且没有读取/生成引用的索引；回收不会主动启动重新扫描 |
| 已释放的预览缓存 | 10 分钟复用宽限期 | 宽限期内可暂时超目标，避免反复切换同一素材造成整片重新处理 |
| 本次失败、取消的中间产物 | 正常路径结束即回收 | 删除失败进入后续重试，不改变已有成功成品或已就绪缓存 |
| 异常退出留下的任务目录 | 下次维护确认归属和相关进程均已结束后回收 | 仍在运行、归属不明或进程状态无法确认时保留并记录原因 |

目标、数量和时间统一放在维护模块的策略常量中，本次不增加用户配置项或设置页面。上述数值是实施默认值，验收时记录依据，不复制到其他文档作为第二真源。

举例：正在使用一个 20 GiB 播放副本时，即使目标为 8 GiB，也保留它；播放暂停、窗口失焦不会使它失去保护。切换素材且底层读取已结束后才开始计算宽限期，期满再回收。如果所有文件都在使用，允许持续超目标，不中断播放或任务。

实际磁盘空间不足仍可能导致写入失败。遇到此类错误只清理确认闲置的资产，说明磁盘空间不足；不将“超过软目标”冒充磁盘不足，也不自动反复执行整片生成。

### 2.2 触发时机

1. 主窗口可交互后异步进行一次维护，不阻塞启动、选入、调参和保存。
2. 缓存发布、请求失败/取消、最后一个使用引用释放后，合并安排一次维护。
3. 应用运行期间每 5 分钟检查一次；有媒体任务时推迟常规容量淘汰，正常任务自身的收尾照常执行。
4. 正常退出时取消生成并完成本次任务收尾；不要求把缓存全部清空，不为全量扫描拖延退出。
5. 构建结束后对受管理候选目录执行一次淘汰；构建前可清理已确认的旧异常候选，为本次构建腾出空间。

同一维护器只运行一轮，重复触发合并；每批最多处理 64 个登记项，批次间让出事件循环。只读登记信息与文件元数据，不读取视频内容，不启动媒体探测、换封装或重新编码。文件多时分轮完成，不为了立即达到目标做无界扫描。

## 3. 首先保证不能误删

### 3.1 所有权登记是删除前提

新产生的缓存和任务目录在创建媒体文件前登记：资产 ID、类型、受控根目录内的相对路径、创建时间、最近使用时间、状态、所属应用进程及已派生媒体进程。文件发布成功后再标为可复用；登记使用临时文件加原子替换，不扫描媒体内容。

删除必须同时满足：

1. 属于该清理器登记的资产类型与受控根目录，登记路径格式合法。
2. 路径规范化、真实路径和直接父目录均仍在允许范围；目标不是根目录本身，没有链接、联接点或可疑重解析点。
3. 没有生成、读取、展示或媒体协议传输引用，没有正在操作该资产的媒体进程，也没有清理冲突。当前应用进程仍存活不妨碍它回收自己已释放的缓存。
4. 不包含或覆盖任何受保护路径，没有后加的未知文件；删除前重新检查文件身份及状态，变化则跳过。

目录归属标记不能赋予任意路径删除权限。登记缺失、损坏或无法验证时，自动清理跳过并留下原因，不通过“文件名符合正则”补猜所有权。

### 3.2 永久保护范围

- `config.json`、`workspace.json`，以及任意工作数据目录中的 `plans/` 全树，包含恢复快照、删除标记和其他恢复数据。
- 正式验收记录及其证据目录：报告、结果 JSON、验收截图和保护清单明确标记的其他附件。文档引用不能被当作删除许可。
- 原始媒体、用户输出成品、源代码、正式测试源码、文档、归档方案、Git 数据和依赖目录。
- 已发布的当前版本、指定保留版本、任何仍在运行的版本。
- 无法确认用途或归属的文件与目录。

清理采用专用缓存容器和登记项白名单，保护名单只是第二道检查。不能按“删除所有 MP4/PNG/JSON”或“保留几个文件名后清空父目录”的方式实施。

工作数据目录可能恰好被用户设置为 `videoCutTool_tmp`。这种情况下不递归删除整个工作数据目录，只处理其中独立登记的专用缓存子目录；配置和 `plans/` 始终排除。若专用缓存目录本身与方案或验收目录冲突，停用该目录的自动回收并记录冲突，不移动或改写用户数据。

### 3.3 历史目录与多运行位置

维护器只接收程序明确解析出的缓存根目录；不扫描盘符、仓库父目录或任意历史发布目录。已登记的历史根目录可以参加同一轮维护，按最近使用时间统一选择闲置候选，避免每个根目录各保留一套大副本。

登记表存放在仓库同级临时空间内的维护专用目录，路径由主进程或打包脚本生成，不接受渲染层传入任意根目录。记录的历史根只有仍通过本方案的所有权、路径和进程检查才可清理；其他进程正在使用的根目录整轮跳过。

每个受控根目录使用独占创建的维护锁，记录进程身份和本轮随机标识；发布、登记变更与回收遵循同一锁规则。锁被其他存活进程持有时跳过，不等待阻塞交互；只有能确认原持有者已结束且锁身份未变化时才回收陈旧锁。锁损坏或状态不明时保留，不因文件年龄强行抢锁。

首次启用不自动认领没有登记的历史文件，不编写旧格式迁移或兼容分支。已有 r9、验收资料以及此次人工清理留下的配置、方案和备份默认受保护；未登记旧目录只列为需人工判断的项目。后续由新流程产生的缓存、候选和发布副本均纳入登记，防止再次积累。

## 4. 运行缓存的技术路径

### 4.1 分清“任务结束”和“文件不再使用”

为缓存增加可释放的使用引用：生成中先保留，发布后在返回 IPC 结果之前取得展示引用；播放器或对比视图确认不再展示才释放。容量维护只看到空闲文件，不从页面是否暂停、失焦或任务 Promise 是否结束推断可删除。

- 播放器切换素材、卸载、替换播放源时显式释放旧预览；只隐藏但仍持有媒体源时保持引用，直到卸载媒体源。
- 对比场景被移除、参数变更或组件不再使用旧结果时，释放对应图片；并发请求共享同一文件时按引用计数保护。
- `media` 协议读取缓存时持有读取引用，流关闭、错误或取消时释放；展示引用已释放但读取未结束仍不能删除。
- 请求取消与成功返回竞争、源素材已切换后收到旧结果、IPC 授权失败等分支，都必须释放本次结果的引用。不能因为 `request.current` 已清空而漏掉已就绪结果。
- 主进程按发送窗口和请求 ID 绑定引用，渲染层只能释放自己的引用；窗口或渲染进程销毁时统一取消请求并释放。

展示引用通过主进程管理，不持久化为永不失效的“正在播放”。异常退出后的存活确认另按任务归属处理，不凭过期时间直接删除。

### 4.2 统一维护和可见的失败处理

新增轻量 `CacheMaintenanceService`，负责登记、使用引用、软目标淘汰、异常回收和重试；`PreviewCache` 负责缓存定位及命中，停止在生成路径中抛出“超过缓存容量”的业务错误。

维护按“已确认异常且无人使用的中间目录 → 超时闲置缓存 → 为回落软目标淘汰最久未使用缓存”的顺序执行。新生成并正在交付的结果始终受保护。

最近使用时间使用独立登记信息维护，不再依赖修改媒体文件时间；命中更新在内存中合并，必要时写回，避免每次播放触发额外重写。

删除失败记录资产、原因和重试状态，不再空 `catch`。Windows 占用或权限错误在后续维护重试，使用退避避免每轮反复刷同一错误；不会强行终止未知进程。某项失败不阻断其他安全候选，也不能将尚未删除的文件算作已释放空间。

### 4.3 补齐失败发布与异常目录

保留“请求私有目录生成 → 验证 → 发布 → 返回结果”的完整生命周期：

- 尽量在发布前完成时长等必要验证；不得为清理再增加一次整片检查。
- 对确实需要发布后检查的路径，失败或取消时仅回滚本次新发布且未被其他请求使用的缓存，不删除原有命中项。
- 正常失败、取消、退出继续走 `finally`；删除失败转入维护器，不以清理失败覆盖原媒体错误。
- 下次启动扫描已登记的中间目录。必须核实所属应用进程及相关媒体子进程已结束；不能只看主进程 PID 不存在。
- 媒体工具启动和结束在 `MediaTools` 中登记进程归属；异常补扫在 Windows 上按记录和操作系统进程信息核对。登记不完整、PID 被复用、权限不足或无法排除仍有相关子进程时跳过，不能仅凭目录年龄认定异常。
- 生成、发布、释放与淘汰的元数据变更串行协调，删除前再次检查，避免刚命中的文件被并发维护删除。

### 4.4 关键帧与媒体检查边界

关键帧索引生成和命中时纳入登记，回收只删除闲置索引文件。媒体流摘要的短期内存缓存继续独立管理，不为了磁盘维护做额外探测。

调用方保持以下边界：

| 直接调用方 | 本次变化边界 |
| --- | --- |
| `VideoPlayer → media:preparePlayback → PlaybackPreviewService` | 加引用生命周期和后台回收，不因软目标拒绝长视频 |
| `CutterPage → compress:previewSamples → CompressionPreviewService` | 加图片引用和失败收尾，不扩大场景数量或媒体读取范围 |
| `MediaCuttingEngine → executeSnapshot` | 登记任务、媒体进程并补充异常残留回收，正常导出算法不变 |
| `KeyframeProber` | 登记索引，不在维护阶段重新生成索引 |
| 批量压缩选入、调参、保存 | 不接入预览生成、整片扫描或同步容量维护 |

## 5. 候选包与旧包的自动淘汰

### 5.1 将构建产物和交付记录分开管理

新增 PowerShell 7 产物登记与清理模块。构建开始登记候选目录及所属构建进程，成功后记录验证状态；失败标记为失败候选。发布使用与候选构建一致的资产 ID 关联副本，版本依据登记时间和验证状态，不靠 `rN` 文件名排序。

验收记录留在临时空间的验收专用目录，发布资产记录只保存其引用及保护路径。报告、结果和截图不放入会被整体淘汰的程序包目录。若发现旧程序包中混入配置、方案、报告或未知文件，跳过整个包并报告原因，不自动搬走、压缩或删除这些数据。

当前受控脚本没有完整的版本 ZIP 交付入口。实施只补充“登记已验证发布副本”的脚本接口，供现有交付步骤在复制或生成 ZIP 后调用；该接口核对关联候选和关键文件后登记。它不代替实际验收，不根据 ZIP 文件存在就标记为验收通过，也不在本次重写打包交付流程。

### 5.2 默认保留规则

| 产物 | 保留规则 |
| --- | --- |
| 正在构建、验证、使用或状态不明的候选 | 保留，不参与淘汰 |
| 成功的独立候选与 `previous` 备份 | 全局保留最近 2 份可用程序副本；已随候选转移的旧版备份计入数量，不让每次构建各保留一套历史 |
| 已确认失败且构建及媒体进程均已结束的候选 | 保留 24 小时供排查，之后回收程序产物；诊断记录单独保留 |
| 已登记的正式发布版本 | 保留当前已验证版本及上一个已验证版本，每版保留已登记的 ZIP 和解压目录；显式指定保留的版本不计入淘汰候选 |
| 验收报告与证据、配置和方案 | 不按包数量、包年龄或容量自动删除 |

正在构建的候选不挤掉此前两份可用副本。只有新产物完成验证、发布流程确认成功后，才允许淘汰被替代的旧产物；构建或发布失败时保留现有可用版本。最后一份可用版本永远不作为淘汰目标。

旧 ZIP 只有在登记为该发布版本的纯程序副本，并且登记时确认没有打入工作数据或验收资料时才可自动删除。目录则在删除前重新核对实际文件与登记清单；出现新文件或文件身份变化就跳过，不递归猜测用途。

维护脚本默认预览，只有显式执行参数才删除；构建脚本在已知自产目录内调用同一执行逻辑。路径核验、单轮互斥、进程占用和受保护文件检查对预览及执行均生效。发现链接、权限不足或并发变化时跳过，不调用其他 shell 绕过保护。

### 5.3 测试与验收资产的收尾

一次性验证目录采用同样的登记规则，区分可回收素材、运行缓存、配置/方案与验收证据。测试结束且报告与证据写入保护位置后，回收已登记的可再生素材和测试运行副本；保留配置、方案及证据，不按年龄清空整个测试目录。

这只覆盖后续通过登记入口创建的验证资产。未登记的一次性脚本或人工目录只列出候选，不让应用在后台接管整个临时空间。

## 7. 实施顺序与验收

### 阶段一：所有权与误删保护

先实现登记、预览清单和引用保护，再接入实际删除。用隔离目录验证路径逃逸、链接、未知文件、工作数据目录重叠、记录损坏和并发变化；任何不确定项都必须跳过。策略单测使用临时文件树，不复制真实用户方案作为测试输入。

### 阶段二：运行缓存与异常收尾

接入播放器、图片预览、协议流及任务中间目录；验证正常释放、取消竞争、失败发布、异常退出后补扫和占用重试。确认媒体检查的直接调用方没有引入新的整片扫描。

### 阶段三：构建与测试产物收尾

接入候选及发布登记、全局保留数量、失败候选延迟清理和验收证据保护。先用目录夹具验证，不为测试淘汰规则重复生成多个约 550 MiB 的真实安装包。

### 验收标准

| 场景 | 必须达到的结果 |
| --- | --- |
| 单份缓存大于软目标 | 用注入的小目标和真实短视频验证相同分支；允许生成、播放、暂停、逐帧和恢复，不因容量报错 |
| 真实长视频 | 在有代表性的长视频上验证兼容预览及释放后的回收；没有原素材时明确替代样本与覆盖限制，不宣称长片压测通过 |
| 多份缓存超目标 | 只按最近使用时间回收已释放且过宽限期的文件；当前播放、图片展示、协议读取及生成中的文件不变 |
| 过期与触发 | 不再使用旧素材也能通过维护周期回收；用可控时钟验证，不实际等待一天 |
| 异常残留 | 强制结束仅由本次验证启动的隔离实例；重启可回收已登记且确认无人使用的残留，仍有媒体子进程或状态不明则跳过 |
| 失败与占用 | 校验失败/取消后只回滚本次新发布结果；占用删除失败有原因和后续重试，不虚报回收成功 |
| 并发与响应过期 | 共享同一缓存、切换素材后旧请求返回、窗口销毁、取消与成功竞争均不误删或永久遗留引用 |
| 工作数据与验收资料 | 配置、方案及恢复数据、报告、结果 JSON、截图、备份包逐字节不变；源视频与输出成品不进入删除清单 |
| 旧包 | 第三份成功候选产生后按规则回收旧副本；失败不挤掉可用版本；当前及上一发布版本保留；混入配置或验收文件的旧包跳过 |
| 路径与多进程 | 仓库同级、`release` 内和隔离目录可分别登记；未登记根不扫描；其他实例或构建仍活跃时不清理其目录 |
| 轻量交互 | 批量压缩选入、调参和保存不因维护启动媒体进程或等待目录全量清理；记录维护耗时、检查数量和实际删除量 |

验证范围限于本次变化：类型检查、维护策略测试及受影响的既有纯函数测试；用 Playwright 连接 Electron 核对播放/对比生命周期。构建脚本改动最后进行一次候选构建和必要包内冒烟，不自动发布 ZIP、不提交、不推送。

一次性验证脚本、日志与媒体只写入仓库同级临时空间。验收报告继续写入 `../videoCutTool_tmp/walkthrough.md`，详细结果和必要截图放入明确保护的验收目录；报告区分文件逻辑大小和实际磁盘变化，不能把硬链接的多路径大小重复当作释放空间。
