# 保留片段自定义合并实施方案

日期：2026-10-17  
状态：已实施并验证，完成日期 2026-10-17；未提交、未推送、未打包。  
验证结论：构建及既有 10 项领域测试通过；任意组合、保存回载与重启恢复、实际输出色彩顺序、压缩、逐文件画幅、非零起始 FLV、普通两种输出方式、取消与失败清理、重名避让及 1920／1100 窗口检查通过。FLV 使用隔离合成样本，并按实际关键帧安全区间验收；未使用用户原始大文件。验收记录位于项目同级 `videoCutTool_tmp/walkthrough.md`。

## 1. 已确认的交互

- 支持任意选择保留片段，点击“合成一个文件”；不限制为相邻片段。
- 例如选择第 1、3、5 段，输出为：文件 1 包含 1 → 3 → 5，文件 2 包含第 2 段，文件 3 包含第 4 段。
- 每个文件内部按原视频时间顺序拼接，与勾选先后无关；未参与组合的保留片段分别输出，丢弃片段不参与组合。
- 可以建立多个组合，支持移出单段、拆开输出、撤销和重做。
- 胶囊区域上方提供“选择合并片段”，进入选择状态才显示勾选控件。沿用编号跳转、保留／丢弃、试听和时间微调的既有操作含义。
- 组合后用“文件 1”等文字标识归属，并显示“将输出 N 个文件”及各文件包含的片段；不要求用户理解内部的“组”。
- 底部“多段合并”改为“分别输出／全部合成一个／自定义合并”，三者共用一份输出配置。
- “合成一个文件”只改变输出归属，不删除切点、不修改保留决策。现有垃圾桶操作仍用于移除切点，文案明确区分。

## 2. 实施采用的细节

以下是为使上述交互完整而采用的默认规则，并非新增需求。

### 2.1 选择与反馈

- 进入选择状态不立即修改草稿；至少选中两个不同的保留片段才可执行合并。取消选择、退出选择状态不改变已有输出配置。
- 在“全部合成一个”下进入选择状态时，提示“选中片段合成一个文件，其余片段分别输出”；提交后切换为自定义合并，避免把原来的全合并隐式保留下来。
- 自定义模式中，选中片段从原组合移出后组成新文件；未选中成员保留原归属，不自动把其整个组合一并选入。组合只剩一段时作为单独文件，空组合移除。
- 文件按其最早成员在原视频中的位置排序并编号；编号是当前结果展示，不是永久身份。实际导出顺序与清单一致。
- 清单使用紧凑文本行，默认可见文件数和组成，不增加视频预览；内容较多时在清单区域滚动，不持续挤压播放器和时间轴。
- 选择态使用复选框与轮廓，文件归属使用文字；不单靠颜色，也不复用播放高亮表示选中。按需提供键盘焦点、明确按钮名称和禁用原因。
- 普通胶囊高度、64px 时间轴、居中播放按钮和倍速控件保持现有布局关系。

### 2.2 切换输出方式与编辑片段

| 操作 | 结果 |
| --- | --- |
| 切换到分别输出或全部合成一个 | 以该方式重建输出归属，清除自定义组合；作为一次可撤销操作，不保留另一套隐藏分组 |
| 从普通模式切换到自定义合并 | 初始各保留片段单独输出，再按需组合 |
| 移出此段／拆开输出 | 原片段仍保留；只改变输出文件归属 |
| 将成员改为丢弃 | 从组合移除；再次改为保留时默认单独输出；撤销可恢复原归属 |
| 在已组合片段中插入切点 | 两个子片段继承该输出归属；单独片段被切开时默认分别输出 |
| 移动切点／微调边界 | 保持片段输出归属，更新时长和结果摘要 |
| 移除切点 | 沿用保留优先规则；两侧保留成员属于同一组合时继承归属；仅一侧保留时继承该侧归属；两侧保留但归属不同时，新片段单独输出，其余组合成员保留原归属，并提示可撤销 |

新建草稿继续按现有设置决定默认“全部合成一个”或“分别输出”；自定义组合只属于当前裁剪方案，不新增全局默认组合设置。

## 3. 代码现状与技术路径

目前 `RetentionDraft` 和方案记录使用 `concatSingleFile`，执行计划使用 `concatToSingleFile`，执行引擎按一个布尔值决定全合并或全分开。不能只增加胶囊按钮。

### 3.1 草稿、快照与保存

- 在裁剪草稿及裁剪方案记录中，以 `outputMode: separate | single | custom` 和自定义成员归属替代旧布尔值，不同时保留两套权威配置。
- 每个保留片段最多属于一个输出文件；自定义数据只记录多成员组合，未登记的保留片段自然成为单独文件。
- 当前 `seg_0` 等 ID 随插入、删除切点重新编号，不能直接将长期归属绑定到旧编号。输出归属在草稿内部随区间保存和变更；序列化时生成当前片段 ID 到组合标识的映射，恢复时在重建区间后应用映射。
- 快照、撤销／重做、保存、另存、重新打开均包含输出模式和归属；临时勾选状态只属于界面，草稿发生结构变更或加载其他方案时清空。
- 主进程校验输出模式、成员是否存在且保留、组合是否有效及字段规模；非法记录明确报错，不静默退化为全合并。
- 整片压缩记录仍表示一个整片输出，不携带自定义裁剪组合。同步调整共享类型和校验调用方，避免裁剪字段变化破坏批量压缩。
- 按项目开发阶段规则直接更新数据结构，不编写旧格式迁移或兼容分支；旧格式记录明确提示无法按新结构载入，不自动改写或删除本地历史方案。实施验收使用隔离工作目录。

### 3.2 输出清单与关键帧规划

- 提供一个共享的纯计算入口，从草稿的片段、输出模式和归属推导有序输出清单，供界面、文件数、路径摘要和执行规划共用。
- 执行计划改为有序 `outputs`：每项包含来源片段 ID、该文件的关键帧安全区间及对应空间配置；不再用全局布尔值决定如何拼接。
- 保留现有关键帧向左吸附和终点保全规则。无损输出可能包含起点前的关键帧余量，不能把“丢弃片段不参与组合”表述成逐帧精确删除保证。
- 重叠安全区间仅能在同一个输出文件内部融合，绝不跨文件融合；空间配置仍保留原成员信息，避免区间融合后丢失片段特效归属。
- 清单反映用户选择的片段；实际媒体时长仍以执行时的安全区间为准。

### 3.3 按输出文件执行

- 执行时复用一次源文件精确探测及必要的时间戳整理，不为每个输出文件重复整片检查。
- 按输出清单依次裁剪成员、在组内拼接、按需压缩或处理画面、验证并发布；每项只产生一个最终文件，不把中间切片作为成品发布。
- 画面裁切和遮罩继续按成员应用；需要统一画幅时，每个输出文件按其自己的首段有效配置确定画幅，不能让其他输出文件的首段影响当前文件。
- 进度步骤使用输出序号和片段序号区分，文件总数来自输出清单；保留取消、编码器回退、失败清理、发布冲突避让和成功产物报告机制。
- 裁剪产物继续进入原视频目录下的 `cut_方案名/`；整片压缩仍进入 `压缩/`。沿用现有文件名前缀和日期后缀，多文件的 `segNN` 表示输出文件序号，不再假定对应单个原始片段。
- 单文件使用既有单文件命名形式，多文件使用既有多文件形式；沿用同批次时间戳和防覆盖规则，不新增一套组命名格式。

### 3.4 耗时边界

遵循[媒体检查的耗时边界](../../../docs/方案/视频裁剪工具架构与实施方案.md#44-媒体检查的耗时边界)。勾选、组合、拆开、模式切换和结果清单更新均为内存计算，不启动 FFmpeg、FFprobe 或媒体预览。

现有 `resolveOutputPath` 间接调用精确媒体探测，不能让每次组合变化都触发它。将路径摘要所需的输出数量与命名计算同媒体检查分开，复用已有格式信息；保存也不因新增组合字段增加媒体扫描。实际执行时再做所需的准确检查，不新增文件摘要计算流程。

## 5. 实施顺序与验收

1. 完成共享模型及草稿操作，先验证归属不随编号错位、快照可以完整恢复。
2. 接入胶囊选择和输出清单，在常用窗口展示局部交互，再核对一个窄窗口；保留既有播放和时间轴布局。
3. 打通保存恢复、主进程校验及逐文件执行，最后同步原型和概念文档。
4. 执行以下最小验证，按 [README 验证与交付](../../../README.md#验证与交付) 通过即停止。

| 验收场景 | 通过标准 |
| --- | --- |
| 任意挑选 1、3、5，保留 2、4 | 使用关键帧对齐的短素材，清单和实际产物均为 3 个文件；第一文件按 1 → 3 → 5 拼接，不夹入 2、4 |
| 多组及部分重新组合 | 同一片段不重复归属，未选成员不被隐式带入；移出、拆开、取消选择和撤销／重做符合规则 |
| 改为丢弃、插入／移动／移除切点 | 归属按第 2 节处理，后续片段不因编号变化串组；非法成员被拒绝 |
| 保存、另存、关闭后载入并执行 | 模式与成员完整恢复；显示的文件组成和实际输出一致 |
| 分别输出、全部合成一个、零／一个保留片段 | 普通两种方式仍有效；零保留时阻止保存和执行裁剪方案；单段不允许无意义多选合并 |
| 组内安全区间重叠、跨组重叠 | 仅组内允许融合，跨组分别生成输出；关键帧向左吸附不变量保持 |
| 无压缩与压缩／空间处理 | 使用可辨认片段的短素材验证组成、顺序、音视频和逐文件空间配置，不只检查文件存在 |
| 取消、重名及组内处理失败 | 中间文件不作为成品；已有文件不被覆盖，成功发布结果与错误报告准确 |
| 交互及保存耗时 | 组合相关交互不启动媒体子进程；批量压缩选入／保存路径不新增精确探测 |
| 界面与类型 | 类型检查通过；Playwright 能力可用时验证常用及窄窗口，控件无重叠，播放与倍速可用 |

使用一套短合成素材和隔离方案目录覆盖上述流程；补充一次既有 FLV 代表素材的受影响执行检查，复用同一次运行记录文件组成、进度和耗时。没有原故障素材时注明验证限制，不重复跑无关完整回归，不默认打包。

方案编写阶段只核对文档差异与引用；实施验证现已完成并归档。提交、推送及打包另按用户指令执行。
