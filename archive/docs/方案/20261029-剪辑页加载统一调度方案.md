# 剪辑页加载统一调度方案

> 完成日期：2026-10-29。状态：调度改动已实施并归档；验收保留项见下。
> 源码基准：`782d779`；改动与本方案一同提交。
> 验证结论：类型检查、构建、调用计数、StrictMode、真实隐藏恢复、取消及迟到结果的定向验证通过。流式 FLV 保留播放位置；普通 MP4 的位置恢复验收未通过，改动前基线同样复现，本次未修改原生播放器。完整证据见[任务验收报告](../../../../videoCutTool_tmp/20261029-剪辑页加载统一调度/验收报告.md)。

## 1. 目标与范围

采用**完整选择请求＋同文件统一调度**，修复切回剪辑页并选择素材／回载方案时，选择 effect 与页面恢复 effect 重复启动加载的问题；同时避免新选择传入时短暂打开旧素材播放器，以及取消来源确认后切页再次加载。

保留现有准备会话、播放会话及切页恢复语义，遵循 [Retention Draft 常驻规则](../../../docs/adr/0003-retention-draft-and-background-cut-engine.md)、[媒体检查的耗时边界](../../../docs/架构.md#媒体检查的耗时边界)和 [README 验证要求](../../../README.md#验证与交付)。不增加扫描、探测、索引回读、正常通信往返或等待阶段，不降低性能。

## 2. 技术路径

1. **App 传递完整选择。** 将 `loadedPlan`、`requestedVideo` 合为 `CutterLoadRequest`：包含必填 `generation` 和“文件路径／裁剪方案记录”二选一的数据；方案路径从记录取得。用一个选择序号区分明确操作，同一路径再次选择仍生成新代次。回载开始时取得序号，异步返回与失败仅在序号仍有效时落地，旧响应不能覆盖更新选择；普通 Tab 点击不产生新选择。保留已加载路径展示及整片压缩编辑分流。
2. **剪辑页统一接纳与恢复。** 一个 effect 同时处理完整请求与可见性，替换两个竞争入口。分别保留已接纳代次、待完成选择和现有 `loadEpoch`：新选择先使旧尝试失效；隐藏时只保存最新请求，不启动新媒体准备；可见且有待完成选择时，通过同文件 `startPending()` 启动。加载函数只执行已接纳的选择，不再自行创建请求。成功、当前尝试失败或用户取消才清除待完成选择；普通状态／配置刷新不触发加载。
3. **明确清理与确认续接。** 未完成选择隐藏时，使本次尝试失效并释放准备引用，保留选择供返回恢复。已完成草稿普通切页不递增 `loadEpoch`，不取消仍有效的后台关键帧补充。卸载／StrictMode 清理沿用现有资源释放，保留未完成选择，允许下一次 setup 重建尝试。来源确认成功后核对选择代次、尝试代次与可见性，更新当前待完成记录，再从本地启动函数继续；成功和失败回调均忽略过期结果。取消确认或准备时同时结束待完成选择、使尝试失效并关闭提示，切页不能复活它。
4. **渲染时阻止旧素材启用。** 成功建立元数据和草稿时，同批设置 `readySelectionId`。播放器及编辑启用条件要求它与当前请求代次匹配，使新选择的首轮渲染就停用旧素材，不等待加载 effect 清空旧状态。同路径重选也按代次区分，不增加延时或额外状态提交阶段。
5. **保留两个会话的交接职责。** 工作台继续持有准备引用，播放 Hook 继续持有播放会话；沿用当前有效 `openSettled` 通知及页面停用时的已完成准备释放。准备中的引用仍由加载流程管理，不把播放器 effect cleanup 当作放弃准备。旧尝试只收尾自身资源，不能释放新选择的引用；时间轴异常分析和修复入口保持。

## 4. 行为变化与成本

- 正常切回并选择素材，准备入口由 **2 次变 1 次**；回载已确认来源的方案，`sourceBinding` 由 **2 次变 1 次**，准备入口仍为 **1 次**。这些计数不包含用户后续来源确认、真实隐藏后恢复或 StrictMode 有意重放。
- 已完成草稿普通切页，准备入口仍为 **0 次**；草稿、撤销历史和播放位置保留，播放器按原生命周期恢复。新选择到达时，旧素材不再短暂启动播放。
- 用户取消后，切页不再加载该选择；显式重新选择仍可加载。加载失败也不因普通切页自动重试，保持现有终结语义。
- 新增工作仅为常量级内存比较与请求交接，不比较整份方案、不复制索引、不新增定时器或防抖。性能结论以同条件定向验收确认。

## 5. 验收点

| 场景 | 通过标准 |
| --- | --- |
| 切回并选择／回载 | 正常业务提交满足上述调用次数；已有 A 时选择 B，首轮渲染不打开 A 的播放器，只为 B 建立一次有效草稿。 |
| StrictMode | 在开发模式真实页面覆盖有待完成请求的 setup → cleanup → setup；第二次 setup 能完成加载。允许旧尝试被取消后重放，但只有当前尝试能提交结果，迟到结果不改页面、不释放新引用，无卡在加载中或会话遗留。 |
| 真实隐藏与恢复 | 覆盖来源校验等待、准备会话打开／分析中，以及准备完成但播放尚未接管时隐藏。未完成选择返回后恢复一次；隐藏时收到新选择只保留最新请求。已完成草稿返回只恢复播放，保留切点、历史、位置和有效后台关键帧补充。 |
| 取消后不再加载 | 取消来源确认、取消视频准备后切走再返回，不再调用来源校验或准备入口，不再弹出旧确认；取消后的迟到成功／失败也无效。再次显式选择可以正常开始。 |
| 选择与确认顺序 | 同路径重选、同源不同方案均生效；快速 A → B 时只允许 B 更新页面，App 中迟到的回载成功／失败不能覆盖 B；来源确认成功在同一选择内继续一次。 |
| 两个会话与成本 | 当前有效播放打开取得结果后按原规则释放准备引用；真实隐藏／放弃释放所属资源。普通与流式路径不新增探测、扫描、索引回读或媒体进程，准备与首帧耗时无稳定退化。 |

实施前记录受影响入口基线。实施后只做类型检查、上述页面时序与调用计数验证、短代表性素材在同配置／同索引预热状态下的前后对比，以及文档和差异检查。页面验证按 README 优先使用可连接的 Playwright／Electron，以受控 IPC 返回顺序覆盖竞态，并实际切换 Tab 使常驻工作台隐藏／显示；不只靠手工调用清理函数代替真实隐藏。一次性脚本、日志及报告放在仓库同级 `../videoCutTool_tmp/20261029-剪辑页加载统一调度/`。通过即停止，不扩展全量回归、UI／E2E 工程、长片扫描或正式打包。
