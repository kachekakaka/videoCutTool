## 问题陈述 (Problem Statement)

用户在实际使用视频裁剪工具时，反馈了 4 个突出的操作痛点与交互断层：

1. **白底系统弹窗割裂（图一）**：在方案中心删除记录时，触发了 Chromium 默认的 `window.confirm()`，弹出带有英文窗口标题（`videocuttoool`）的 Windows 原生白底对话框，与整体 Motrix 暗黑科技风产生强烈的视觉割裂。
2. **定位按钮失效与布局冗余（图二、图三）**：
   - 工作台底部 Dock 栏右侧的 `[ ↗ ]` 按钮调用 Electron `shell.showItemInFolder` 时，由于视频刚载入尚未完成剪辑，预测产物在磁盘上尚未真实存在，导致系统静默失败、无任何响应；
   - 底部 Dock 栏左侧已经呈现了 `📁 预定: xxx` 的产物路径，右侧却又塞入了一个分割按钮 `[ 📁 输出目录 | ↗ ]`，造成功能与信息重复，右侧动作区域拥挤，让用户在设置目录时产生困惑。
3. **方案中心跨 Tab 数据丢失假象**：用户配置好偏好并存为方案后进入方案中心，切换到其他 Tab（如工作台或偏好设置）再切换回方案中心，列表呈现空白（“里面就没东西了”）。根本原因在于 `PlansPage` 被常驻内存的 `hidden` 容器包裹后，仅在应用首次冷启动时加载了一次数据，在 Tab 重新激活时从未触发重新读取。
4. **快捷键提示信息不足（图四）**：分段卡片上方的引导栏仅有一句简单的 `按 C 插入切点...`，未能向用户完整展现播放控制、逐帧微调、删除切点、撤销重做等已有键盘快捷键能力。

## 解决方案 (Solution)

从用户体验出发，进行针对性的交互精炼与架构加固：

1. **内嵌暗黑确认模态框**：彻底移除 `window.confirm`，在方案中心实现与 Motrix 暗黑风格深度契合的内置模态框（包含危险警示图标、确认/取消按钮、`Esc` 键与遮罩点击关闭），确保全流程视觉质感统一。
2. **预定产物胶囊整合与主进程路径容错**：
   - **整合入图三**：将输出目录的查看与更改完整收敛至底部 Dock 左侧的【📁 预定产物】胶囊。点击路径文本直接在资源管理器中打开目标目录；胶囊内置微型更换图标，点击随时弹出目录选择器；
   - **彻底移除图二冗余按钮**：完全移除右侧的 `[ 📁 输出目录 | ↗ ]` 按钮，右侧动作区纯粹聚焦于【存为方案】与【🚀 立即执行剪辑】；
   - **主进程加固**：在 `electron/main.ts` 的 `shell:showItemInFolder` 处理器中增加智能容错：若目标文件已存在则高亮选中；若尚未生成，则自动递归确保其父级目录存在并直接打开该目录，确保点击 100% 必定打开资源管理器。
3. **Tab 激活生命周期感知与实时拉取**：为 `PlansPage` 引入 `isActive` 激活属性。无论何时用户切换进入【方案管理中心】Tab，立即触发 `fetchPlans()` 重新从持久化介质拉取最新列表，彻底消除“切换后无内容”的视觉假象。
4. **全景键盘快捷键指南栏**：在分段卡片上方以按键徽章（`<kbd>` 风格）完整呈现全套快捷键，并在悬停时提供轻量提示，兼顾小白易用性与专业剪辑师的操作效率。

## 用户故事 (User Stories)

1. 作为一名专注剪辑的用户，我在删除不再需要的方案记录时，希望看到与软件暗黑界面一致的确认弹窗，而不是刺眼的系统白底框，以便于获得沉浸统一的操作体验。
2. 作为一名剪辑师，我希望在工作台随时点击预定产物即可打开对应保存目录，且能直接在胶囊内更换保存位置，以便于更直观地管理产物去向，同时省去界面右侧重复的按钮占用。
3. 作为一名用户，即使视频尚未导出，我点击预定产物打开目录时，也希望软件能正常打开该文件即将保存的所在文件夹，而不是点击毫无反应。
4. 作为一名高频使用方案中心的用户，无论我何时在工作台存入方案或在设置页修改配置，当我切到其他 Tab 再切回方案中心时，我希望总是能立刻看到最新完整的方案列表，而不是看到一片空白。
5. 作为一名快捷键操作爱好者，我希望在工作台卡片区域直观看到空格播放、C 键打点、方向键逐帧、Del 删点、Ctrl+Z 撤销等全部快捷键说明，以便于我能够脱离鼠标、实现毫秒级盲打粗剪。

### 2. 接口契约与数据流

- **主进程 `shell:showItemInFolder` 增强契约**：
  ```ts
  // 保持现有 IPC channel 签名不变，内部增强容错：
  ipcMain.handle('shell:showItemInFolder', async (_event, fullPath: string) => {
    if (!fullPath) return;
    try {
      if (fs.existsSync(fullPath)) {
        shell.showItemInFolder(fullPath);
      } else {
        const dir = path.extname(fullPath) ? path.dirname(fullPath) : fullPath;
        if (!fs.existsSync(dir)) {
          fs.mkdirSync(dir, { recursive: true });
        }
        shell.openPath(dir);
      }
    } catch (err) {
      console.error('打开目录失败:', err);
    }
  });
  ```
