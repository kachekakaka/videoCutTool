## 问题陈述 (Problem Statement)

1. **原生标题栏黑白突兀割裂**：
   在 Windows 10/11 系统中，由于未配置自定义窗口控制条，系统默认给应用程序顶部加装了一条浅白色的经典标题栏，与软件整体的 Motrix 极客深色风格（`#0c0e14`）产生剧烈的视觉割裂感，且额外挤占了 32px 的纵向宝贵屏幕视野。
2. **无损成品体积巨大导致分享受阻**：
   工具默认的流复制无损裁剪（`-c copy`）完整保留了原片的超高码率。对高清录屏或相机原片，即使只保留数分钟片段，成品体积依然高达数 GB，无法通过微信、钉钉或企业邮件传输，用户剪完后仍需四处寻找第三方工具二次压缩。
3. **参数调节的“降码黑盒焦虑”**：
   用户在尝试压缩视频时，面对 CRF 或画质档位普遍存在不确定性：担心选择了“肉眼无损”或“均衡”档位后，实际导出的画面严重发糊或噪点失真；迫切需要在真正耗时导出之前，**先抽取画面进行毫秒级前后 A/B 画质对比**，确认无误再行动。

## 解决方案 (Solution)

1. **一体化沉浸式顶栏改造（TitleBarOverlay）**：
   彻底消除独立的亮白标题栏，采用现代 Windows 沉浸式窗口叠加层，将系统原生最小化、最大化、关闭按钮无缝嵌入深色顶栏 Header 最右侧；支持 Win11 原生贴靠分屏，释放 32px 纵向视野。
2. **工作台分体式双态模式切换**：
   在底栏【立即剪辑】按钮旁引入 `[ ⚡ 无损秒切 (默认) | 📦 智能降码 ]` 分体胶囊。默认保持极速无损不变；切换至降码后文案联动为 `[🚀 降码导出]`，旁边紧跟 `[⚙]` 参数面板，完全遵循渐进式展开，不干扰无损用户肌肉记忆。
3. **对齐 ja_workspace 与 f2 的四档经典预设**：
   - 彻底贯彻**音频绝对保真铁律**：统一使用 `-c:a copy`，绝不重新编码音频，零音质劣化与多余耗时；
   - 预设标准化：`high_quality`（CRF 18）、`balanced`（CRF 22）、`high_compression`（H.265 CRF 24）、`scale_1080p`（限宽 1920 降码），并提供高级 CRF 滑块与限高；
   - 显卡加速：默认 `auto` 策略，自动探测 NVIDIA NVENC，支持则 GPU 硬件极速压制，不支持平滑回退至 CPU `libx264`。
4. **先切后压单次执行管线**：
   当任务既包含分段裁剪又启用了降码时，后台引擎先极速无损切片并合并正片，再对该成片单次整体降码压制，压制完成自动清理中间临时片，杜绝算力浪费与音频不同步。
5. **双模画质对比预览系统（Visual Compression Preview）**：
   在降码设置中提供 `[ 🔍 预览画质与细节对比 ]` 按钮。后台从保留区间均匀抽取 3~5 张关键帧单帧压制（耗时 < 500ms），在模态框中提供：
   - **卷帘对比模式（video-compare 风格）**：中央垂直滑块左右拖动，左半边原画、右半边降码后，像素级微瑕一览无遗；
   - **左右并排模式（Simple-FFMPEG 风格）**：双屏并列对齐，直观总览全貌与预估体积；
   - 支持特征帧切换（1/2/3/4/5）与滚轮缩放放大。
6. **方案模型契约与方案中心双色徽章**：
   `MediaRetentionPlan` 固化 `compress` 属性；方案管理中心卡片以 `⚡ 无损秒切`（青色）与 `📦 压缩: 均衡`（橙紫色）双色徽章鲜明标示，一键批量执行自动分流。

## 用户故事 (User Stories)

1. 作为剪辑操作员，我希望窗口顶部拥有浑然一体的深色沉浸式顶栏，以便于消除刺眼的白条突兀感，并为视频播放器和时间轴争取到更开阔的垂直视野。
2. 作为日常用户，我希望在裁剪完成后能一键将视频压缩到合适体积，以便于直接通过微信或钉钉分享给他人，而无需在不同软件间来回倒腾。
3. 作为对画质有要求的操作员，我希望在正式开始压制前能先预览压缩画质，以便于验证“肉眼无损”是否真的无损，消除导出黑盒顾虑。
4. 作为精细对比用户，我希望对比窗口能提供“卷帘拖拽对比”和“左右并排对比”两种视图切换，以便于我既能用卷帘看微小噪点，又能并排看整体色彩和画面。
5. 作为批量剪辑用户，我希望把带有降码设置的任务保存到方案中心，以便于后续批量执行时，工具自动知道哪些走秒级无损、哪些走后台降码。

### 2. 方案模型契约 (Schema & Invariants)

在 `src/shared/types.ts` 中扩展 `compress` 契约：

```ts
export interface CompressConfig {
  enabled: boolean;
  preset: 'high_quality' | 'balanced' | 'high_compression' | 'scale_1080p' | 'custom';
  crf?: number;         // 18 ~ 35 (默认 22)
  maxHeight?: number;   // 分辨率限制 (如 1080, 720)
  encoder?: 'auto' | 'cpu' | 'nvenc' | 'qsv';
}

// 扩展既有不可变方案
export interface MediaRetentionPlan {
  // ... 既有字段保持完全不变
  compress?: CompressConfig;
}
```

### 3. 一体化沉浸顶栏技术契约 (TitleBarOverlay)

在 `electron/main.ts` 中重塑窗口创建参数：
```ts
mainWindow = new BrowserWindow({
  width: 1360,
  height: 900,
  minWidth: 1080,
  minHeight: 700,
  backgroundColor: '#0c0e14',
  titleBarStyle: 'hidden',
  titleBarOverlay: {
    color: '#090b10',       // 顶栏深色基调，完美融入应用
    symbolColor: '#94a3b8', // 最小化/最大化/关闭按钮符号颜色
    height: 38              // 控件高度与顶栏高度协调
  },
  webPreferences: { ... }
});
```
在 `Header.tsx` 中：
- 最外层容器增加 `-webkit-app-region: drag`，使顶栏可正常拖拽移动窗口；
- 内部所有按钮、下拉框增加 `-webkit-app-region: no-drag`，保证交互点击灵敏；
- 右侧预留 `pr-36`（约 140px）内边距，确保标题栏控制按钮（- □ ✕）不遮挡任何功能按钮。

### 4. 关键帧瞬时抽样与双模对比系统设计

1. **抽样服务（`CompressionPreviewService`）**：
   - 接收参数：`videoPath`、`sampleCount = 4`、`compressConfig`；
   - 在保留片段区间内计算 4 个采样时间点（如 `15%`, `35%`, `65%`, `85%`）；
   - 使用内置 FFmpeg 执行毫秒级抽样：
     - 原帧：`ffmpeg -ss <ts> -i <src> -vframes 1 -q:v 2 <tmp>/orig_%d.jpg`
     - 降码帧：`ffmpeg -ss <ts> -i <src> -vframes 1 -c:v <encoder> -crf <crf> <scale_vf> <tmp>/comp_%d.jpg`
   - 将生成的图片以本地文件协议或 Base64 传递给渲染层，耗时严格控制在 **< 500ms**。
2. **双模对比组件（`CompressionPreviewModal.tsx`）**：
   - **顶栏控制**：视图切换按钮 `[ ↔ 卷帘对比 (video-compare) | ⧉ 左右并排 (Simple-FFMPEG) ]`，缩放档位 `100% / 200%`，关闭按钮；
   - **视图 1（卷帘对比）**：基于容器百分比的垂直可拖动分割线，原生 CSS `clip-path` 渲染，拖动平滑如丝，边缘噪点与微小色阶差异瞬间暴露；
   - **视图 2（左右并排）**：左右双卡片同步缩放平移，左标“原画”，右标“降码后 (预估减负 ~45%)”；
   - **底栏采样导航**：展示 1、2、3、4 缩略图标签，支持点击切换不同画面场景。

## 测试决策 (Testing Decisions)

1. **测试边界与标准**：
   - 遵守 AGENTS.md 测试红线，严禁引入重型 UI 自动化测试体系；
   - 核心参数逻辑编写纯函数单测（`tests/compressPresets.test.ts`，< 40 行）：
     - 校验 `high_quality`、`balanced`、`high_compression`、`scale_1080p` 产出的命令行参数是否严格包含 `-c:a copy`；
     - 校验 NVENC 启用分支与限高 `scale='min(1920,iw)':-2` 的数学表达式；
2. **手工与视觉验收标准**：
   - Windows 10/11 浅色主题系统下打开应用，顶部刺眼的白条彻底消失，右上角最小化/最大化/关闭按钮与应用顶栏浑然一体；
   - 点击【📦 智能降码】，展开参数面板并点击【🔍 预览画质与细节对比】，在 500ms 内弹出模态框；
   - 拖拽卷帘分界线，可清晰看到左右画质对比，切换为左右并排模式正常同步；
   - 点击【立即剪辑】，生成成品视频后，检查物理文件大小是否显著减少，且视频音质完全保真。

## 范围外说明 (Out of Scope)

1. **音频二次转码与重采样**：严格维持 `-c:a copy` 铁律，不提供音频码率调整选项；
2. **耗时巨大的 2-Pass 动态码率深度调优**：预设以 CRF 恒定质量为唯一标准，不引入需要扫描全片的 2-Pass 模式；
3. **复杂色彩滤镜与特效**：降码专注体积缩减与分辨率限高，不引入锐化、去噪或色彩校正等额外重型滤镜。
