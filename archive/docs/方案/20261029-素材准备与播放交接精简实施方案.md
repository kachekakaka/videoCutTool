## 1. 目标与范围

保留准备会话与播放会话，减少无用数组的构造、传输和保留，并明确每份引用的关闭责任。扫描器、持久索引、播放器挂载时机和首帧／定位算法沿用现状，不增加扫描、串行通信往返、等待或长期缓存，不降低性能。

媒体读取遵守[媒体检查的耗时边界](../../../docs/架构.md#媒体检查的耗时边界)。普通文件探测、方案来源确认、时间轴修复和独立切点缩略预览保持现有行为；不扩展为工作台整体重构或会话移交框架。

## 2. 技术路径

### 第一步：分别生成准备结果与播放数据

| 用途 | 调整后的行为 |
| --- | --- |
| 打开准备会话 | 新增 `openStreamPreparation(file, id)`，返回准备状态；完整且无错误时附编辑所需 `metadata`，非流式文件仍返回 `null`。 |
| 取得准备结果 | 新增 `streamPreparation(id)`，替换工作台完成时的 `streamStatus`；带回已有 `timings`，删除随后单独取计时的查询。 |
| 轮询进度 | 继续使用 `streamProgress`，不返回关键帧、逐帧数组或位置目录。 |
| 打开／查询播放会话 | 保留 `openStream`、`streamStatus`，直接返回播放所需的逐帧时间、位置目录、时间基准及状态。 |

准备结果仍包含编辑必需的 `keyframes/keyframePoints`，不宣称其为固定大小的小包。准备与播放入口复用同一内部会话创建逻辑及已有 `identify/acquire`；只在返回时生成各自所需数据，不能先生成完整快照再删字段。

从播放快照移除无实际读取者的 `preview`，以及工作台改用准备结果后不再需要的 `metadata`；同时删除控制器中未被使用的媒体信息通知。保留其他调用方使用的媒体信息生成能力。

`Session.ready` 只保存小型初始化结果，不再保存完整快照；原始索引仍由现有使用引用保护。新增准备入口复用文件授权、窗口代次和取消检查，并纳入通用处理入口的窗口代次保护，不能绕过现有检查直接创建会话。

### 第二步：明确关闭责任

- 工作台持有准备会话，释放函数捕获当次 ID 并保持幂等；用同一个准备对象替代 `preparedStreamId` 与当前 ID 的相等比较。保留 `loadEpoch` 对草稿和提示等过期结果的过滤。
- 保留 `onStreamOpened` 通知，传递当次准备对象的释放函数。正常路径严格保持“取得播放引用 → 释放准备引用”，交接期间不能让共享任务的引用归零。
- `useStreamPlayback` 统一关闭其创建的播放会话；卸载、打开失败、取消、迟到响应和控制器报错共用本次清理函数，同时释放不再需要的当次准备引用。异步回调捕获本次实例，不能关闭新素材的会话或控制器。
- `StreamPlaybackController.destroy()` 只清理播放器、帧回调和媒体元素，移除后台会话关闭职责；后端关闭的幂等行为继续保留。

时间轴异常仍提示修复并继续同次可取消分析，不能按普通播放失败提前释放最后引用。切 Tab、进入画质对比及重新显示时沿用现有播放会话开关行为，保留 Retention Draft；缩略预览继续独占自己的会话并共享索引。

## 4. 验收点

以下为实施时的验收标准；实际覆盖、测量结果及未重复验证的范围见头部验收报告。

| 验收项 | 通过条件 |
| --- | --- |
| 数据与通信 | 准备请求不生成或返回播放器专用 `frames/index`；播放快照不生成无用 `preview/metadata`；进度保持小响应，通信往返不增加。 |
| 扫描与索引复用 | 对正常受支持流式素材，首次完整分析仍为一次；命中有效索引时完整扫描为零。准备到播放交接复用同一在途／内存任务，不因引用断档重新扫描或回读持久索引。 |
| 首次与重开 | 首次准备、已有索引重开、方案回载均得到正确完整时长，完成后才创建播放器；切点及撤销历史不因返回 Tab 或画质对比而重置。 |
| 取消与清理 | 准备中取消／换片、取得播放引用前后切页、打开失败及报错均释放对应会话；迟到结果不关闭新会话。正常退出不再由 Hook 与控制器重复发关闭请求。 |
| 异常与其他入口 | 时间轴异常继续同次分析并可取消，修复入口可复用结果；普通 MP4、独立缩略预览和原片按位置读取行为保持。 |
| 性能与内存 | 同素材、同配置、同索引状态比较准备总耗时、会话取得及首帧耗时；不得出现可复现的变慢。`ready` 不保留完整快照，不新增长期大数组副本或缓存。 |

按 [README 验证与交付](../../../README.md#验证与交付) 控制范围：类型检查、上述两组既有流式测试，以及受影响流程的定向检查。新增断言覆盖实际数据生成和交接风险，不为局部释放函数建立镜像测试，也不引入组件测试框架。

性能用代表性正常 TS 和修复后 MP4；以隔离测试数据目录构造无索引／已有索引状态，不删除用户索引。记录改前改后版本、素材格式／体积／时长、工具配置、扫描次数及已有阶段计时，冷／热各做一组对比；差异无法判断时仅复测对应场景。可复现变慢或扫描增加即不通过，不能以“预计更快”代替测量。真实高码率长 FLV 的[暂缓验收](../../../docs/待做事项.md#暂缓事项)不重新开启，也不标记通过。
