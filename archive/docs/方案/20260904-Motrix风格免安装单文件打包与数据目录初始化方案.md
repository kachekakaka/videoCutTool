## 问题陈述 (Problem Statement)

1. **分发与运行依赖重**：当前项目构建流程仅产出静态网页资产（`dist/`）和主进程编译脚本（`dist-electron/`），缺少像 Motrix 那样双击即可运行的单一免安装桌面可执行程序；若将产物直接复制到未安装配置 FFmpeg 的新设备上，应用会因找不到媒体工具链而彻底失效。
2. **源码仓库受运行数据污染**：目前程序在运行时直接使用当前工作目录（`process.cwd()`）写入 `config.json` 和 `plans/` 目录，在开发与日常测试时导致大量业务方案 JSON 散落在代码仓库根目录下，破坏了仓库的规范与整洁；且便携打包后若被置于只读或权限受限目录，会导致写入崩溃。

---

## 解决方案 (Solution)

1. **Motrix 风格单文件便携构建（Standalone Portable Executable）**：
   - 引入并配置 `electron-builder`，针对 Windows 平台构建完全自包含的单文件免安装便携版本；
   - 打包产物输出至 `dist/VideoCutTool-1.0.0-Portable.exe`，免除任何安装向导步骤，双击即开即用；
   - 自动在打包资源包（`resources/bin/`）中内嵌静态 `ffmpeg.exe` 和 `ffprobe.exe` 二进制文件，启动时首选内置工具链，达成零依赖开箱即用。
2. **工作数据目录解耦与同级零污染引导（Data Directory & Local Setup）**：
   - 将用户运行数据（`config.json`、`plans/` 方案目录）与可执行程序二进制彻底解耦；
   - 启动时通过便携可执行程序真实路径探测同级目录的 `config.json`：
     - 若同级无配置，弹出系统原生文件夹选择对话框，引导用户显式选择专属的“工作数据目录（Data Directory）”；
     - 若用户取消选择，系统弹出友好提示并安全退出程序；
     - 用户选定后，在选定目录下生成完整 `config.json` 与 `plans/` 目录；并在 exe 同级生成轻量配置记录数据目录路径，严格不向系统 `%APPDATA%` 写入垃圾，随拷随用；
     - 下次启动直接从同级配置文件读取数据目录，实现无感平滑秒开。
3. **工程化固化与仓库净化**：
   - 建立专属打包命令目录 `scripts/`，提供一键打包批处理 `scripts/build-portable.bat` 和 `npm run package`；
   - 彻底清理当前仓库根目录下遗留的测试 `plans/` 与临时 json 文件，将相关目录加入 `.gitignore`。

## 用户故事 (User Stories)

1. 作为一名普通用户，我希望能直接下载一个名为 `VideoCutTool-1.0.0-Portable.exe` 的单一文件，无需运行安装程序或在系统里安装 FFmpeg，双击就能直接剪辑视频。
2. 作为一名便携软件爱好者，我希望能把单个 exe 放在 U 盘或移动硬盘中携带使用，软件在运行时不会向我的 Windows 系统 `%APPDATA%` 写入冗余残留，拔下 U 盘不留任何系统垃圾。
3. 作为一名首次使用的操作者，当我首次启动尚未配置的剪辑工具时，我希望程序能主动弹窗询问我“希望将剪辑工程与配置保存在哪个文件夹”，并在我选择的目录下自动建立方案文件夹，避免在我的电脑各处乱放文件。
4. 作为一名操作者，如果我在首次启动选择数据目录时不小心点击了取消，我希望程序能清晰提示我需要指定目录后安全退出，而不是发生未捕获异常或将数据丢失在不可知的内存中。
5. 作为一名二次使用的操作者，当我再次双击打开软件时，我希望软件能直接加载我上次指定的数据目录和之前保存的所有剪辑方案，无需重复询问。
6. 作为一名开发者，我希望在项目根目录下双击 `scripts/build-portable.bat` 或执行 `npm run package` 就能一键产出最终便携版，且日常开发调试不会在代码仓库根目录下生成散落的方案 JSON。

## 实现决策 (Implementation Decisions)

### 1. 架构解耦与启动探测机制 (Startup & Data Directory Detection)
- **便携路径解析**：主进程优先检查环境变量 `process.env.PORTABLE_EXECUTABLE_DIR`（`electron-builder` 注入的便携 exe 真实宿主物理目录），开发期或非便携期回退至 `path.dirname(process.execPath)` 或 `process.cwd()`。
- **目录生命周期时序**：
  ```
  App Launch
      │
      ▼
  探测 exe 同级目录是否存在 config.json？
      ├─► [存在] ──► 读取同级 config.json
      │                 ├─► 若包含 dataDirectory，以其作为数据目录
      │                 └─► 否则以同级目录自身作为数据目录
      │
      └─► [不存在] ──► 弹出原生目录选择框（dialog.showOpenDialog）
                        ├─► [用户取消] ──► 弹出警告提示并 app.quit() 安全退出
                        └─► [用户选定目录 D:/MyData]
                              ├─► 在 D:/MyData 生成完整 config.json 与 plans/
                              ├─► 在 exe 同级目录生成指向 config.json: { "dataDirectory": "D:/MyData" }
                              └─► 进入正常加载流程
  ```

### 2. 服务层接口改造 (Services Adaptation)
- **`ConfigService`**：
  - 构造函数支持传入 `baseDir`（存储主配置的数据目录），以及同级配置的引用；
  - 增加 `dataDirectory` 字段支持；
  - 支持向用户指定目录原子化写入初始完整配置。
- **`PlanStore`**：
  - 将 `plans/` 的基准路径强绑定至有效 `dataDirectory`，严禁在应用根目录下硬编码新建 `plans`。
- **`KeyframeProber` 与 `FFmpegExecutor`**：
  - 寻址优先队列：`process.resourcesPath/bin/ffmpeg.exe` -> 用户配置自定义路径 -> 系统 PATH，确保内置免配置优先级最高。

### 3. 打包系统与依赖配置 (Packaging Toolchain)
- **新增开发依赖**：`electron-builder`。
- **`package.json` 配置**：
  - `build` 目标为 `portable` (Windows x64)；
  - 打包产物输出目录为 `dist/`，命名为 `VideoCutTool-1.0.0-Portable.exe`；
  - 配置 `extraResources`：将开发机中 `D:/Tools/ffmpeg/ffmpeg.exe` 与 `ffprobe.exe` 包含进打包镜像的 `bin/` 目录；
  - 注册脚本命令：`"package": "npm run build && electron-builder --win portable"`。
- **专属批处理脚本**：
  - 创建 `scripts/build-portable.bat`：封装 UTF-8 编码环境检查、编译与打包执行链路，输出清晰进度。

### 4. 仓库清理与规范保护
- 物理删除源码根目录下遗留的 `plans/` 目录及测试 JSON；
- 在 `.gitignore` 中追加：
  ```gitignore
  # 运行时数据与配置隔离
  config.json
  plans/
  dist/
  dist-electron/
  release/
  ```

## 测试决策 (Testing Decisions)

### 1. 核心高层 Seam 与自动化验证
- **Seam 1：`ConfigService` 与数据目录引导寻址纯逻辑测试**：
  - 在隔离的测试目录中模拟无配置、同级存在指向配置、直接同级自包含三种场景；
  - 验证 `dataDirectory` 是否正确驱动 `PlanStore` 的 `plans/` 物理定位，确保不会在被测代码仓库根目录下意外创建任何物理文件。
- **Seam 2：既有 10 项核心无损切片算法与状态机单测**：
  - 确保向左吸附数学不变量与防重名递增逻辑在重构后依然 100% 保持通过。

### 2. 真实便携可执行程序交付验证标准
- **产物构建完整性**：执行 `npm run package` 后，在 `dist/` 目录下生成单个 `VideoCutTool-1.0.0-Portable.exe`，文件体积处于 120MB~160MB 合理自包含区间；
- **免依赖开箱即用性**：在关闭环境变量与全局 PATH 的测试上下文中，便携版能无障碍调用内置 `ffmpeg.exe` 与 `ffprobe.exe` 完成关键帧分析与切片；
- **目录引导行为验证**：
  - 初次运行未放置 `config.json` 的便携程序，弹窗引导；选择测试文件夹后，确认测试文件夹内成功生成 `config.json` 与 `plans/`；
  - 第二次双击同一 exe，不再弹窗，直接秒开进入工作台并正确展现既有历史方案。

## 范围外说明 (Out of Scope)

1. **NSIS 安装向导与系统写入**：明确不引入安装包式安装向导，不向 Windows 注册表或开始菜单写入注册条目。
2. **系统 `%APPDATA%` 存储**：遵循纯绿色便携要求，坚决不使用 `%APPDATA%` 存储运行配置与工程文件。
3. **跨平台（macOS/Linux）二进制打包**：本期专注交付 Windows x64 绿色免安装单文件；跨平台打包流水线不在本任务范围内。
