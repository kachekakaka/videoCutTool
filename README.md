# Video Cut Tool (视频裁剪工具)

轻量的视频裁剪桌面工具，采用 Motrix 风格界面，支持快速无损导出、精确导出、画面处理和批量压缩。当前支持与验证范围见[架构](docs/架构.md#支持范围)。

关键帧模式优先保全所选内容，精确模式按显示帧边界重新编码；模式、适用限制和实现入口见[导出模式](docs/架构.md#导出模式)。界面交互约定见[界面与范围边界](docs/架构.md#界面与范围边界)，业务名词以 CONTEXT 为准。

## 开发与协作约束

开发前阅读 [AGENTS.md](AGENTS.md)。开发、构建与测试命令以 [package.json](package.json) 为准。

Windows 便携构建使用 PATH 中的 PowerShell 7 执行 [build-portable.ps1](scripts/build-portable.ps1)，原 BAT 入口转发到该脚本。使用 `-BuildOnly` 只验证候选包。构建资源可通过 `VCT_FFMPEG_PATH`、`VCT_FFPROBE_PATH` 指定完整路径，解析与验证规则见 [electron-builder.cjs](scripts/electron-builder.cjs)。候选包验证通过后才切换正式目录，构建失败保留旧版本；使用时保留根启动器与 `app/` 的完整结构。

手动预览已登记旧产物的清理清单使用 `pwsh -File scripts/cleanup-artifacts.ps1`，添加 `-Apply` 才执行删除。发布副本和一次性验证素材的登记入口见 [portable-artifacts.ps1](scripts/portable-artifacts.ps1)；发布登记要求已关联合格候选并确认实际验收完成。媒体、索引、缓存和报告的保护边界见[数据与产物归属](docs/架构.md#数据与产物归属)。

## 验证与交付

按改动风险选择最小验证范围，通过即结束；只有新增改动、失败或明确未解决的问题才追加检查。验证脚本自身出错时，修正并重跑受影响部分，不默认重跑全部流程。

| 改动 | 默认验证范围 |
| --- | --- |
| 文档、规则 | 核对差异与表述一致性，运行 `npm run check:docs` 检查本地链接；不构建、不运行功能测试 |
| 高度、间距、颜色 | 核对差异；存在视觉不确定性时查看一次实际页面 |
| 控件排布 | 常用窗口及一个窄窗口，检查位置、遮挡和受影响按钮 |
| 播放、保存逻辑 | 类型检查及受影响流程，覆盖相关错误分支 |
| 媒体处理、性能 | 代表性素材、目标耗时及受影响流程回归 |
| 打包 | 一次构建，包内关键流程冒烟检查及必要文件核对 |

- 布局修改先核对当前尺寸、参考版本和需要保持的视觉关系；主观观感尽早展示局部效果。
- 性能问题先记录素材格式、体积、数量与等待环节，复现并计时。覆盖相关历史问题（如大 FLV 的非零起始时间戳、调参后缓存过期再保存）；没有原素材时注明替代样本与结论限制。区分整片扫描、换封装、重新编码，以及磁盘、CPU、内存成本。
- 类型检查可单独运行 `npx tsc --noEmit`，无需完整打包。保留既有纯函数测试，按受影响模块选跑；新增测试针对实际风险，不为样式修改扩展测试。关键帧向左吸附不变量继续由 [RetentionPlanner.test.ts](tests/RetentionPlanner.test.ts) 保护。不引入组件测试、UI/E2E 工程、CI 门禁或覆盖率指标。
- 需要界面验证时，先检查 Playwright 对目标 Electron／网页的连接能力；仅在不可用或涉及其无法覆盖的原生操作时，用 Computer Use 补充并说明原因。一次性验证资产遵循 AGENTS 的临时目录规则。
- 文档检查为手动入口，检查仓库 Markdown 的本地目标及 Markdown／HTML 锚点；仓库内失效引用报错，仓库外临时证据缺失给出警告。工具只检查引用能否到达，报告是否对应同一任务与版本仍须人工核对。

### 验收证据

小范围样式或文档修改在最终回复说明改动、检查结果及未验证项即可，不单独生成报告。多模块功能、性能优化与打包交付的报告放在 `../videoCutTool_tmp/<任务目录>/`，使用任务专属文件名；同一任务的小修正追加到该报告。内部 Artifact 如有镜像，镜像到同一任务目录。

`../videoCutTool_tmp/walkthrough.md` 可作为报告索引或最新报告入口，历史方案应链接任务专属报告或其中明确的任务段落，不能仅凭同名文件认定为当时的验收证据。已有混合报告保留原文；原始证据缺失时写明缺失和可用的替代材料，不补写“已通过”。

最终 ZIP 在已授权范围内的目标场景通过后生成；发现阻塞且额外修复仍待确认时，保留候选构建并说明阻塞。源码未变且已有可追溯的合格候选包时复用候选包。交付说明源码、运行验证与安装包各自对应的版本或改动范围，并说明是否提交；旧截图或旧包不能证明新改动已验证。
