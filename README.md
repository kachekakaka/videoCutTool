# Video Cut Tool (视频裁剪工具)

轻量、极简的视频裁剪桌面工具。采用 **Motrix** 暗黑界面，支持快速无损导出、精确导出和智能降码。

## 核心设计原则

1. **关键帧保全铁律（Floor to Keyframe）**：
   - 裁切起点自动向左吸附至前一个 I 帧（关键帧），严格遵守：
     $$\text{safeRange.startMs} \le \text{userRange.startMs} \quad \text{且} \quad \text{safeRange.endMs} \ge \text{userRange.endMs}$$
   - 无损模式使用流复制；智能降码在无损裁剪后重新编码视频，全部保留音轨继续流复制。
   - 快速无损与智能降码均可能扩出所选边界：界面估算起点提前量，片尾余量需以实际产物为准，不能承诺固定上限。

   **精确导出**按显示帧边界重新编码所选片段，保留起点画面、不包含终点画面；帧间手输时间向下一帧对齐，毫秒舍入的逐帧切点还原到对应帧。视频使用软件 H.264 高画质编码，全部音轨最终编码为 AAC，输出 MP4；速度较慢，不承诺严格无损。支持一路视频、多音轨、无音轨、分段画面处理及输出组合；附加流须先明确处理，不静默丢弃。模式随方案保存，原片不覆盖。时间轴异常仍须先修复，精确导出不能恢复原片损坏的画面。

2. **Motrix 极简体验与 1360px 统一垂直对齐轴线**：
   - 采用 Motrix 经典左侧 68px 紧凑功能侧边栏；
   - 全局界面视图严格对齐于 `1360px` 垂直容器，消除漂移与错位。
   - 后续业务确认交互统一采用应用内弹窗，保留清晰的取消入口与必要风险说明；文件／目录选择继续使用系统选择器。

## 开发与协作约束

所有参与本项目的开发者与 AI Agent 须严格遵守 [`AGENTS.md`](./AGENTS.md) 所定义的协作红线（包括原型演进方式、未获授权不改代码、Windows 下 Git 提交防乱码规范等）。

Windows 便携构建入口为 [`scripts/build-portable.ps1`](./scripts/build-portable.ps1)，通过 `PATH` 中的 PowerShell 7 执行；原有 BAT 入口继续转发到该脚本。使用 `-BuildOnly` 只验证候选包。构建资源可通过 `VCT_FFMPEG_PATH`、`VCT_FFPROBE_PATH` 指定完整路径，解析及验证规则见 [`scripts/electron-builder.cjs`](./scripts/electron-builder.cjs)。候选包验证通过后才切换正式目录，构建失败保留旧版本；正式使用时保留根启动器和 `app/` 的完整目录结构。

缓存维护按登记归属和实际使用引用回收闲置资产；长视频允许超过缓存软目标，配置、已保存方案和验收资料不参与淘汰。策略真源为 [`CacheMaintenanceService.ts`](./src/main/services/CacheMaintenanceService.ts)，实施及验收边界见[缓存与旧包自动清理方案](./archive/docs/方案/20261019-缓存与旧包自动清理实施方案.md)。历史未登记文件不会被自动认领。

流式索引发现时间戳重置或大幅跳变时，工作台提供“修复并继续编辑”，并继续本次可取消的只读分析。用户确认后由 [`TimelineRepairService.ts`](./src/main/services/TimelineRepairService.ts) 复用同次分析，无损另存 MP4 并发布成品索引；原片和已保存方案保留，新草稿不迁移切点。无法可靠配对断点或不符合支持条件时停止修复，不自动转码。修复成品是用户素材，不属于播放缓存；跨盘临时副本登记在目标盘的同级临时空间，重启按归属回收。安全另存需要目标文件系统支持排他硬链接（已验证 Windows NTFS）；不支持时提示更换保存位置，不向最终文件名写半成品。

媒体索引统一持久保存在数据目录，多个方案共享引用，完整索引不自动删除。已有方案缺少源版本记录时，通过应用内提示确认对应关系后再回载切点；取消不改方案。实际读取范围与复用边界见[架构方案 4.4](./docs/方案/视频裁剪工具架构与实施方案.md#44-媒体检查的耗时边界)。

构建候选自动登记并按保留策略收尾。手动预览已登记旧产物的清理清单使用 `pwsh -File scripts/cleanup-artifacts.ps1`，添加 `-Apply` 才执行删除；发布副本和一次性验证素材的显式登记入口在 [`portable-artifacts.ps1`](./scripts/portable-artifacts.ps1)，发布登记要求已关联合格候选并显式确认实际验收完成。

## 验证与交付

按改动风险选择最小验证范围，通过即结束；只有新增改动、失败或明确未解决的问题才追加检查。验证脚本自身出错时，修正并重跑受影响部分，不默认重跑全部流程。

| 改动 | 默认验证范围 |
| --- | --- |
| 文档、规则 | 核对差异、引用与表述一致性，不构建、不运行功能测试 |
| 高度、间距、颜色 | 核对差异；存在视觉不确定性时查看一次实际页面 |
| 控件排布 | 常用窗口及一个窄窗口，检查位置、遮挡和受影响按钮 |
| 播放、保存逻辑 | 类型检查及受影响流程，覆盖相关错误分支 |
| 媒体处理、性能 | 代表性素材、目标耗时及受影响流程回归 |
| 打包 | 一次构建，包内关键流程冒烟检查及必要文件核对 |

- 布局修改先核对当前尺寸、参考版本和需要保持的视觉关系；主观观感尽早展示局部效果，避免完整验证后才反馈。
- 性能问题先记录素材格式、体积、数量与等待环节，复现并计时。覆盖相关历史问题（如大 FLV 的非零起始时间戳、调参后缓存过期再保存）；没有原素材时注明替代样本与结论限制。解释时区分整片扫描、换封装、重新编码，以及磁盘、CPU、内存成本。
- 类型检查可单独运行 `npx tsc --noEmit`，无需为此完整打包；构建及测试入口以 [package.json](./package.json) 为准。保留既有纯函数测试，按受影响模块选跑，不因旧的“唯一测试”表述删除保护；新增测试须针对实际风险，不为样式修改扩展测试。关键帧向左吸附不变量继续由 `RetentionPlanner.test.ts` 保护。不引入组件测试、UI/E2E 工程、CI 门禁或覆盖率指标。
- 需要界面验证时，先检查 Playwright 对目标 Electron/网页的连接能力；仅在不可用或涉及其无法覆盖的原生操作时，用 Computer Use 补充并说明原因。一次性验证资产按 AGENTS 的外部临时目录规则存放。

小范围样式或文档修改在最终回复说明改动、检查结果及未验证项即可，不单独生成报告。多模块功能、性能优化与打包交付保留验收报告，落盘至 `../videoCutTool_tmp/walkthrough.md`；如同时生成内部 Artifact，同步镜像到该路径。同一任务的小修正只追加简短记录。

最终 ZIP 在已授权范围内的目标场景通过后生成；发现阻塞且额外修复仍待确认时，保留候选构建并说明阻塞，不默认发布无法完成目标场景的中间包。源码未变且已有可追溯的合格候选包时，复用候选包。交付说明源码、运行验证与安装包各自对应的版本或改动范围，并说明是否提交；不把旧截图或旧包当作新改动的验证证据。
